# 产品功能与信息架构评审

## 评审方法
- 以 [01-需求](../01-需求.md)、[02-功能树](../02-功能树.md)、[03-功能清单](../03-功能清单.md) 为主基线。
- 核对所有 UI 页面文档与原子功能文档之间是否形成一致的信息架构。
- 优先攻击会直接破坏用户主路径或导致产品定位失真的问题。

## 发现 1：产品承诺和主路径入口不一致
- 严重级别：致命
- 受影响文档：
  - [01-需求](../01-需求.md)
  - [欢迎页](../04-UI设计/01-欢迎页.md)
  - [新建工程与模板中心](../04-UI设计/02-新建工程与模板中心.md)
  - [无工程编排模式](../04-UI设计/10-无工程编排模式.md)
- 不合理点：
  - 需求文档应当体现“创建编排”和“创建工程”是并列主路径，但当前文档集还没有完全把这个关系固定下来。
  - 无工程编排模式存在页面文档，但只有两个未完成功能，说明它还没有真正作为首屏主路径成立。
- 为什么不合理：
  - 产品虽然以编排为核心，但小白用户的真实入口既可能是“开始编排”，也可能是“新建工程”。
  - 如果这两个入口不是并列设计，用户会搞不清先做什么，产品定位也会继续摇摆。
- 解决方案：
  - 欢迎页固定双主入口：`开始编排`、`新建工程`。
  - `打开已有工程` 为同层第三入口。
  - 无工程编排模式必须补齐草稿保存、草稿恢复、后续绑定工程。

## 发现 1A：流程定义输出结构的原则还没有彻底压到信息架构里
- 严重级别：致命
- 受影响文档：
  - [01-需求](../01-需求.md)
  - [02-功能树](../02-功能树.md)
  - [03-功能清单](../03-功能清单.md)
  - [编排页](../04-UI设计/07-编排页.md)
  - [新建工程与模板中心](../04-UI设计/02-新建工程与模板中心.md)
- 不合理点：
  - 文档口径已经说清楚：最终输出文档结构和管理方式由模板与编排定义。
  - 但信息架构上，用户主视角仍然更容易先看到“工程和模板”，而不是“这个流程会产出什么”。
- 为什么不合理：
  - 如果工件目录、阶段输出和导出映射不是首要对象，后续实现很容易退回到平台自己预设固定结果结构。
  - 这会直接违背产品的通用场景定位。
- 解决方案：
  - 在编排页中提升 `工件` 和 `输出契约` 的层级。
  - 在模板详情里显式展示模板定义的工件目录、默认流程和导出映射。
  - 在无工程编排模式里允许先定义输出结构，再决定是否创建工程。

## 发现 1B：产品定位仍然偏软件场景表达
- 严重级别：高
- 受影响文档：
  - [01-需求](../01-需求.md)
  - [02-功能树](../02-功能树.md)
  - [03-功能清单](../03-功能清单.md)
  - [F-094 软件工厂默认模板闭环](../05-功能具体实现方案/06-模板工件与导出/F-094-软件工厂默认模板闭环.md)
- 不合理点：
  - 现有文档仍然容易让人把产品理解成“软件方案生产工具”，而不是“通用文本/图文思路梳理平台”。
- 为什么不合理：
  - 用户场景已经明确包括流程、故事、攻略、视频脚本、拍摄思路。
  - 如果文档表达仍以软件场景为默认，会引导后续实现持续偏向某一个模板。
- 解决方案：
  - 在需求层和入口层明确：软件工厂只是默认模板之一。
  - 在功能树和清单里，把模板体系和工件体系表达成场景无关的通用平台能力。

## 发现 2：模板体系没有形成完整产品能力
- 严重级别：高
- 受影响文档：
  - [平台入口与模板 README](../05-功能具体实现方案/01-平台入口与模板/README.md)
  - [新建工程与模板中心](../04-UI设计/02-新建工程与模板中心.md)
  - [F-013 安装/导入模板](../05-功能具体实现方案/01-平台入口与模板/F-013-安装-导入模板.md)
  - [F-014 保存当前工程为模板](../05-功能具体实现方案/01-平台入口与模板/F-014-保存当前工程为模板.md)
  - [INF-029 Template registry](../05-功能具体实现方案/01-平台入口与模板/INF-029-Templateregistry.md)
  - [INF-030 Template scaffold and save service](../05-功能具体实现方案/01-平台入口与模板/INF-030-Templatescaffoldandsaveservice.md)
- 不合理点：
  - 模板被定义为平台核心资产，但安装、下载、保存、搜索、最近模板都仍然是未完成或部分完成。
  - UI 文档只定义了“左侧模板列表 + 右侧详情 + 底部表单”，没有定义模板来源、版本、信任、兼容性和更新策略。
- 为什么不合理：
  - 没有完整生命周期的模板，不是平台资产，只是工程脚手架。
  - 一旦模板可导入可下载，来源可信度、覆盖策略和版本升级就是一等问题。
- 解决方案：
  - 模板中心必须补齐 5 个维度：
    - 来源：内置 / 本地 / 远程
    - 状态：已安装 / 可更新 / 已损坏 / 不兼容
    - 版本：当前版本 / 最新版本 / 升级说明
    - 信任：官方 / 用户导入 / 未验证
    - 行为：创建工程 / 预览 / 安装 / 更新 / 删除 / 另存
  - 模板中心还必须同时支持“进入编排继续调整”，而不是只支持“从模板创建工程”。

## 发现 3：页面导航语义仍是占位语句
- 严重级别：高
- 受影响文档：
  - [欢迎页](../04-UI设计/01-欢迎页.md)
  - [新建工程与模板中心](../04-UI设计/02-新建工程与模板中心.md)
  - [主工作台](../04-UI设计/03-主工作台.md)
  - [AI会话栏](../04-UI设计/05-AI会话栏.md)
  - [流程面板](../04-UI设计/06-流程面板.md)
  - [编排页](../04-UI设计/07-编排页.md)
  - [技能与连接中心](../04-UI设计/08-技能与连接中心.md)
  - [设置与模型配置](../04-UI设计/09-设置与模型配置.md)
- 不合理点：
  - 几乎所有页面都用了同一句“退出路径：返回来源页、切换活动栏、命令面板或关闭当前对象”。
- 为什么不合理：
  - 这不是设计，是占位。
  - 真正的导航语义必须说明：
    - 页面是替换整个主内容区，还是抽屉、模态、侧栏、子页
    - “返回”回到哪里
    - 对象关闭后回到哪个默认视图
- 解决方案：
  - 每个页面文档补“导航语义”一节，明确：
    - 页面容器类型
    - 打开方式
    - 替换范围
    - 返回目标
    - 是否保留面板状态

## 发现 4：小白/高手分层仍停留在口号层
- 严重级别：高
- 受影响文档：
  - [00-UI总则](../04-UI设计/00-UI总则.md)
  - [F-108 小白降噪与高手深层入口](../05-功能具体实现方案/08-系统安全与观测/F-108-小白降噪与高手深层入口.md)
  - [主工作台](../04-UI设计/03-主工作台.md)
  - [编排页](../04-UI设计/07-编排页.md)
- 不合理点：
  - 文档反复说“小白降噪，高手深藏”，但没有哪一页给出“默认可见/二级入口/专家入口”的明确动作矩阵。
- 为什么不合理：
  - 没有矩阵，就只能靠工程师临场判断，最终会重新长成“什么都摆在首屏”或“高频功能被藏起来”。
- 解决方案：
  - 为每个页面增加一个固定表格：
    - 一级可见动作
    - 二级可见动作
    - 右键动作
    - 命令面板动作
    - Inspector 高级动作

## 发现 5：MSABC 优先级定义失真
- 严重级别：中
- 受影响文档：
  - [02-功能树](../02-功能树.md)
  - [03-功能清单](../03-功能清单.md)
- 不合理点：
  - 一些明显影响主路径合法性的能力没有被定义为 M。
  - 例如：
    - [F-049 只有满足 guard 才允许阶段确认](../05-功能具体实现方案/04-AI会话与阶段控制/F-049-只有满足guard才允许阶段确认.md)
    - [F-061 设计态与运行态切换](../05-功能具体实现方案/05-编排与流程资产/F-061-设计态与运行态切换.md)
    - [F-088 阶段输出契约配置](../05-功能具体实现方案/06-模板工件与导出/F-088-阶段输出契约配置.md)
- 为什么不合理：
  - 这些功能缺失时，核心路径不是“体验受损”，而是“逻辑不成立”。
- 解决方案：
  - 重新校准优先级：
    - 合法性、主路径连续性、输出可信度相关功能直接升级到 M。
    - 只有确属差异化价值但不影响基础可用性的，才放到 S。

## 发现 6：完成状态和用户旅程脱节
- 严重级别：高
- 受影响文档：
  - [03-功能清单](../03-功能清单.md)
  - [新建工程与模板中心](../04-UI设计/02-新建工程与模板中心.md)
  - [编排页](../04-UI设计/07-编排页.md)
- 不合理点：
  - 单个功能可能标记为“已完成”，但所在用户旅程仍然不闭环。
  - 例如模板创建相关功能里，`F-009 已完成` 并不代表“模板驱动创建工程体验已完成”。
- 为什么不合理：
  - 用户评估的是整条旅程，不是原子点状能力。
- 解决方案：
  - 在功能清单之外，再加“旅程完成状态”层：
    - 首次启动旅程
    - 模板创建工程旅程
    - 无工程编排旅程
    - 编排设计旅程
    - 阶段确认与导出旅程

## 建议的整改顺序
1. 回正首屏信息架构。
2. 重新定义模板体系完整生命周期。
3. 逐页补齐导航语义与动作分层矩阵。
4. 重新校准 MSABC。
5. 引入旅程级完成状态，避免“点状完成、整体不可用”。
