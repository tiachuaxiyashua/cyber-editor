# 编排层与交互层级专项评审

## 评审结论
当前编排层的文档最大问题不是“功能不够多”，而是“执行语义、交互层级、运行闭环”都没有真正站稳。它看起来像一个流程编辑器，但文档尚未定义出专业编排器必须有的运行规则和操作模型。

## 发现 1：设计态与运行态没有被强制分离
- 严重级别：致命
- 受影响文档：
  - [编排页](../04-UI设计/07-编排页.md)
  - [F-061 设计态与运行态切换](../05-功能具体实现方案/05-编排与流程资产/F-061-设计态与运行态切换.md)
  - [F-084 节点级调试与从此继续](../05-功能具体实现方案/05-编排与流程资产/F-084-节点级调试与从此继续.md)
- 不合理点：
  - 当前编排页首层就同时想承载资产浏览、节点编辑、运行与调试。
- 为什么不合理：
  - 小白会被编辑器噪音淹没。
  - 高手也无法快速判断当前是在“设计流程”还是“执行流程”。
- 解决方案：
  - 强制拆成两态：
    - 设计态：节点、连线、角色、工件、连接、工具、模板
    - 运行态：阶段状态、节点状态、变量/工件检查、从此继续、局部重跑
  - 设计态与运行态的工具栏、Inspector、底部面板应不同。

## 发现 2：画布语义不完整，无法支撑真实工作流
- 严重级别：致命
- 受影响文档：
  - [F-064 拖拽节点进入画布](../05-功能具体实现方案/05-编排与流程资产/F-064-拖拽节点进入画布.md)
  - [F-066 连线创建、删除与流向可读](../05-功能具体实现方案/05-编排与流程资产/F-066-连线创建、删除与流向可读.md)
  - [F-067 条件节点配置](../05-功能具体实现方案/05-编排与流程资产/F-067-条件节点配置.md)
  - [F-068 循环节点配置](../05-功能具体实现方案/05-编排与流程资产/F-068-循环节点配置.md)
  - [F-069 并行分叉与并行汇合配置](../05-功能具体实现方案/05-编排与流程资产/F-069-并行分叉与并行汇合配置.md)
  - [F-070 并行分支通信策略配置](../05-功能具体实现方案/05-编排与流程资产/F-070-并行分支通信策略配置.md)
- 不合理点：
  - 条件、循环、并行都列成了节点能力，但文档没有给出足够清晰的运行约束。
- 为什么不合理：
  - 没有明确语义，用户拖出来的图只是“图形”，不是“工作流”。
  - 尤其并行和循环，如果没有失败策略、最大轮次、等待条件、汇合条件，运行结果不可预测。
- 解决方案：
  - 对每类控制节点分别定义：
    - 输入条件
    - 执行策略
    - 成功条件
    - 超时/失败条件
    - 输出合并方式
    - UI 可编辑字段

## 发现 3：输出物没有成为编排页的一等公民
- 严重级别：高
- 受影响文档：
  - [编排页](../04-UI设计/07-编排页.md)
  - [模板工件与导出 README](../05-功能具体实现方案/06-模板工件与导出/README.md)
  - [F-087 模板工件目录查看](../05-功能具体实现方案/06-模板工件与导出/F-087-模板工件目录查看.md)
  - [F-088 阶段输出契约配置](../05-功能具体实现方案/06-模板工件与导出/F-088-阶段输出契约配置.md)
  - [F-089 节点输入输出工件绑定](../05-功能具体实现方案/06-模板工件与导出/F-089-节点输入输出工件绑定.md)
  - [F-090 导出映射配置](../05-功能具体实现方案/06-模板工件与导出/F-090-导出映射配置.md)
- 不合理点：
  - 产品本质上是“文本工件生产平台”，但编排页首层仍然是“资产区 + 节点库 + 画布 + Inspector”。
  - 工件、阶段契约、节点 IO 仍被放在次级甚至未完成位置。
- 为什么不合理：
  - 没有工件中心，用户看不出这个 Flow 最终要产出什么。
  - 也无法判断当前图是否真的能导出目标结果。
- 解决方案：
  - 在编排页左侧资产区把“工件”提升为一级资产。
  - Inspector 中固定保留“输入工件 / 输出工件 / 输出格式 / 校验规则”区块。
  - 运行态中增加“工件完成状态”面板。

## 发现 4：角色、技能、连接、工具、模型的优先级关系不清
- 严重级别：高
- 受影响文档：
  - [F-078 多角色定义与切换](../05-功能具体实现方案/05-编排与流程资产/F-078-多角色定义与切换.md)
  - [F-079 角色目标/设定/角色包配置编辑](../05-功能具体实现方案/05-编排与流程资产/F-079-角色目标-设定-角色包配置编辑.md)
  - [F-080 角色技能绑定、权限边界与实例化](../05-功能具体实现方案/05-编排与流程资产/F-080-角色技能绑定-权限边界与实例化.md)
  - [F-083 节点绑定角色、连接和工具](../05-功能具体实现方案/05-编排与流程资产/F-083-节点绑定角色、连接和工具.md)
  - [INF-019 ModelRouter](../05-功能具体实现方案/04-AI会话与阶段控制/INF-019-ModelRouter.md)
- 不合理点：
  - 文档定义了很多资产，但没有说明冲突时谁优先。
  - 例如：
    - 模板默认模型策略 vs 角色模型策略 vs 节点覆盖
    - 角色绑定技能 vs 节点临时工具
    - 连接权限 vs 工具权限
- 为什么不合理：
  - 没有优先级矩阵，就无法稳定实现运行时。
  - 这会直接导致“用户以为配对了，运行却命中别的东西”。
- 解决方案：
  - 单独补一份“绑定优先级与覆盖规则”：
    - 模板默认 < Flow 默认 < 角色默认 < 节点覆盖 < 运行时临时覆盖
  - 每次命中都要有 UI 显示最终解析结果。

## 发现 5：成熟编排器的基本画布能力缺项明显
- 严重级别：高
- 受影响文档：
  - [02-功能树](../02-功能树.md)
  - [03-功能清单](../03-功能清单.md)
- 不合理点：
  - 当前基线没有明确列出这些专业画布基础能力：
    - 缩放/平移/Fit View
    - 最小地图或总览
    - 框选/多选
    - 对齐/分布
    - 画布级撤销/重做
    - 注释/便签/节点说明
- 为什么不合理：
  - 这些不是“锦上添花”，而是任何专业流程编辑器的基本操作面。
  - 缺失后，用户会直接判断产品不专业。
- 解决方案：
  - 把以上能力补进功能树与清单，至少列为 A/B 级，而不是完全缺失。
  - 注释与说明层尤其重要，因为这类产品面向大量非技术用户。

## 发现 6：无工程编排模式只是壳，不是模式
- 严重级别：高
- 受影响文档：
  - [无工程编排模式](../04-UI设计/10-无工程编排模式.md)
  - [F-005 欢迎页无工程直接进入编排页](../05-功能具体实现方案/01-平台入口与模板/F-005-欢迎页无工程直接进入编排页.md)
  - [F-060 无工程状态进入编排页](../05-功能具体实现方案/05-编排与流程资产/F-060-无工程状态进入编排页.md)
- 不合理点：
  - 页面写了，功能没有。
  - 这意味着“模式”只是一个口号，不是产品能力。
- 为什么不合理：
  - 用户会把无工程编排理解为“先设计流程，再决定是否工程化”。
  - 如果没有草稿存储、恢复、导出、转模板，这个模式没有存在价值。
- 解决方案：
  - 定义无工程编排的四个必备动作：
    - 新建草稿 Flow
    - 保存本地草稿
    - 导出 Flow 包
    - 转成模板 / 绑定工程

## 发现 7：编排页对新手过噪，对高手又不够深
- 严重级别：高
- 受影响文档：
  - [编排页](../04-UI设计/07-编排页.md)
  - [F-108 小白降噪与高手深层入口](../05-功能具体实现方案/08-系统安全与观测/F-108-小白降噪与高手深层入口.md)
- 不合理点：
  - 首层默认就把资产区、节点库、画布、Inspector 全展开。
  - 但深层又没有真正把高级动作定义清楚。
- 为什么不合理：
  - 小白一进来认知负担太重。
  - 高手也没有真正高效的深层工具链。
- 解决方案：
  - 默认首层改成“运行视图/简化设计视图”。
  - 高级模式再显示完整资产区、Inspector 高级项、调试抽屉、历史恢复。

## 建议的整改顺序
1. 先补设计态/运行态分离。
2. 再补画布最小专业能力包。
3. 再补输出物与工件一等公民。
4. 最后补角色/技能/连接/工具/模型的优先级矩阵和无工程编排模式。
