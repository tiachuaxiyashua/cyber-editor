# 01 页面与交互 PRD

## 总体原则

Cyber Editor 是生产工具，不是营销页。界面应安静、密集、有层级，优先让用户处理当前对象和下一步动作。

## 全局布局

| 区域 | 作用 |
|---|---|
| 左活动栏 | 切换工作域：工程、编排、资源、运行、规则、设置 |
| 左侧资源区 | 当前域的树、列表、搜索和过滤 |
| 中央主区域 | 当前主对象：文档、画布、工件或证据 |
| 右侧检查器 | 当前对象配置、AI、审批、错误恢复和上下文 |
| 底部/顶部状态条 | 运行状态、待决事项、错误和进度 |

## 活动视图清单

当前代码中，左活动栏至少支持以下视图：

| 视图 | 主对象 | 入口文件 |
|---|---|---|
| 工程视图 | 文件树、文档、表格工件 | `App.tsx`, `FileTree.tsx`, `DocumentTabs.tsx` |
| 会话视图 | 会话列表、阶段状态、上下文入口 | `App.tsx`, `AppShellSections.tsx` |
| 思路地图视图 | 会话结构、证据节点、布局 | `ThinkingChainPage.tsx` |
| 编排视图 | Flow 画布、节点、运行控制 | `OrchestrationWorkspace.tsx` |
| 资源视图 | 模板、技能、角色、连接 | `ResourceCenterPage.tsx`, `TemplateCenterPage.tsx` |
| 规则视图 | 规则、沉淀、提升草案、知识图 | `RulesWorkspacePage.tsx` |
| 搜索视图 | 工程全文搜索与定位 | `App.tsx` |
| 设置视图 | provider profile、主题、全局配置 | `SettingsWorkspacePage.tsx`, `ProviderProfilesDialog.tsx` |

## 交互分级

| 层级 | 含义 | 必须出现的位置 | 不允许的唯一入口 |
|---|---|---|---|
| P0 中断决策 | 审批、拒绝、写回冲突、危险副作用、阻断错误 | 当前对象附近 + 全局待决入口 | 命令面板、隐藏面板、历史列表、API |
| P1 下一步动作 | 生成草稿、确认阶段、继续运行、局部重跑 | 当前阶段条、画布节点、文档状态条 | 抽屉、弹窗、更多菜单 |
| P2 对象编辑 | 节点配置、规则绑定、导出映射、连接设置 | 右侧检查器或对象详情区 | 中心模态作为必经路径 |
| P3 详情历史 | 运行历史、审查明细、日志、证据包 | 抽屉、详情页、历史页 | 不适用 |
| P4 低频管理 | 导入、安装、危险删除、完整设置 | 专用弹窗、资源中心、设置页 | 不适用 |

## 页面要求

### 欢迎页

1. 第一屏只保留四个主入口：继续最近工程、创建工程、打开工程、开始编排。
2. 模板和资源推荐降级为辅助区域。
3. 用户不需要理解工程结构也能进入编排草稿。

### 文档工作台

1. 文件树和文档区是主对象。
2. AI 写回必须展示差异、来源、影响范围和确认动作。
3. 阶段推进和待确认事项不能只存在流程面板。
4. 文档冲突必须给出保留本地、采用 AI、手动合并和查看差异。
5. 表格工件必须与 Markdown 文档共用同一工作台入口，而不是独立系统。

### 会话视图

1. 会话列表、当前阶段、上下文控制和跳转入口必须直接可见。
2. 用户从会话视图必须能跳到文档、思路地图和编排视图。
3. 阶段状态不能只显示颜色，必须有明确标签和下一步动作。

### 思路地图

1. 思路地图必须来自真实会话和证据，而不是静态示意图。
2. 布局、缩放和详情面板状态要能持久化和重置。
3. 节点点击后必须能定位回文档、会话或相关输出。

### 资源中心

1. 模板、角色、技能、连接必须按类型分组。
2. 导入和安装必须展示来源、版本、权限、风险和兼容性。
3. 资源详情不能阻断主旅程。
4. 需要审批的导入操作必须有结构化审查界面，不能退回原生确认框。

### 规则视图

1. 全局规则、工程规则、沉淀条目和提升草案必须分区展示。
2. 用户必须能看见规则来自哪里、当前是否启用、影响哪个对象。
3. 经验同步和规则提升属于低频动作，但不能被隐藏到无法发现。

### 设置中心

1. Provider、模型、密钥、主题、安全策略独立分区。
2. 设置变更必须有测试连接或即时反馈。
3. 高风险配置必须可恢复。

### 搜索与结果定位

1. 搜索结果必须能直接回到文件树与文档区。
2. 搜索视图是定位入口，不替代文档编辑。
3. 搜索、引用对比和知识关系要共享同一对象定位口径。

## 响应速度要求

1. 主页面切换应在 100ms 内有可见反馈。
2. 常用点击应在 50ms 内反馈按下状态。
3. 长任务 500ms 内显示运行状态。
4. 超过 2s 的任务必须显示进度、取消或后台运行。
5. 打包应用中 UI 延迟必须有自动化测试覆盖核心路径。
