# 03 关键交互裁决

本文记录当前最终设计裁决。实现、测试和后续文档必须遵守。

## 裁决 1：关键动作不能隐藏

阶段确认、人工审批、运行暂停/恢复、AI 写回冲突、资源信任审查、可恢复错误属于主旅程动作。

它们必须出现在当前对象附近，并进入全局待决入口。命令面板、隐藏面板、运行历史、测试 API 只能作为辅助入口。

## 裁决 2：编排页以画布为主

编排页不是配置表单页，也不是说明页。画布必须居中最大，顶部说明和大按钮降级为状态条、菜单或空状态。

## 裁决 3：节点点击后直接编辑

选中节点后，右侧检查器直接展示可编辑配置。高级 JSON 和诊断信息放入折叠区。

## 裁决 4：流程面板降级为详情

流程面板可以展示历史、步骤、日志和证据，但不能作为阶段推进、人工确认或恢复动作的唯一入口。

## 裁决 5：API 测试不能证明用户可用

如果测试绕过 UI 直接调用运行时 API 完成审批、暂停、恢复或写回，只能证明底层能力可调用，不能证明用户路径完成。

## 裁决 6：原生确认框不用于高风险动作

资源导入、技能安装、本地副作用、AI 写回冲突和危险删除必须使用结构化审查界面，展示来源、影响、风险、可恢复方式和审计记录。

## 裁决 7：完成状态只由验收门禁决定

文档里出现“已完成”不能作为成熟完成证明。成熟完成由 PRD、owner、用户路径、测试和打包态共同决定。
