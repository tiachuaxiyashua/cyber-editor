# F-116 角色包目录与实例化

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 角色 / 角色包
- MSABC 分类：S
- 当前状态：未完成
- 关联页面：[编排页](../../04-UI设计/07-编排页.md)、[无工程编排模式](../../04-UI设计/10-无工程编排模式.md)
- 上游需求：`D-C2`、`D-C3`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 角色必须是可以复用、导入、下载和版本化的资产。
2. 角色的身份、人格、协作规则和服务对象不能散落在 UI 表单里。
3. 实例化过程必须可解释，否则用户无法理解为什么同一个角色在不同节点表现不同。

### 2.2 完成定义
1. 每个角色以目录形式存储，而不是单文件或内存对象。
2. 角色目录结构固定，关键文件缺失时视为损坏角色包。
3. Flow 绑定角色包引用，运行时按固定顺序实例化。
4. 最终实例化结果可在 Inspector 中查看摘要。

## 3. 角色包目录结构
```text
.roles/
  red-reviewer/
    role.json
    IDENTITY.md
    SOUL.md
    AGENTS.md
    USER.md
    Skills/
      requirements-review.json
    MEMORY/
      MEMORY.md
    schemas/
      review-packet.schema.json
```

## 4. 各文件职责
1. `role.json`
   - 角色 ID
   - 名称
   - 版本
   - 默认模型策略
   - 默认权限边界
2. `IDENTITY.md`
   - 名称
   - 角色定位
   - 专注领域
3. `SOUL.md`
   - 人格
   - 价值观
   - 语气与原则
4. `AGENTS.md`
   - 与其他 Agent 的协作规则
   - 输入处理原则
   - 冲突处理方式
5. `USER.md`
   - 服务对象画像
   - 偏好与禁忌
6. `Skills/`
   - 默认技能引用与顺序
7. `MEMORY/`
   - 长期偏好与历史决策
8. `schemas/`
   - 可选，仅用于内部消息和包结构校验

## 5. 实例化顺序
1. 加载角色目录
2. 解析 `role.json`
3. 依次加载 `IDENTITY.md`、`SOUL.md`、`AGENTS.md`、`USER.md`
4. 读取 `Skills/` 和 `MEMORY/`
5. 叠加 Flow 级覆盖
6. 叠加节点级覆盖
7. 输出最终运行时角色实例

## 6. 关键约束
1. 角色包定义人格、原则、协作和默认能力边界。
2. 最终输出格式、输出目录、导出结构不属于角色包职责。
3. 这些由以下对象定义：
   - 节点 IO 契约
   - 阶段输出契约
   - Export Mapping
   - Flow 输入/输出目录

## 7. 多 Agent 沟通机制
1. Agent 之间通过三类通道沟通：
   - 工件
   - 消息
   - 控制信号
2. 角色包只定义“如何处理这些输入和如何协作”。
3. 具体哪些工件、哪些消息、哪些信号，由节点 IO 和边绑定决定。

## 8. 数据模型
```json
{
  "rolePackageRef": {
    "roleId": "red-reviewer",
    "packagePath": ".roles/red-reviewer",
    "version": "1.2.0"
  },
  "runtimeRoleInstance": {
    "effectiveSkills": ["requirements-review"],
    "effectiveModelPolicy": "prefer-cloud-with-local-fallback",
    "effectiveRestrictions": ["deny-delete-project"]
  }
}
```

## 9. 具体实现方案
### 9.1 Renderer
组件：
1. `RolePackageSummaryPanel`
2. `RolePackageFileStatus`
3. `RoleRuntimeInstanceSummary`

Renderer 责任：
1. 在角色详情区显示角色包目录状态。
2. 显示哪些字段来自角色包、哪些来自 Flow 覆盖、哪些来自节点覆盖。

### 9.2 Main / Service
服务：
1. `role-package-loader`
2. `flow-asset-persistence`

Main 责任：
1. 校验目录结构。
2. 加载并实例化角色包。
3. 记录最终实例化快照供运行和调试使用。

## 10. 校验与阻断
1. 缺少 `role.json`、`SOUL.md`、`AGENTS.md`、`USER.md`、`IDENTITY.md` 之一时，角色包标记为损坏。
2. 损坏角色包不允许绑定到新节点。
3. 旧节点若已绑定损坏角色包，必须显示阻断提示。

## 11. 自动测试
### 11.1 单元
1. 角色包目录完整性校验
2. 实例化顺序校验
3. Flow/节点覆盖叠加顺序校验

### 11.2 端到端
1. 导入角色包。
2. 在 Flow 中绑定该角色包。
3. 查看实例化摘要。
4. 删除关键文件后确认角色包变为损坏态。

## 12. 用户模拟测试
1. 导入一个完整角色包。
2. 打开角色详情，确认各类设定可见。
3. 在某节点上给角色添加 Flow/节点覆盖。
4. 查看最终实例化结果。
5. 手动删掉 `SOUL.md`，确认角色包立即变为不可用。

## 13. 不允许的错误实现
1. 角色包退化为单个 prompt 文本框。
2. 角色包直接定义最终导出格式。
3. Flow 覆盖直接覆盖原始角色包而不可追踪来源。
