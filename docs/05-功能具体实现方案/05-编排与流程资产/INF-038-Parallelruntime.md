# INF-038 Parallel runtime

## 1. 基本信息
- 类型：内部功能
- 所属层级：编排层 / 流程语义 / 并行
- MSABC 分类：S
- 当前状态：未完成
- 关联页面：运行态、调试态、流程面板
- 共享实现基线：[编排与流程资产](README.md)

## 2. 责任与完成定义
### 2.1 服务责任
1. 执行并行分叉后的多个分支。
2. 为每个分支维护独立运行上下文。
3. 按汇合策略计算何时继续主流程。
4. 将分支状态暴露给运行态 UI。

### 2.2 完成定义
1. 支持并行分支真实并发或并发调度。
2. 支持汇合策略：
   - `all_success`
   - `all_settled`
   - `first_success`
   - `stop_all_on_error`
3. 分支状态可追踪：
   - 待运行
   - 运行中
   - 成功
   - 失败
   - 超时
4. 汇合节点能读取分支工件、消息和信号。

## 3. 输入与输出
### 3.1 输入
1. Flow 结构
2. 分叉节点定义
3. 汇合节点定义
4. 边绑定
5. 运行 ID

### 3.2 输出
1. 每个分支的运行结果
2. 汇合判断结果
3. 分支级错误和超时信息

## 4. 核心接口
```ts
type ParallelGroupResult = {
  branchResults: Record<string, BranchRunResult>;
  joinDecision: 'continue' | 'blocked' | 'fail';
};

runParallelGroup(groupId: string, runtimeContext: RuntimeContext): Promise<ParallelGroupResult>;
```

## 5. 实现要求
1. 并行运行不是“顺序跑两遍”的 UI 假象，必须存在分支级上下文。
2. 每个分支都有自己的消息目录和结果快照。
3. 汇合节点在策略允许前不得继续执行。
4. `first_success` 下其余分支如何处理必须固定：
   - 默认取消未完成分支
   - 已完成分支保留结果

## 6. 失败与超时策略
1. 任一分支失败时按 `failurePolicy` 执行：
   - 立即停止全部
   - 允许部分失败继续
   - 等待所有分支完成再决策
2. 分支超时必须写入运行记录和 UI。
3. 汇合前缺必要分支结果时返回阻断错误，而不是悄悄继续。

## 7. 自动测试
### 7.1 单元
1. 双分支全成功
2. 单分支失败
3. `first_success`
4. 汇合等待超时

### 7.2 集成
1. 带工件和消息通道的红蓝裁判并行 Flow
2. 分支失败后部分继续的 Flow

## 8. 不允许的错误实现
1. 只是画了两条边，没有真实分支上下文。
2. 汇合节点不校验分支状态。
3. 运行态看不见各分支进度和结果。

## 9. 当前审计结论
- 审计状态：未完成
- 审计说明：并行运行时仍未形成可执行、可观测、可汇合的统一能力。
