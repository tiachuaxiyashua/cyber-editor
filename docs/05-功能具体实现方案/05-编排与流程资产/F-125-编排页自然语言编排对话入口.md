# F-125 编排页自然语言编排对话入口

## 1. 功能定义
在编排页顶部提供专用 AI 编排对话入口。用户可以用自然语言描述要搭建的流程，或要求 AI 对当前 Flow 做增量修改。

等级：S  
状态：未完成

## 2. 触发与入口
- 页面入口：编排页左上角 `AI 编排` 按钮。
- 次级入口：无工程编排模式下的空画布提示区。
- 快捷入口：命令面板 `打开 AI 编排`。

## 3. 用户操作
1. 用户打开编排页。
2. 点击 `AI 编排`。
3. 右侧或悬浮侧板打开对话面板。
4. 输入自然语言。
5. 点击 `生成草稿` 或 `生成补丁`。

## 4. 期望效果
- 对话面板显示本次输入、AI 解释和待应用结果摘要。
- 若当前无 Flow，则返回一份新的 Flow 草稿预览。
- 若当前已有 Flow，则返回一份补丁预览。
- 未经用户确认，不允许自动改写当前 Flow。

## 5. 局部组件与对象边界
- Renderer 组件：
  - `FlowConversationPanel`
  - `FlowConversationInput`
  - `FlowDraftProposalList`
  - `FlowPatchReviewPanel`
- Shared 对象：
  - `FlowConversationRequest`
  - `FlowPatch`
- Main 服务：
  - `ConversationToFlowPlanner`

## 6. 方法级 IO
### Renderer
- `openFlowConversationPanel(): void`
- `submitFlowConversation(message: string): Promise<void>`

输入：
- `message: string`
- `activeFlowId?: string`
- `flowDraftSummary?: string`

输出：
- `pendingFlowPatch: FlowPatch`
- `flowConversationState.status = "draft_ready" | "patch_ready"`

### IPC
- `conversationToFlow.plan`

请求：
```json
{
  "message": "帮我做一个从需求澄清到 QA 复盘的软件交付流程",
  "activeFlowId": "optional-flow-id",
  "flowDraft": {}
}
```

响应：
```json
{
  "mode": "new-flow",
  "summary": "生成了 8 个节点和 7 条边",
  "patch": {}
}
```

## 7. 动作时序
1. 用户点击 `AI 编排`。
2. Renderer 打开对话面板。
3. 用户提交文本。
4. Renderer 调用 `conversationToFlow.plan`。
5. Main 侧生成 `FlowPatch`。
6. Renderer 展示补丁预览。
7. 用户选择接受、拒绝或局部接受。

## 8. 错误与阻断
- 输入为空：本地阻断，不发请求。
- 当前 Flow 处于运行中：提示仅允许只读分析，不允许应用补丁。
- AI 生成补丁不可解析：进入错误态，允许重试。

## 9. 自动化测试
- 打开编排页，点击 `AI 编排`，面板出现。
- 输入自然语言后，调用对应 IPC。
- 无 Flow 时返回 `new-flow`。
- 有 Flow 时返回 `patch`。
- 不点确认时，画布不变。

## 10. 用户模拟测试
- 小白用户输入一句自然语言后，能看懂 AI 生成了什么。
- 高手用户能看见新增/修改/删除的节点、边、角色建议。

## 11. 不允许的错误实现
- 把自然语言编排放到设置页。
- 用户一发送消息就直接改写当前 Flow。
- 只返回纯文本说明，不返回结构化补丁。
