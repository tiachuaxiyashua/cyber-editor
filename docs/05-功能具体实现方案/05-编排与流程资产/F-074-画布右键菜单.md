# F-074 画布右键菜单

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 对象交互 / 右键
- MSABC 分类：A
- 当前状态：部分完成
- 关联页面：[编排页](../../04-UI设计/07-编排页.md)
- 上游需求：`D-C2`、`D-C4`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 画布空白区右键是高手用户最快的编辑入口。
2. 右键必须能在当前位置直接新增节点，而不是迫使用户来回移动到节点库。
3. 画布整理动作应就地可达，不能全部塞进顶部工具栏。

### 2.2 完成定义
1. 右键空白画布时弹出画布菜单。
2. 菜单支持在光标处新增常用节点。
3. 菜单支持粘贴、适配视图、整理布局、添加注释。
4. 选择“新增节点”后，新节点必须落在右键位置，而不是画布中心。

## 3. 页面入口与层级
1. 入口页面：编排页设计态
2. 入口动作：鼠标右键单击空白画布
3. 所在层级：`P1 编排页 -> P2 画布对象层 -> P3 上下文菜单`

## 4. 用户操作流程
1. 用户在画布空白区右键。
2. 系统记录当前画布坐标并弹出菜单。
3. 用户可选择：
   - 新增角色节点
   - 新增工具节点
   - 新增条件节点
   - 新增循环节点
   - 新增并行节点
   - 新增子流程节点
   - 粘贴节点
   - 自动整理布局
   - 适配视图
   - 添加注释
4. 系统在记录的坐标处执行动作。

## 5. 菜单结构与可见效果
### 5.1 菜单分组
1. 新增
2. 剪贴板
3. 视图与布局
4. 辅助说明

### 5.2 视觉规则
1. “新增”分组按最常用节点优先排序：角色、工具、条件、循环、并行、子流程。
2. 注释节点使用弱视觉样式，防止和真实执行节点混淆。
3. “粘贴”在剪贴板为空时禁用但保留位置。

## 6. 数据模型
```json
{
  "canvasPosition": { "x": 1080, "y": 520 },
  "menuAction": "create-role-node",
  "payload": {
    "nodeType": "role",
    "position": { "x": 1080, "y": 520 }
  }
}
```

## 7. 具体实现方案
### 7.1 Renderer
组件：
1. `CanvasContextMenu`
2. `CanvasQuickCreateSection`
3. `CanvasLayoutSection`

Renderer 责任：
1. 将屏幕坐标换算为画布逻辑坐标。
2. 在菜单关闭前保留这组坐标。
3. 触发动作后滚动/聚焦到新节点。

### 7.2 Main / Service
服务：
1. `flow-asset-persistence`
2. `canvas-layout-state-store`

Main 责任：
1. 真正创建节点并写入 Flow 草稿。
2. 执行自动布局和视图修复类动作。

## 8. 校验与阻断
1. 当流程为只读态时，新增相关菜单全部禁用。
2. 当剪贴板为空时，“粘贴”禁用。
3. 自动布局执行前必须保留一个撤销点。

## 9. 自动测试
### 9.1 单元
1. 右键屏幕坐标到画布坐标转换
2. 剪贴板启用态判断

### 9.2 端到端
1. 在空白区右键新增角色节点，确认节点落点正确。
2. 右键执行“适配视图”，确认画布回归全览。
3. 右键执行“添加注释”，确认注释节点被创建。

## 10. 用户模拟测试
1. 在画布右下角空白区右键。
2. 选择“新增角色节点”。
3. 确认节点出现在右键位置附近。
4. 再次右键，选择“适配视图”，确认视图恢复。
5. 尝试在只读态右键，确认新增动作不可执行。

## 11. 不允许的错误实现
1. 右键新增节点总是出现在画布中心。
2. 画布右键菜单和节点库重复到完全没有区别。
3. 菜单只做视觉壳，没有真实粘贴、布局和注释能力。

## 12. 当前审计结论
- 审计状态：部分完成
- 审计说明：当前画布右键仍缺少坐标精确投放、布局动作和辅助说明动作的完整闭环。
