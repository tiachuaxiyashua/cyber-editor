# 02 AI 编排运行时

## 核心对象

| 对象 | 当前代码 owner | 说明 |
|---|---|---|
| Flow | `ConversationFlowService`, `RuntimeAssetService`, `OrchestrationWorkspace.tsx` | 用户设计或由自然语言生成的流程资产 |
| Node | `OrchestrationWorkspace.tsx`, `RuntimeService` | 单个执行单元，可绑定角色、模型、工具、输入输出和治理约束 |
| Run | `RuntimeService` | 一次 Flow 执行，包含状态、事件、审批、恢复与 rerun 信息 |
| Approval | `RuntimeService`, `SideEffectGovernanceService` | 运行中的人工确认，或副作用执行前审批 |
| Artifact | `ProjectService`, `TableArtifactService`, `DeliveryExportService`, `ArtifactGovernanceService` | 节点或阶段输出，支持失效传播、版本和导出 |
| Evidence | `EvidenceStoreService`, `ProvenanceService` | 运行、审查、资源验证、副作用、上下文包和工件治理证据 |
| ContextPack | `KnowledgeIndexService`, `HybridRetrievalService`, `RuntimeService` | AI 运行时上下文包 |
| ThinkingChain | `ThinkingChainProjector`, `ThinkingChainLayoutStore`, `ThinkingChainPage.tsx` | 会话思路结构、证据节点与布局状态 |

### 3. 运行、暂停、恢复、停止、重试

`OrchestrationWorkspace.tsx -> preload.ts: runtime:pause-run / resume-run / retry-run / stop-run -> register-runtime-platform-ipc.ts -> RuntimeService -> run 状态持久化与运行事件 -> 运行条和节点状态刷新`

### 4. 审批、debug、局部重跑

`OrchestrationWorkspace.tsx -> preload.ts: runtime:resolve-approval / debug-node / preview-rerun / apply-rerun -> register-runtime-platform-ipc.ts -> RuntimeService -> pendingApprovals / rerunPlan / debug artifact -> 运行治理面板与画布更新`

### 6. 知识索引、思路地图与上下文

`ContextPane / ThinkingChainPage.tsx -> preload.ts: knowledge:* runtime.thinkingChain.* -> register-settings-session-ai-ipc.ts / register-runtime-platform-ipc.ts -> KnowledgeIndexService / HybridRetrievalService / ProjectKnowledgeGraphBuilder / ThinkingChainProjector / ThinkingChainLayoutStore -> 上下文包、索引状态、思路结构与布局持久化`

## 运行语义

1. Flow 运行必须生成 `runId`，并由 `RuntimeService` 写入事件与恢复状态。
2. 节点进入、完成、失败、跳过、重试、等待审批、需要合并都必须形成可见状态。
3. 人工确认不是 UI 假动作，必须落到 `pendingApprovals` 与证据存储。
4. 局部重跑必须先生成预览，再允许真正应用。
5. 工件写入不能只写文件，还必须更新工件治理、证据与失效传播。
6. 思路地图不是演示层，必须能从真实会话与证据投影出来，并保存布局。
7. 规则沉淀、知识索引和上下文包必须能在当前工程上重复生成，而不是一次性 UI 数据。

## AI 写回与治理

AI 写回文档或工件前必须展示：

1. 修改目标。
2. 变更 diff。
3. 来源消息、阶段或节点。
4. 影响范围。
5. 冲突状态。
6. 接受、拒绝、局部接受、手动合并。
7. 回滚或快照恢复方式。

本地副作用和远程资源导入必须经过：

1. `ResourceGovernanceService` 或 `SideEffectGovernanceService` 的预览/校验。
2. 审批记录或 review gate 结果写入证据。
3. UI 中可见的批准、拒绝或阻断反馈。

## 证据追溯

每个可交付输出至少应能追溯到：

1. 用户输入或触发命令。
2. 使用的上下文包和索引状态。
3. 模型、Provider 与结构化生成链路。
4. 执行节点与 run 事件。
5. 审批记录或副作用批准。
6. 写回 diff、工件版本或导出结果。
7. 对应测试或运行证据路径。

## 失败恢复

当前失败恢复必须能回到以下入口：

1. 运行控制条上的暂停、恢复、停止、重试。
2. 审批节点的批准/拒绝。
3. rerun 预览后的局部重跑。
4. 文档快照与冲突合并。
5. 思路地图布局重置。
6. 资源导入与副作用的 review gate / approval 结果。
