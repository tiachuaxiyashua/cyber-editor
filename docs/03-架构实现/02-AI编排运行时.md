# 02 AI 编排运行时

## 核心对象

| 对象 | 说明 |
|---|---|
| Flow | 用户设计的流程资产 |
| Node | 单个执行单元，可绑定角色、模型、工具、输入输出 |
| Edge | 节点间依赖和条件 |
| Run | 一次 Flow 执行 |
| Checkpoint | 可恢复运行快照 |
| Approval | 人工确认或治理决策 |
| Artifact | 节点或阶段输出 |
| Evidence | 输出来源、模型、消息、时间、审批和文件变更 |
| ContextPack | AI 运行时上下文包 |

## 运行语义

1. Flow 运行必须生成 run id。
2. 每个节点进入、完成、失败、跳过、重试都写入事件。
3. 长任务必须定期 checkpoint。
4. 暂停和恢复必须基于持久化状态。
5. 并行分支必须隔离上下文和输出。
6. 汇合节点必须处理分支冲突。
7. 循环必须有最大次数和退出条件。
8. 子流程必须有输入输出契约。
9. 人工确认必须阻断运行并进入待决入口。
10. 工件写入必须生成证据和版本。

## AI 写回

AI 写回文档或工件前必须展示：

1. 修改目标。
2. 变更 diff。
3. 来源消息和节点。
4. 影响范围。
5. 冲突状态。
6. 接受、拒绝、局部接受、手动合并。
7. 回滚方式。

## 证据追溯

每个可交付输出必须追踪到：

1. 用户输入。
2. 使用的上下文。
3. 模型和 Provider。
4. 执行节点。
5. 运行事件。
6. 审批记录。
7. 写回 diff。
8. 测试或质量评分。

## 失败恢复

失败必须映射为 RecoveryCard：

1. 错误码。
2. 影响对象。
3. 失败原因。
4. 可恢复动作。
5. 是否需要人工确认。
6. 详情和日志入口。
