# 06 框架方案选型

## 1. 目标

固定 Cyber Editor 当前代码采用的主框架、关键依赖和选型边界，避免后续文档或实现重新发明第二套技术路线。

本文只描述当前代码事实和可接受演进方向，不替代 [系统架构与分层 Owner](./01-系统架构与分层Owner.md)。

## 2. 当前技术栈

| 层 | 当前选型 | 代码依据 | 选型结论 |
|---|---|---|---|
| 桌面壳 | Electron 39 + Electron Forge | `package.json`, `src/main/main.ts` | 继续作为桌面运行壳，最终用户验证以打包应用为准 |
| 构建 | Vite 6 + TypeScript 5 | `vite.*.config.ts`, `package.json` | main/preload/renderer 分别构建，避免把前后端边界混在一起 |
| Renderer | React 19 + React DOM | `src/renderer/main.tsx`, `src/renderer/App.tsx` | 页面状态和交互仍走 React，不引入第二套 UI 框架 |
| 编排画布 | `@xyflow/react` | `src/renderer/components/OrchestrationWorkspace.tsx` | Flow 画布、节点、边、缩放和平移继续围绕 React Flow 能力建设 |
| Markdown 阅读 | `react-markdown` + `remark-gfm` | `src/renderer/components/MarkdownContent.tsx` | Markdown 是正式文档真源的主要阅读渲染路径 |
| 表格工件 | `exceljs` + CSV/TSV 解析 | `src/main/services/table-artifact-service.ts` | XLSX 解析和写出留在 main service，Renderer 不直接解析 Office 文件 |
| Schema/契约 | `zod` + TypeScript 类型 | `src/shared/*` | 共享契约优先落在 `src/shared/`，服务边界再做校验 |
| 图标 | `lucide-react` | `src/renderer/components/*` | 图标按钮优先用 lucide，不手写一套图标系统 |
| 单测 | Vitest | `tests/unit/`, `scripts/run-vitest-with-report.mjs` | 服务、契约、边界和治理逻辑走单测 |
| E2E | Playwright | `tests/e2e/` | Electron 用户路径、UI 合同和打包态验证走 Playwright |

## 3. 不选什么

1. 不把 Cyber Editor 做成浏览器网页应用；桌面文件系统、窗口、打包态和本地工程是核心约束。
2. 不引入第二套状态管理框架承载业务规则；跨域规则必须收敛到 main services 或 shared contracts。
3. 不在 Renderer 直接读写磁盘、解析 XLSX、安装远程资源或执行副作用。
4. 不把模板、角色、导出结构、Provider 默认值和业务流程写死在通用代码里。

## 4. 选型边界

1. 新页面默认使用现有 React 组件体系和 `src/renderer/styles.css`，除非先完成样式拆分设计。
2. 新 IPC 必须先进入 `preload.ts` 白名单和 `register-*.ts` owner，不允许 Renderer 直接拼通道名。
3. 新运行时对象必须先进入 `src/shared/types.ts` 或对应 shared contract 文件。
4. 新资源安装能力必须经过 `ResourceGovernanceService` 或等价治理入口。
5. 新打包态用户功能必须补 Playwright 或 packaged smoke 证据。

## 5. 当前技术债

1. `App.tsx`、`OrchestrationWorkspace.tsx`、`styles.css`、`runtime-service.ts`、`types.ts` 和 `project-service.ts` 已是热点文件，继续堆功能会提高回归风险。
2. 编排画布虽然用了 React Flow，但拖拽、右键、面板缩放、运行态和自然语言 patch 还没有完全拆出稳定子模块。
3. `src/shared/types.ts` 聚合过大，长期应按工程、运行时、资源、知识底座和证据域拆分。
4. IPC 文档必须以 `preload.ts` 和 `src/main/ipc/register-*.ts` 为准持续同步。
