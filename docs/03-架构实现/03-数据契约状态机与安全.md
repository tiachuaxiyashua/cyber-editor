# 03 数据契约、状态机与安全

## 文件契约

| 文件 | 作用 |
|---|---|
| project manifest | 工程元数据、版本、最近状态 |
| flow manifest | Flow、节点、边、布局、运行配置 |
| run event log | 运行事件、节点状态、错误、checkpoint |
| artifact catalog | 工件、版本、来源、失效状态 |
| evidence index | 证据、引用、审批、写回、测试 |
| settings | Provider、模型、安全和 UI 偏好 |

## 状态机

### Run

`idle -> running -> waiting_approval -> paused -> running -> completed`

失败路径：

`running -> failed -> recovering -> running`

取消路径：

`running -> cancelling -> cancelled`

### Node

`pending -> ready -> running -> succeeded`

失败路径：

`running -> failed -> retrying -> running`

跳过路径：

`ready -> skipped`

### Artifact

`draft -> current -> stale -> regenerating -> current`

冲突路径：

`current -> conflict -> merging -> current`

### Approval

`created -> pending -> approved`

拒绝路径：

`pending -> rejected -> rollback_or_replan`

## 版本和迁移

1. 所有持久化对象必须有 schemaVersion。
2. 缺字段必须有默认值策略。
3. 不兼容版本必须阻断并提示迁移。
4. 自动修复必须写入审计记录。

## 安全治理

| 场景 | 要求 |
|---|---|
| 本地文件写入 | 展示目标、差异、可回滚方式 |
| 技能安装 | 展示来源、权限、文件清单、风险 |
| 模板导入 | 校验版本、签名或来源可信度 |
| 外部命令 | 展示命令、工作目录、影响范围 |
| 密钥配置 | 不进入文档、不进入日志、不被导出 |
| 高风险副作用 | 必须人工确认和审计 |

## 日志要求

日志必须能帮助恢复和追溯，但不能泄露密钥、完整敏感内容或用户私有上下文。
