## 当前状态机口径

### Run

主路径：

`queued -> running -> waiting-approval / merge-required / pause-requested -> paused / running -> completed`

失败与恢复：

`running -> failed -> recovering -> running`

取消：

`running -> cancelling -> cancelled`

### Node

主路径：

`pending -> ready -> running -> succeeded`

失败与重试：

`running -> failed -> retrying -> running`

阻断与跳过：

`ready -> skipped`

### Artifact

主路径：

`draft -> current -> stale -> regenerating -> current`

冲突与治理：

`current -> conflict -> merging -> current`

### Approval

主路径：

`created -> pending -> approved`

拒绝路径：

`pending -> rejected -> rollback_or_replan`

## 版本和迁移

1. 持久化对象必须带版本字段或等价迁移口径，不能靠隐式猜测结构。
2. 缺字段必须有默认值策略，不能因为旧数据缺字段直接白屏或崩溃。
3. 不兼容版本必须阻断，并给出明确修复或迁移提示。
4. 自动修复、降级或回滚必须写入审计或证据记录。

## 安全治理

| 场景 | 当前 owner | 要求 |
|---|---|---|
| 本地文件写入与 AI 写回 | `ProjectService`, `HumanAiMergeService`, `DocumentSnapshotService` | 展示目标、差异、冲突和恢复方式 |
| 模板/技能/角色导入 | `ResourceGovernanceService`, 各 Registry Service | 校验来源、结构、阻断可执行文件、输出 review gate 结果 |
| 本地副作用执行 | `SideEffectGovernanceService`, `CapabilityRuntime` | 先预览，再审批，再执行，审批失效要阻断 |
| 工件导出 | `ArtifactGovernanceService`, `DeliveryExportService` | 导出前检查工件失效与阻断项，落治理证据 |
| 外部命令/脚本工具 | `PlatformService`, `CapabilityRuntime`, `NetworkTargetGuard`, `RemoteFetchGuard` | 展示命令、工作目录、影响范围，必要时审批 |
| 密钥与 provider 配置 | `SettingsStore`, `AiService` | 不进入文档、不进入导出、不进入明文审计日志 |

## 日志与证据要求

1. 日志必须帮助恢复和追溯，但不能泄露密钥、完整敏感内容或用户私有上下文。
2. 证据不能只留在内存里，必须有 `.project/evidence/` 下的可复查记录。
3. 资源导入、副作用、审批、上下文包、工件治理都必须进入证据体系，而不是散落在 UI 状态里。
