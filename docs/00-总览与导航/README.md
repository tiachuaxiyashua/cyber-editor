# 00 总览与导航

本目录只做阅读导航和跨层索引，不替代 `01-需求与PRD/`、`02-产品设计/`、`03-架构实现/`、`04-测试验收/` 或 `06-详细设计库/` 的裁决职责。

## 一句话需求

Cyber Editor 是一个以编排层为核心的桌面图文工作台，帮助用户把模糊想法逐步沉淀为结构化文档、流程和可交付文本产物。

权威来源：[04-详细需求基线](../01-需求与PRD/04-详细需求基线.md)。

## 核心需求

1. 文档和图文工件必须围绕真实工程文件工作。
2. 编排页必须是一等主工作面，支持从无工程先编排，也支持从模板创建工程。
3. AI 会话、阶段、审查、写回和证据必须可见、可追溯、可恢复。
4. 模板、角色包、技能、连接和导出结构必须是可变资产，不能硬编码成单一业务场景。
5. 大工程上下文必须通过索引、检索、固定/排除和 provenance 管理，不能只靠一次性读全文。

权威来源：[产品定位](../01-需求与PRD/01-产品定位与目标用户.md)、[用户旅程](../01-需求与PRD/02-用户旅程与信息架构.md)、[详细需求基线](../01-需求与PRD/04-详细需求基线.md)。

## 核心功能

1. 平台入口、模板中心与双主入口。
2. 工程、文件、文档编辑、表格工件和图文嵌入。
3. AI 会话、阶段 guard、结构化生成、审查和写回保护。
4. Flow 画布、节点、角色、连接、工具、运行、调试、快照和导出。
5. 技能、角色包、Provider profile、资源治理和远程资源安装。
6. 知识索引、混合检索、上下文包、provenance 和思路地图。
7. 打包、测试门禁、运行证据和交付质量治理。

权威来源：[功能范围与优先级](../01-需求与PRD/03-功能范围与优先级.md)、[功能树](../01-需求与PRD/05-功能树.md)、[功能清单](../01-需求与PRD/06-功能清单.md)。

## 功能分级

功能分级采用 `MSABC`：

| 等级 | 含义 | 文档要求 |
|---|---|---|
| M | 必需 | 入口、前置、主操作、成功、失败、恢复都必须明确 |
| S | 核心特色 | 核心对象、页面层级、状态变化、输入输出契约、阻塞条件必须明确 |
| A | 重要 | 用户动作、主要反馈、异常处理和主路径关系必须明确 |
| B | 增强 | 可以延后，但不能改变对象边界 |
| C | 可选 | 可以延后，不能伪装成已完成能力 |

权威来源：[功能清单](../01-需求与PRD/06-功能清单.md)。

## 框架方案选型

框架和依赖选型统一看 [06-框架方案选型](../03-架构实现/06-框架方案选型.md)。

当前代码采用 Electron + Vite + React + TypeScript；编排画布使用 `@xyflow/react`；Markdown 阅读使用 `react-markdown` 与 `remark-gfm`；表格解析使用 `exceljs`；测试使用 Vitest 与 Playwright。

## 软件总体实现思路

实现链路固定为：

`Renderer 页面 / hooks -> preload 白名单 -> IPC 注册 -> main services -> 工程文件或 .project runtime/evidence -> BootstrapData/UI`

权威来源：[系统架构与分层 Owner](../03-架构实现/01-系统架构与分层Owner.md)、[AI 编排运行时](../03-架构实现/02-AI编排运行时.md)、[代码目录与 Owner 映射](../03-架构实现/05-代码目录与Owner映射.md)。
