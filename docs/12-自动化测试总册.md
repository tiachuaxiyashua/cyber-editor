# 12 自动化测试总册

## 1. 目标
1. 固定 Cyber Editor 自动化测试的执行顺序、覆盖范围和通过标准。
2. 明确每类测试覆盖哪些功能域、调用哪些脚本、产出哪些证据。
3. 让另一名程序员或另一套 AI 不需要猜测“应该跑哪些命令才算完成验证”。

## 2. 测试分层
### 2.1 静态验证
- 命令：`npm run lint`
- 目的：TypeScript 编译期校验，不允许存在类型错误、遗漏的 prop、无效导入。
- 通过标准：命令退出码为 `0`。

### 2.2 单元测试
- 命令：`npm run test:unit`
- 目的：校验共享规则、运行时服务、结构化生成、引用图、模型路由等纯逻辑模块。
- 通过标准：`vitest` 全绿，退出码为 `0`。

### 2.3 Electron 端到端测试
- 命令：`npm run test:e2e`
- 目的：校验欢迎页、模板中心、主工作台、编排页、技能/设置页等用户路径。
- 通过标准：Playwright Electron 测试全部通过，退出码为 `0`。

### 2.4 打包态冒烟测试
- 命令：`npm run package`
- 命令：`npm run test:packaged-smoke`
- 目的：确认打包后的可执行文件能启动并完成基础路径。
- 通过标准：生成 `out/package/.../Cyber Editor.exe`，且 Playwright 打包态 smoke 通过。

### 2.5 闭环回归
- 命令：`npm run demo:closed-loop`
- 命令：`npm run demo:closed-loop:regression`
- 命令：`npm run test:packaged-closed-loop`
- 命令：`npm run demo:packaged-closed-loop:regression`
- 目的：确认从需求输入到文档/Flow/导出闭环仍可运行。
- 通过标准：回归脚本退出码为 `0`，并产出闭环报告。

## 3. 执行前提
1. 已执行 `npm install`。
2. 若首次运行 Playwright：先执行 `npm run test:install-browsers`。
3. 若要校验本地模型链路：
   - 本机已安装 Ollama
   - 已拉取 `qwen3:8bm`
   - `ollama serve` 正在运行
4. 若要做打包态验证：
   - 目标平台为 Windows
   - 当前工作目录没有被旧的 `Cyber Editor.exe` 占用

## 4. 推荐执行顺序
1. `npm run lint`
2. `npm run test:unit`
3. `npm run build`
4. `npm run test:e2e`
5. `npm run package`
6. `npm run test:packaged-smoke`
7. 需要闭环时再跑：
   - `npm run demo:closed-loop`
   - `npm run demo:closed-loop:regression`
   - `npm run test:packaged-closed-loop`

## 6. 功能域到自动化测试映射

| 功能域 | 主要测试文件 | 覆盖重点 | 判定标准 |
|---|---|---|---|
| 模板中心与双主入口 | `platform-mvp.spec.ts`, `recent-projects.spec.ts`, `smoke.spec.ts` | 欢迎页、最近工程、创建工程、模板入口 | 主入口可达，模板/工程路径可创建或重开 |
| 文档工作台 | `workbench-basics.spec.ts`, `note-references.spec.ts`, `ui-review.spec.ts` | 文件树、文档标签、引用关系、编辑视图 | 文件打开/切换/保存一致，引用关系刷新正确 |
| AI 会话与阶段控制 | `platform-mvp.spec.ts`, `user-behavior-ollama.spec.ts` | 消息发送、阶段 guard、真实本地模型 | 运行状态、消息增长、阶段结果与错误反馈正确 |
| 编排页与 Flow 编辑器 | `critical-editor-workflows.spec.ts`, `ui-global-scan.spec.ts` | 节点创建、连线、Inspector、布局与紧凑宽度 | 关键对象可编辑，页面不崩溃，不出现布局遮挡 |
| 工件契约与导出 | `critical-editor-workflows.spec.ts`, 闭环脚本 | 工件目录、导出映射、OpenSpec/文本导出 | 目标目录与导出文件存在且结构正确 |
| 技能/连接/模型 | `platform-mvp.spec.ts`, `user-behavior-ollama.spec.ts` | provider profile、Ollama、本地技能目录 | 选择即激活、模型可生成、安装点击有效 |
| 系统壳层与布局 | `ui-review.spec.ts`, `ui-global-scan.spec.ts`, `packaged-smoke.spec.ts` | 窗口、拖拽、浅深色、打包启动 | 页面稳定、打包后可启动、缩放不跑版 |

## 7. 自动化测试 oracle
1. 若功能是 `M` 级：
   - 必须存在自动化测试
   - 且至少覆盖一个失败路径
2. 若功能是 `S` 级：
   - 必须存在单测或 e2e
   - 若涉及多层联动，必须有 e2e
3. 若功能是 `A` 级：
   - 至少要有单测、e2e、或被更高层闭环测试间接覆盖，并在原子文档中明确写出
4. 若自动化测试不存在，只能标记为 `部分完成` 或 `未完成`，不能标记为 `已完成`。

## 8. 失败分类与处理
### 8.1 代码层失败
- 现象：`npm run lint` 非零退出
- 处理：先修类型错误，再继续运行任何 e2e

### 8.2 逻辑层失败
- 现象：单元测试失败
- 处理：根据失败模块回到对应的开发设计和代码唯一性文档

### 8.3 UI 路径失败
- 现象：Playwright Electron e2e 失败
- 处理：
  1. 先看失败用例对应功能域
  2. 再看 [11-复杂页面状态矩阵](./06-代码唯一性文档/11-复杂页面状态矩阵.md)
  3. 若是交互语义问题，再看 [17-页面动作矩阵](./06-代码唯一性文档/17-页面动作矩阵.md)

### 8.4 打包态失败
- 现象：`package` 或 `packaged-smoke` 失败
- 处理：
  1. 检查旧的 `Cyber Editor.exe` 是否仍在运行
  2. 检查 `out/package` 是否被占用
  3. 必要时重跑 `npm run package`

## 9. 产出物与证据
自动化测试运行后应可在这些位置看到证据：
- 代码与测试映射：见 [14-代码测试运行证据矩阵.md](./14-代码测试运行证据矩阵.md)
- UI 截图：`artifacts/ui-review/`、`artifacts/ui-global-scan/`
- 闭环报告：`artifacts/closed-loop/`、`artifacts/closed-loop-regression/`、`artifacts/packaged-closed-loop-regression/`
- 打包产物：`out/package/`、`out/make/`

## 10. 完成定义
只有当以下 4 项同时成立时，才能说某个功能域通过自动化验证：
1. 该功能域对应命令全部执行成功。
2. 对应测试文件全部通过。
3. 对应产出物或证据文件存在。
4. [03-功能清单.md](./03-功能清单.md) 中的状态与测试结果一致。
