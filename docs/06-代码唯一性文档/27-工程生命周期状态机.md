# 27 工程生命周期状态机

## 1. 目标
固定工程从未打开到已打开、脏状态、关闭、切换、导出之间的状态跃迁。

## 2. 状态集合
- `no_project`
- `creating_project`
- `opening_project`
- `project_ready`
- `project_dirty`
- `project_conflict`
- `project_exporting`
- `project_closing`
- `project_error`

## 3. 状态跃迁
### 3.1 无工程到工程就绪
1. `no_project -> creating_project`
   - 触发：用户在欢迎页点击“创建工程”
2. `creating_project -> project_ready`
   - 条件：目录创建成功、manifest 写入成功、bootstrap 返回成功
3. `creating_project -> project_error`
   - 条件：路径非法、模板脚手架失败、manifest 写入失败

### 3.2 打开已有工程
1. `no_project -> opening_project`
2. `opening_project -> project_ready`
   - 条件：工程目录存在、manifest 可读、bootstrap 成功
3. `opening_project -> project_error`
   - 条件：目录缺失、manifest 损坏、bootstrap 失败

### 3.3 工程脏状态
1. `project_ready -> project_dirty`
   - 条件：任一文档、flow draft、设置变更未保存
2. `project_dirty -> project_ready`
   - 条件：保存成功、脏集合为空

### 3.4 冲突态
1. `project_dirty -> project_conflict`
   - 条件：外部修改被检测到且与本地草稿冲突
2. `project_conflict -> project_ready`
   - 条件：用户选择覆盖外部或接受外部并完成同步

### 3.5 导出与关闭
1. `project_ready|project_dirty -> project_exporting`
2. `project_exporting -> project_ready`
   - 条件：导出成功
3. `project_ready|project_dirty -> project_closing`
4. `project_closing -> no_project`
   - 条件：用户确认关闭、必要保存已完成

## 4. 禁止行为
1. `project_dirty` 不得直接静默回到 `no_project`。
2. `project_conflict` 不得自动覆盖用户内容。
3. `project_error` 不得伪装成 `project_ready`。

## 5. UI 约束
1. `no_project`：显示欢迎页或无工程编排页。
2. `project_ready`：显示主工作台。
3. `project_dirty`：标签、页头或状态栏显示脏标记。
4. `project_conflict`：必须弹出冲突决策 UI。

## 6. 测试 Oracle
1. 创建工程失败时必须停留在原页面并显示错误。
2. 切换工程前若存在脏状态，必须进入确认流程。
3. 工程关闭后，最近工程列表必须更新。
