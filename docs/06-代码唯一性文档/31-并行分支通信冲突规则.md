# 31 并行分支通信冲突规则

## 1. 目标
固定并行分支之间如何共享工件、交换消息、解决冲突。

## 2. 通道类型
- `read_only_artifact`
- `branch_message`
- `control_signal`
- `join_payload`

## 3. 规则
1. 并行分支默认只能读取共享工件，不可直接写同一正式工件。
2. 若多个分支需要产出结果，必须各写各自分支工件，再由 `parallel_join` 合并。
3. 分支消息只允许写到分支级临时消息区，不允许覆盖正式工件。
4. 控制信号只能影响流程走向，不可承载业务正文。

## 4. 冲突类型
### 4.1 正式工件写冲突
- 条件：两个分支都想写同一路径
- 处理：运行前阻断，不允许开始

### 4.2 临时消息命名冲突
- 条件：两个分支写相同 message key
- 处理：自动加 branch namespace，例如 `branchA.review_packet`

### 4.3 汇合输入缺失
- 条件：汇合策略要求全部成功，但某分支未产出
- 处理：进入 `join_blocked` 或 `join_failed`，取决于策略

## 5. 汇合策略
- `all_success`: 所有分支成功且全部工件齐全
- `any_success`: 至少一条成功
- `quorum(n)`: 达到 n 条成功

## 6. 测试 Oracle
1. 同工件并发写必须在运行前被拦截。
2. 分支消息必须带命名空间。
3. 汇合结果必须能追溯来源分支。
