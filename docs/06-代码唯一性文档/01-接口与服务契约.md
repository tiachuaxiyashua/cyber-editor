# 01 接口与服务契约

## 1. 总边界
- Renderer：
  - 负责页面显示、局部交互、输入态、选中态、草稿态
- Main：
  - 负责文件系统、目录选择、导出、Provider 调用、运行控制、索引刷新、持久化
- Service：
  - 负责主进程中的业务能力封装
- Shared：
  - 负责跨进程类型、Schema 和纯函数契约

## 2. 禁止边界
- Renderer 不能直接：
  - 写工程文件
  - 修改模板注册表
  - 直接调用 Ollama / DeepSeek
  - 直接改写 Flow 持久化文件
- Main / Service 不能直接决定页面布局，只能返回结构化状态。

## 4. 统一返回契约
1. 所有 IPC 返回值必须是对象。
2. 所有失败都必须返回统一错误对象：
```json
{
  "error": {
    "code": "string",
    "message": "string",
    "recoverable": true,
    "details": {}
  }
}
```
3. 所有会改变工作台核心状态的 IPC，都必须返回足够让 Renderer 同步 UI 的结构化结果。

## 5. 唯一性要求
1. 不允许不同页面重复发明同义 IPC。
2. 不允许同一动作有两套成功结构。
3. 不允许“保存成功但 bootstrap 不刷新”这类半更新路径。
