# 39 知识底座索引与刷新状态机

## 1. 目标
固定知识底座从初始未建索引、增量刷新、过期、损坏到恢复的状态跃迁。

## 2. 状态集合
- `index_absent`
- `index_building`
- `index_ready`
- `index_stale`
- `index_refreshing`
- `index_damaged`
- `index_recovering`

## 3. 跃迁
1. `index_absent -> index_building`
   - 条件：首次打开工程或首次启用知识底座
2. `index_building -> index_ready`
   - 条件：初次索引完成
3. `index_ready -> index_stale`
   - 条件：文档、flow、template、role、artifact 任一源对象变化
4. `index_stale -> index_refreshing`
   - 条件：自动增量刷新或用户手动刷新
5. `index_refreshing -> index_ready`
   - 条件：增量刷新成功
6. `index_building|index_refreshing -> index_damaged`
   - 条件：索引文件损坏、schema 不匹配、关键分片缺失
7. `index_damaged -> index_recovering`
   - 条件：用户选择重建索引
8. `index_recovering -> index_ready`
   - 条件：全量重建成功

## 4. UI 约束
1. `index_stale` 时必须显示新鲜度提示。
2. `index_damaged` 时必须阻止“已验证准确”的表述，并提供重建入口。
3. 刷新过程中允许继续使用旧索引，但必须标记 `stale_index_warning`。

## 5. 测试 Oracle
1. 修改文档后必须能从 `index_ready` 进入 `index_stale`。
2. 手动刷新后必须回到 `index_ready`。
3. 索引损坏时不得静默返回空结果。
