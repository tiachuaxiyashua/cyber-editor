# 14 组件层级与职责表

## 1. 目标
- 固定高风险页面和复杂功能域的组件树边界。
- 防止另一套 AI 用不同的组件切分方式实现同一功能，导致状态源、事件路径和测试选择器分叉。

## 2. 唯一性规则
- `页面级容器 -> 域级面板 -> 功能级组件 -> 原子控件` 四层结构必须保留。
- `页面级容器` 负责页面路由、bootstrap 消费、面板布局和顶层命令。
- `域级面板` 负责单一区域的状态聚合，不得跨域直接改写其他区域状态。
- `功能级组件` 负责单一对象或单一操作链路。
- `原子控件` 只负责展示和触发事件，不持有业务状态。

## 7. 组件职责硬约束
- `DocumentWorkspace` 不得直接改写工程级最近记录。
- `CanvasViewport` 不得持久化 flow；只能发出草稿更新事件。
- `NodeInspector` 不得自行决定节点位置；节点位置只来自 `FlowDraft.nodes[].position`。
- `ProviderProfilePanel` 不得直接调用模型；它只负责配置与诊断。
- `ConversationComposer` 不得直接发起主进程外请求；必须走统一 IPC。

## 8. 测试 Oracle
- 任一页面的主要区域都能映射到唯一组件树，不允许出现同一职责落在两个并行组件上。
- 同一操作链路只允许一个状态源。
- 组件销毁与重建不得导致业务状态丢失，除非状态定义明确属于局部临时态。
