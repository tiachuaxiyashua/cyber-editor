# 19 关键动作时序图

## 1. 目标
- 固定高风险主路径的事件顺序。
- 防止另一套 AI 在“什么时候校验、什么时候写盘、什么时候刷新 UI”上做出不同实现。

## 2. 从模板创建工程
1. 用户在模板中心选择模板。
2. Renderer 更新 `selectedTemplateId`。
3. 用户点击“从模板创建工程”。
4. Renderer 打开工程创建表单，并预填模板信息。
5. 用户输入工程名、父目录、是否新建文件夹。
6. Renderer 本地做字段级校验。
7. 用户点击“创建”。
8. Renderer 调用 `project.create`。
9. Main 侧执行：
   - 校验路径
   - 创建目录
   - 写 manifest
   - 复制模板脚手架
   - 更新最近工程
10. Main 返回 `projectSummary + bootstrap`。
11. Renderer 切换到工作台或指定入口页面。
12. 若失败，保持表单不关闭，并在原位展示错误。

## 3. 发送消息并生成运行
1. 用户在会话输入框输入内容。
2. Renderer 本地校验非空。
3. 用户点击发送。
4. Renderer 立即创建本地 optimistic message。
5. Renderer 调用 `session.sendMessage`。
6. Main 侧创建 `runAccepted`。
7. Main 开始运行，持续推送 `runtime.events`。
8. Renderer 根据事件流更新：
   - 运行状态
   - 过程面板
   - 消息流
9. 运行成功后，消息转正并写入会话历史。
10. 运行失败后，消息保留但标记失败，并显示重试入口。

## 4. 生成阶段草稿
1. 用户在流程面板点击“生成阶段草稿”。
2. Renderer 先调 `stage.guard`。
3. 若 guard 未通过：
   - 不发起 run
   - 直接显示阻断原因
4. 若 guard 通过：
   - 调 `stage.generateDraft`
5. Main 创建阶段 run。
6. Main 生成草稿，写工件。
7. Main 返回事件流：
   - run started
   - generation started
   - artifact written
   - run completed
8. Renderer 刷新工件状态、阶段状态和文档区。

## 5. 阶段确认
1. 用户点击“确认当前阶段”。
2. Renderer 调 `stage.guard` 再校验一次。
3. guard 未通过则阻止确认。
4. guard 通过再调 `stage.confirm`。
5. Main 写阶段确认记录并更新阶段状态。
6. Renderer 刷新流程面板和会话栏。

## 6. 编排页拖拽节点进入画布
1. 用户从节点库拖拽小卡片。
2. Renderer 在画布上显示拖拽预览。
3. 用户松手。
4. Renderer 计算画布坐标。
5. Renderer 在 `flowDraft.nodes` 追加新节点。
6. 画布立即重绘。
7. Inspector 自动切到新节点。
8. 若用户未保存，`flowDraft.dirty=true`。

## 7. 编排页保存 Flow
1. 用户点击保存。
2. Renderer 本地先跑 flow 基础校验。
3. 基础校验失败则阻止保存，定位问题。
4. 校验通过后调 `flow.save`。
5. Main 写持久化文件。
6. Main 返回新的 `flowDraft + saveMeta`。
7. Renderer 清除 dirty 状态，但不改变节点位置。

## 8. 运行 Flow
1. 用户点击“运行”。
2. Renderer 先跑本地结构校验。
3. Renderer 调 `flow.run`。
4. Main 侧：
   - 校验输入目录
   - 校验输出目录
   - 校验阶段契约
   - 校验节点 IO
5. 若任一不满足，返回 `run_blocked`。
6. 若满足，创建 run 并推送事件。
7. Renderer 打开运行抽屉。
8. 运行过程中持续刷新节点状态、控制台和变量预览。

## 9. 保存为模板
1. 用户在工程或无工程编排模式点击“保存为模板”。
2. Renderer 打开模板保存表单。
3. 用户填写模板名称、版本、说明。
4. Renderer 调 `template.saveCurrentProject` 或 `template.saveCurrentFlow`。
5. Main 校验模板目录结构后写入模板中心。
6. 成功后模板中心列表立即可见该模板。

## 10. 测试 Oracle
- 所有关键主路径都必须符合上述顺序。
- 允许附加内部事件，不允许跳过关键校验点。
- “先写盘后校验”“先切页面后返回失败”等顺序都视为错误实现。
