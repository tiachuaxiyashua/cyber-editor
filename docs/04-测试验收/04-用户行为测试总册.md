# 04 用户行为测试总册

## 1. 目标
1. 用用户视角验证 Cyber Editor 的主路径、异常路径和关键高频操作。
2. 让手工测试不再依赖个人记忆，而是有固定步骤、预期结果和失败判定。
3. 把“小白默认怎么用”和“高手如何进入深层能力”一起纳入验证。

## 2. 测试前提
1. 运行环境为 Windows 桌面端。
2. 本地已安装依赖，若测试开发态则可运行 `npm run dev`。
3. 若测试打包态，则使用：
   - `out/package/Cyber Editor-win32-x64/Cyber Editor.exe`
   - 或安装器 `out/make/squirrel.windows/x64/Cyber-Editor-Setup-0.1.0.exe`
4. 若验证本地模型：
   - Ollama 已启动
   - 已安装 `qwen3:8bm`
5. 若验证技能目录导入：
   - 准备一个本地技能包目录
6. 若验证模板导入：
   - 准备一个本地模板包目录

## 3. 测试原则
1. 每一步都必须有“动作”和“预期结果”。
2. 若某一步预期不成立，该路径直接判定失败，不得口头解释为“应该是可优化项”。
3. 高风险功能必须验证失败路径：
   - 路径非法
   - guard 不满足
   - 模型不可用
   - 模板损坏
   - 输出目录缺失

## 4. 主路径测试
### 4.1 首次启动与欢迎页
1. 动作：启动程序。
   - 预期：出现欢迎页，不崩溃，不直接落入未知视图。
2. 动作：观察首屏主入口。
   - 预期：能明显看到“创建工程”和“创建编排”两条主路径。
3. 动作：查看最近工程与最近模板区域。
   - 预期：空状态时有明确引导；有数据时可点击。

### 4.2 新建工程
1. 动作：点击“新建工程”。
   - 预期：进入新建工程/模板中心，不被遮挡。
2. 动作：选择“创建新文件夹”。
   - 预期：可选择父目录并输入工程名，非法名称会被阻断。
3. 动作：选择一个模板后创建。
   - 预期：进入工作台，工程目录被创建，模板内容已落盘。
4. 动作：返回欢迎页，点击最近工程。
   - 预期：可重新打开同一工程。

### 4.3 无工程直接开始编排
1. 动作：在欢迎页点击“开始编排”。
   - 预期：可进入编排页草稿模式。
2. 动作：保存当前 Flow 草稿。
   - 预期：可保存为草稿、模板或绑定工程，不要求先有工程。
3. 动作：从该草稿返回欢迎页。
   - 预期：最近编排或最近模板入口可再次找到它。

### 4.4 文档工作台
1. 动作：打开多个文档。
   - 预期：出现多个标签页，可切换、关闭、恢复。
2. 动作：在阅读/编辑/源码间切换。
   - 预期：三种视图状态变化正确，内容一致。
3. 动作：编辑 Markdown、插入 Mermaid、插入思维导图、粘贴图片。
   - 预期：内容能正常显示或保存，渲染态可见。
4. 动作：修改文档后关闭或切换。
   - 预期：脏状态可见，保存后消失。

### 4.5 引用关系
1. 动作：在两篇笔记中互相添加链接。
   - 预期：右侧上下文能显示正向和反向引用。
2. 动作：切到“引用对比”。
   - 预期：能比较两篇笔记的引用差异，不显示旧数据。

### 4.6 AI 会话与阶段控制
1. 动作：配置本地 provider，选中 `Ollama qwen3:8bm`。
   - 预期：选中即激活，不需要额外“激活”按钮。
2. 动作：在 AI 会话栏发送一条需求消息。
   - 预期：出现运行状态，模型返回可见消息。
3. 动作：不满足 guard 时尝试阶段确认。
   - 预期：应被阻断，并显示原因。
4. 动作：满足条件后生成阶段草稿并确认。
   - 预期：对应工件写入磁盘，阶段状态变化可见。

### 4.7 编排页
1. 动作：进入编排页。
   - 预期：左侧资产栏、节点库、画布、Inspector、运行区层级清晰。
2. 动作：从节点库拖拽节点到画布。
   - 预期：节点以拖拽方式进入，不是只能点击创建。
3. 动作：连线两个节点。
   - 预期：连线方向可读，边不会莫名消失。
4. 动作：配置条件、循环、并行、子流程节点。
   - 预期：Inspector 中有明确字段，不是空壳。
5. 动作：双击或对象级操作进入子流程。
   - 预期：能直接进入子流程编辑，并可返回。
6. 动作：拖动节点位置、切换面板、保存再重开。
   - 预期：节点位置不被重置。
7. 动作：缩小窗口并拖动左右面板。
   - 预期：不出现遮挡、竖排挤压或无法点击的区域。

### 4.8 工件契约与导出
1. 动作：配置 Flow 的输入目录、输出目录。
   - 预期：目录字段可编辑，可校验非法路径。
2. 动作：配置阶段输出契约、节点 IO、导出映射。
   - 预期：配置项清晰，修改后保存有效。
3. 动作：导出 `md/txt/pdf` 或 `OpenSpec`。
   - 预期：文件实际出现在目标目录，结构符合映射。

### 4.9 模板中心
1. 动作：打开模板中心。
   - 预期：可以搜索、筛选、查看模板详情。
2. 动作：导入模板。
   - 预期：可通过深层入口完成导入，状态变化可见。
3. 动作：保存当前工程为模板。
   - 预期：模板中心能看到新模板。
4. 动作：检查模板版本、来源、兼容性、信任状态。
   - 预期：有显式展示，不是隐藏字段。

### 4.10 技能、连接与模型
1. 动作：进入技能/连接中心。
   - 预期：已安装技能、可安装来源、连接状态可见。
2. 动作：从目录安装技能。
   - 预期：弹出目录选择并实际安装，不是点击无反应。
3. 动作：设置技能启用范围。
   - 预期：全局、工程、会话三级范围可见。
4. 动作：删除或禁用技能。
   - 预期：状态变化可见，引用中的阻断逻辑明确。

### 4.11 设置与布局
1. 动作：打开设置页，编辑 provider profiles。
   - 预期：字段可输入、可保存、重开后仍在。
2. 动作：拖动工作台三栏宽度并重启程序。
   - 预期：宽度被记忆。
3. 动作：切换深浅主题。
   - 预期：页面风格保持一致，不出现乱码或错位。

## 5. 高风险失败路径
### 5.1 guard 失败
- 动作：在没有必需输入时确认阶段。
- 预期：阻断 + 明确缺失项。

### 5.2 模型失败
- 动作：停掉 Ollama，再触发模型生成。
- 预期：出现可理解的错误，而不是静默失败。

### 5.3 模板损坏
- 动作：导入不完整模板包。
- 预期：阻断安装，并显示原因。

### 5.4 编排页损坏
- 动作：写入无效 Flow draft 后重新打开。
- 预期：进入错误态和恢复路径，不直接白屏。

## 6. 失败判定标准
以下任一出现即判定用户行为测试失败：
1. 用户看不到主入口或主动作。
2. 点击无反应，且没有禁用解释。
3. 页面切换后出现遮挡、错位、无法恢复。
4. 本应被阻断的操作被放行。
5. 本应写盘的文件没有生成。
6. 本应提示的错误没有提示。

## 7. 测试结果记录方式
每条路径记录：
1. 测试环境
2. 执行动作
3. 实际结果
4. 是否符合预期
5. 截图或文件证据路径
6. 对应原子功能 ID

## 8. 与自动化测试的关系
1. 自动化测试负责回归稳定性。
2. 用户行为测试负责真实可用性。
3. 若自动化通过、用户行为失败，仍视为功能未达成。
