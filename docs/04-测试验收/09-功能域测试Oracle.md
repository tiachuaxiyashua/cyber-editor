# 09 功能域测试 Oracle

## 1. 目标
- 把测试通过标准从“能跑”提升到“结果足够证明实现正确”。
- 防止另一套 AI 用更弱的断言伪造完成。

## 2. 模板中心与双主入口

### 必测
- 欢迎页点击 `开始编排` 进入无工程编排模式
- 欢迎页点击 `新建工程` 进入模板中心
- 模板中心选择模板但不创建时，不产生工程副作用
- 从模板创建工程进入工作台
- 从模板直接开始编排进入无工程编排模式
- 模板损坏时动作被阻断

### 通过标准
- 必须同时验证：
  - 页面层级变化
  - 主按钮可用性变化
  - 返回结构或 bootstrap 变化
  - 必要时文件系统变化

## 3. 文档工作台

### 必测
- 打开两个文档并切换标签
- 编辑文档进入脏状态
- 保存文档后脏状态清除
- Mermaid/Mindmap 打开正确
- 引用关系在保存后刷新
- 表格工件单独打开

### 通过标准
- 不能只断言 DOM 出现文案
- 必须断言：
  - 当前打开对象
  - 脏状态
  - 保存版本或结果
  - 引用关系变化

## 4. AI 会话与阶段

### 必测
- 发送消息后 run 生命周期完整可见
- 停止生成进入 `stopped`
- 失败后可重试，且生成新 run
- 没有输入时 guard 阻断阶段确认
- 补齐输入后 guard 放行
- 红蓝裁判过程有三段结果

### 通过标准
- 不允许只测“按钮是否可点”
- 必须断言：
  - `RuntimeRun.status`
  - `RuntimeEvent.type`
  - `StageGuardStatus`
  - 审查工件或过程块存在

## 5. 编排页

### 必测
- 节点库拖拽到画布
- 创建边并保持方向
- Inspector 编辑节点不重置位置
- 子流程从卡片直接打开
- 保存 Flow 后重开位置不变
- 紧凑宽度下仍可操作

### 通过标准
- 必须同时断言：
  - 画布对象数量
  - 节点位置
  - FlowDraft 保存结果
  - 页面布局未错位

## 6. 工件契约与导出

### 必测
- 配置输入目录/输出目录
- 配置阶段输出契约
- 配置节点 IO
- 配置导出映射
- 导出 md/txt/pdf
- 导出 openspec

### 通过标准
- 必须同时断言：
  - 配置持久化
  - 阶段阻断与放行
  - 导出目录结构
  - 文件格式存在

## 7. 技能、连接与模型

### 必测
- 从目录安装技能
- 设置技能范围
- 删除技能
- Provider 选择即激活
- Provider 连接测试
- 脚本工具不合法时阻断

### 通过标准
- 必须断言：
  - 列表变化
  - 范围状态变化
  - 当前激活 profile 变化
  - 结构化诊断结果

## 8. 知识索引与上下文管理

### 必测
- 手动刷新索引
- 关键词+语义+引用扩展搜索
- 上下文包推荐
- 引文来源和命中原因可见
- 增量刷新后新鲜度更新

### 通过标准
- 不能只返回文本答案
- 必须返回结构化搜索/上下文/引用结果

## 9. 打包与真实运行

### 必测
- 打包可启动
- 首屏欢迎页可进入双主路径
- 真实 Ollama 路径成功一次
- 基础 smoke 跑通

### 通过标准
- 任何声称“可用”的主路径都必须至少有一次：
  - 开发态证据
  - 打包态证据
  - 真实 provider 证据（涉及模型时）

## 10. 唯一性要求
- 如果某功能只有 happy path 测试，没有失败/阻断/恢复路径，则不算通过。
- 如果某功能只在 mock 下通过，没有真实主路径证据，则不能声明“用户可用”。
