# 05 代码测试运行证据矩阵

## 1. 目标
1. 把需求域、主代码文件、测试文件和运行证据串起来。
2. 明确“某个能力已经落到代码”和“某个能力已经被测过”的证据落点。
3. 让审计时不再只看文档描述，而能直接定位源代码、测试和产物。

## 2. 证据类型定义
- `代码证据`：主实现文件或主模块目录。
- `测试证据`：单测、e2e、回归脚本。
- `运行证据`：`artifacts/`、`out/` 下的报告、截图、产物。
- `状态口径`：仍以 [03-功能清单.md](../06-详细设计库/03-功能清单.md) 为准。

## 4. 自动化命令到证据路径

| 命令 | 主要目的 | 主要证据 |
|---|---|---|
| `npm run lint` | 类型与编译期一致性 | 命令退出码 |
| `npm run test:unit` | 逻辑层回归 | `vitest` 输出 |
| `npm run test:e2e` | Electron 开发态主路径 | Playwright 输出、`artifacts/ui-review/`, `artifacts/ui-global-scan/` |
| `npm run package` | 生成打包产物 | `out/package/Cyber Editor-win32-x64/Cyber Editor.exe`, `out/logs/package-trace.log` |
| `npm run test:packaged-smoke` | 打包态可启动与基础交互 | Playwright 输出 |
| `npm run demo:closed-loop` | 单场景闭环 | `artifacts/closed-loop/` |
| `npm run demo:closed-loop:regression` | 多场景闭环 | `artifacts/closed-loop-regression/` |
| `npm run test:packaged-closed-loop` | 打包态闭环 | `artifacts/packaged-closed-loop-regression/` |

## 5. 审计规则
1. 若一个功能域没有对应代码文件，不得标记为 `已完成`。
2. 若一个功能域没有对应测试文件或回归脚本，不得标记为 `已完成`。
3. 若一个功能域没有任何运行证据，只能标记为 `部分完成` 或 `未完成`。
4. 若代码、测试、运行证据之间互相对不上，以最保守状态为准。
