# 05 项目规则

本目录定义后续 AI、开发者和评审者必须遵守的工作规则。

## 当前治理目标

项目规则用于防止文档、代码和测试重新分裂。任何补全文档的工作都必须在 `docs/` 内完成，并以现有 PRD、代码 owner、用户路径和测试证据互相校验。

## 文件

1. `01-AI协作与文档维护规则.md`
2. `02-变更流程与完成定义.md`
3. `03-文档治理与交付行动路线.md`

## 作用

1. `01` 约束 AI 协作、文档维护和真相源管理。
2. `02` 约束变更流程、完成定义和交付口径。
3. `03` 约束从需求整理到开发、评审、归档的全链路工作方式。

## 文档修复规则

1. 不创建 `docs-old`、`archive-docs` 或代码外的新真相源。
2. 已损坏或过薄的设计页，应在原路径补齐；如果确需拆分，只能拆到 `docs/06-详细设计库/` 的对应分类。
3. 状态从“未完成”调整为“部分完成/已完成”前，必须同时核对代码 owner、用户可见入口和测试文件。
4. 代码已有能力但文档缺失时，先补文档，再决定是否需要补测试或实现缺口。
5. 发现代码文案、状态或持久化与文档冲突时，不得静默改代码；必须在相关文档写清当前事实和剩余差距。
