# 02 变更流程与完成定义

## 标准变更流程

1. 明确用户问题和目标。
2. 阅读相关 PRD、产品设计、架构实现、测试验收和详细设计库。
3. 判断是否需要修改 PRD。
4. 修改 UI、架构或代码。
5. 补测试。
6. 使用开发态验证。
7. 用户可见能力使用打包态验证。
8. 更新文档和交付说明。

## 完成定义

| 维度 | 必须满足 |
|---|---|
| PRD | 需求、旅程、范围和验收清楚 |
| UI | 用户能看到当前对象、下一步、阻断原因和恢复入口 |
| 架构 | owner 清楚，状态和业务不散落 |
| 运行时 | 长任务、审批、恢复、证据可闭环 |
| 数据 | schema、版本、迁移、错误恢复明确 |
| 安全 | 高风险动作有审查和审计 |
| 测试 | 主路径、失败路径、恢复路径可证明 |
| 打包态 | 用户可见功能最终可在打包应用中验证 |

## 交付说明必须包含

1. 改了哪些文件。
2. 解决了什么冲突。
3. 删除了什么过时结论，以及哪些实现细节已经迁移保留。
4. 运行了哪些验证。
5. 仍然存在什么风险。
