# 01 AI 协作与文档维护规则

## AI 开始工作前必须阅读

1. `docs/README.md`
2. `docs/01-需求与PRD/`
3. 与任务相关的 `docs/02-产品设计/`
4. 与任务相关的 `docs/03-架构实现/`
5. 与任务相关的 `docs/04-测试验收/`
6. 与任务相关的 `docs/06-详细设计库/` 详细材料

如果任务是全局重构、系统评审、UI 重构、运行时改造或发布验收，必须读完整个 `docs/`。

## 文档维护规则

1. 新增功能先改 PRD，再改设计，再改架构，再改测试。
2. 不新增平行真相源。
3. 不保留多个文件描述同一决策。
4. 同一内容必须合并到当前对应文件。
5. 冲突内容必须直接裁决，不写“待确认”逃避。
6. 过时结论可以删除，但其中尚未迁移的实现细节必须先进入 `06-详细设计库/` 或当前设计文件。
7. 文档必须短、清晰、可执行，同时不能牺牲必要的实现细节。

## 禁止事项

1. 禁止从既有实现反推产品真相。
2. 禁止用外部材料替代当前 PRD。
3. 禁止用 API 测试替代用户路径测试。
4. 禁止把“已完成”写成没有证据的状态。
5. 禁止新增任何平行文档目录或归档式真相源。
