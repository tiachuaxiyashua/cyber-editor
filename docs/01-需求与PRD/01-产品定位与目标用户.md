# 01 产品定位与目标用户

## 产品定位

Cyber Editor 是面向复杂文档、AI 协作和流程编排的桌面工作台。它不是普通 Markdown 编辑器，也不是单纯聊天工具，而是把“需求、文档、AI 运行、流程、工件、证据、测试”放在同一个可追溯工作空间里的生产工具。

## 核心价值

1. 帮用户把复杂任务拆成可执行流程。
2. 帮用户把 AI 输出写回文档、工件和证据，而不是停留在聊天记录。
3. 帮用户追踪每次生成、审批、修改、恢复和导出的来源。
4. 帮用户在长任务中暂停、恢复、局部重跑和处理冲突。
5. 帮团队把 PRD、设计、代码 owner、测试和交付门禁连接起来。

## 目标用户

| 用户 | 主要任务 | 必须得到的体验 |
|---|---|---|
| 产品负责人 | 定义需求、PRD、用户旅程、验收标准 | 不需要懂代码，也能看懂当前状态和下一步 |
| 架构师/技术负责人 | 拆 owner、定义接口、控制复杂度 | 文档能直接指导模块拆分和边界治理 |
| 开发者 | 根据 PRD 和设计实现功能 | 不需要猜文档优先级，不被冲突文档误导 |
| 测试负责人 | 验证主旅程、失败路径和发布质量 | 测试能证明用户可走通，不只证明 API 可调 |
| AI 工作流使用者 | 编排 Agent、运行流程、处理人工确认 | 当前节点、阻断原因、恢复动作始终可见 |

## 产品边界

Cyber Editor 必须优先成为成熟的工作台，而不是功能展示 demo。当前重构优先级是：

1. 文档真相源清晰。
2. 用户主路径可走通。
3. UI 主次明确。
4. 编排、运行、审批、恢复闭环。
5. owner、契约和测试能约束开发。

暂不优先追求大量插件、复杂市场化模板、远程协作和社区生态。

## 关键判断

如果一个设计让用户必须先理解内部实现、隐藏面板、命令面板或测试 API 才能完成任务，它就是错误设计。
