# 02 用户旅程与信息架构

## 主旅程

Cyber Editor 有两条并列主路径：

1. 创建或打开工程，进入文档工作台。
2. 直接开始编排，进入 Flow 工作台。

两条路径最终都必须进入同一套工程、工件、AI 运行和证据体系，不能生成两套孤立体验。

## 旅程 A：文档工作台

1. 用户打开应用。
2. 欢迎页展示最近工程、创建工程、打开工程、开始编排。
3. 用户进入工作台。
4. 左侧看到工程和文件。
5. 中间编辑或阅读文档。
6. 右侧与 AI 协作。
7. 顶部或对象附近展示当前阶段、待确认事项、错误和恢复入口。
8. AI 写回前展示差异、来源和冲突。
9. 用户确认后文档、工件和证据同步更新。

## 旅程 B：编排工作台

1. 用户点击开始编排。
2. 系统创建草稿 Flow 和必要上下文。
3. 中间画布成为主区域。
4. 用户拖拽、连接或通过自然语言生成节点。
5. 点击节点后，右侧直接出现可编辑配置。
6. 用户运行 Flow。
7. 运行状态、暂停、恢复、重试、人工确认、冲突和错误在当前对象附近出现。
8. 输出写入工件。
9. 工件失效、局部重跑和证据追溯可见。

## 支撑旅程

### 旅程 C：资源治理与安装

1. 用户在资源视图、模板中心或技能/角色入口发起导入或安装。
2. 系统展示来源、版本、风险、兼容性和是否需要人工审查。
3. 用户批准后，模板、技能或角色包真正进入本地目录和当前工程上下文。
4. 导入结果、阻断原因和审查记录进入证据体系。

### 旅程 D：思路地图与知识底座

1. 用户在工程或会话中打开思路地图。
2. 系统基于真实会话、文档、规则、运行证据和知识图生成结构化节点。
3. 用户可查看节点、证据关系和布局，并保存或重置布局。
4. 上下文包、索引状态和来源说明可回到 AI 会话或运行时使用。

### 旅程 E：规则沉淀与设置

1. 用户在规则视图查看全局规则、工程规则、沉淀条目和提升草案。
2. 用户在设置视图配置 provider profile、主题和全局偏好，并立即测试连接。
3. 规则、设置、知识索引和模型配置共同影响后续 AI 运行与编排行为。

## 信息架构

| 区域 | 责任 | 不承担 |
|---|---|---|
| 欢迎页 | 最近工程、创建工程、打开工程、开始编排 | 不承载复杂配置 |
| 工程视图 | 文件、文档、表格工件、AI 协作、阶段推进 | 不隐藏阻断动作 |
| 会话视图 | 会话列表、阶段状态、上下文入口 | 不替代当前对象操作 |
| 思路地图视图 | 会话结构、证据关系、布局与探索路径 | 不变成静态插图页 |
| 编排视图 | Flow、节点、运行、审批、工件 | 不把画布降级成展示区 |
| 资源中心 | 模板、角色、技能、连接、导入 | 不作为主旅程阻断入口 |
| 规则视图 | 规则、沉淀条目、提升草案、知识图 | 不隐藏当前生效规则来源 |
| 搜索视图 | 全文搜索、定位和结果跳转 | 不承载文件编辑本体 |
| 设置中心 | Provider、模型、全局偏好、安全选项 | 不承载当前任务关键动作 |
| 证据与运行记录 | 审计、追溯、日志、质量评分 | 不替代当前对象操作 |

## 页面原则

1. 当前对象必须明确：工程、文档、Flow、节点、工件、运行或审批。
2. 下一步动作必须可见。
3. 阻断原因必须可见。
4. 恢复入口必须可见。
5. 历史和详情可以折叠，主动作不能隐藏。
6. 表格工件、Markdown 文档和导出结果属于同一工作台体系，不得拆成平行产品。
7. 资源导入、规则沉淀、思路地图和设置虽是支撑旅程，但都必须能回接主旅程。
