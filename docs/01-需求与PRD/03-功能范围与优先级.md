# 03 功能范围与优先级

## P0 必须完成

| 能力 | 完成标准 |
|---|---|
| 工程入口 | 创建、打开、最近工程、直接开始编排都能进入可用工作台 |
| 文档工作台 | 文件树、文档打开、编辑、保存、冲突提示和 AI 写回可走通 |
| AI 会话 | 用户能选择上下文、发送消息、停止、重试、看到来源和写回结果 |
| 阶段推进 | 当前阶段、guard、生成草稿、确认阶段和阻断原因在主界面可见 |
| 编排画布 | Flow 创建、节点拖拽、连接、保存、导入导出、运行入口可用 |
| 节点配置 | 点击节点后右侧直接编辑配置、角色、输入输出、运行策略 |
| 运行控制 | 开始、暂停、恢复、停止、重试、局部重跑、错误恢复可见可测 |
| 人工确认 | 待审批在节点、画布和全局待决入口可见，可批准、拒绝、回退 |
| 工件闭环 | 输出写入工件，失效传播，下游重跑建议和证据追溯可见 |
| 测试门禁 | 主旅程用打包应用验证，不能只用 API 证明 |

## P1 应尽快完成

1. 并行、循环、子流程的完整配置和运行语义。
2. 长任务断点恢复、运行预算、并发和限流。
3. AI 写回冲突合并、差异预览、局部修改策略。
4. 混合检索、上下文预算、来源引用和证据链。
5. 角色包、技能、连接、Provider 健康检查和能力标签。
6. 资源导入信任审查和本地副作用治理。
7. 多窗口和分屏查看。

## P2 延后

1. 远程资源市场。
2. 团队协作和权限体系。
3. 大规模模板生态。
4. 高级可视化分析。
5. 复杂报表和运营看板。

## 范围控制

新增功能必须先回答：

1. 属于哪条用户旅程。
2. 是否解决 P0/P1 问题。
3. 页面入口在哪里。
4. 代码 owner 是谁。
5. 测试如何证明。

回答不清楚时，不进入开发。
