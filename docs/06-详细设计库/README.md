# 06 详细设计库

本目录保存从旧文档恢复并继续保留的详细材料。这里不是废弃区，也不是历史垃圾桶；它是实现细节库，用来承接不能在 PRD 和主架构文档里展开的全部细节。

## 使用顺序

1. 先读 `docs/README.md`。
2. 先按 `01-需求与PRD/`、`02-产品设计/`、`03-架构实现/`、`04-测试验收/` 判断当前方向。
3. 再进入本目录查详细实现细节。
4. 如果本目录与当前 PRD 或关键交互裁决冲突，以当前 PRD 和裁决为准，但不能删除细节；必须迁移、改写或标注冲突。

## 当前内容

本目录当前覆盖：

1. 早期行动路线、需求、功能树、功能清单。
2. UI 页面详细说明与低保真线框。
3. 功能具体实现方案与 INF 级内部能力设计。
4. 代码唯一性文档。
5. 开发设计方案。
6. 实现追踪矩阵与工程分析报告。

## 目录说明

| 路径 | 说明 |
|---|---|
| `00-行动路线.md` ~ `03-功能清单.md` | 早期基线材料，仅作细节追溯，不替代现行 PRD |
| `04-UI设计/` | 旧版页面级细节、跳转图与低保真线框 |
| `05-功能具体实现方案/` | F/INF 原子能力实现方案 |
| `06-代码唯一性文档/` | 契约、状态机、时序、错误与测试 Oracle 约束 |
| `08-开发设计方案/` | 程序员向的模块开发设计和组件拆分设计 |
| `09-实现追踪矩阵.md` | 需求到实现的跨层追踪 |
| `10-gstack工程分析与模板提取报告.md` | 模板来源分析与提取依据 |

## 后续整理规则

1. 合并同主题文档时，先把细节迁移到当前设计文件或本目录对应位置。
2. 只有确认细节已经迁移，才允许删除重复或过时表述。
3. 不允许用“文档简洁”作为删除实现细节的理由。
4. 不允许让本目录重新变成多个真相源；它提供细节，裁决仍看 PRD、关键设计文件和当前架构文档。
