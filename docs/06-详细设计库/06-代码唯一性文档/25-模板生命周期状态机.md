# 25 模板生命周期状态机

## 1. 目标
1. 固定模板从发现、安装、使用、更新到损坏恢复的完整生命周期。
2. 防止模板中心退化成固定写死的入口卡片或无状态列表。

## 2. 模板来源状态机
```text
unknown_source
  -> builtin
  -> local_imported
  -> remote_downloaded
```

约束：
- 每个模板必须带 `sourceType`。
- `sourceType` 必须至少区分：`builtin`、`local`、`remote`。

## 3. 模板安装状态机
```text
discoverable
  -> installing
installing
  -> installed
  -> install_error
install_error
  -> installing
```

约束：
- 安装阶段必须先做 manifest 校验和目录结构校验。
- `installed` 后模板必须立即可见于模板中心和相应入口。

## 4. 模板信任状态机
```text
untrusted
  -> trusted_official
  -> trusted_user
untrusted
  -> blocked
blocked
  -> repaired
```

约束：
- 未验证模板默认不可静默执行高风险能力。
- `blocked` 模板必须在 UI 中显式标红并禁用“使用模板”。

## 5. 模板兼容状态机
```text
compat_unknown
  -> compat_ok
  -> compat_warning
  -> compat_blocked
compat_warning
  -> compat_ok
compat_blocked
  -> compat_ok
```

约束：
- 兼容性至少比较：
  - 模板 schema 版本
  - Flow schema 版本
  - 角色包 schema 版本
- `compat_blocked` 时禁止创建工程和开始编排。

## 6. 模板使用状态机
```text
installed
  -> selected_for_project
  -> selected_for_orchestration
selected_for_project
  -> project_created
selected_for_orchestration
  -> draft_created
```

约束：
- 模板必须同时支持：
  - `从模板创建工程`
  - `从模板直接开始编排`
- 不允许只支持前者。

## 7. 模板更新状态机
```text
installed
  -> update_available
update_available
  -> updating
updating
  -> installed
  -> update_error
update_error
  -> update_available
```

约束：
- 更新前必须保留当前模板旧版本快照。
- 更新失败不得破坏已安装可用版本。

## 8. 模板损坏修复状态机
```text
installed
  -> damaged
damaged
  -> blocked
blocked
  -> repaired
  -> removed
repaired
  -> installed
```

约束：
- 损坏原因必须可见：
  - 缺文件
  - 目录结构错误
  - 版本不兼容
  - manifest 非法
- 修复成功前不得恢复可用状态。

## 9. 模板删除状态机
```text
installed
  -> delete_confirming
delete_confirming
  -> removed
  -> installed
```

约束：
- 内置模板默认不可物理删除，只允许隐藏或禁用。
- 删除前必须检查：
  - 是否被最近项目引用
  - 是否被当前草稿引用

## 10. 错误实现示例
1. 安装后模板列表不刷新。
2. 版本不兼容只给 toast，不阻止使用。
3. 远程下载模板默认和官方模板同等信任。
4. 损坏模板仍可用于创建工程。
