# 21 编排层调试语义表

## 1. 目标
- 固定编排层调试、局部重跑、从此继续和快照恢复的语义。
- 防止另一套 AI 把调试做成临时按钮，没有统一恢复边界。

## 2. 设计态与运行态
- 设计态：
  - 编辑草稿
  - 不产生正式 run 结果
  - 允许改布局、改节点、改契约
- 运行态：
  - 只读展示当前执行图
  - 调试动作通过运行抽屉进入
  - 不得把运行态编辑与设计态编辑混在同一区域

## 3. 调试入口
- 节点卡片快捷操作：可有“测试节点”
- 节点右键菜单：可有“从此节点调试”
- 运行抽屉：可有“从此继续”“局部重跑”
- Inspector：只显示调试资格与当前可调试原因，不直接启动调试

## 4. 调试类型

### 4.1 单节点测试
- 输入用户提供的调试 payload。
- 不写正式工件。
- 写临时调试结果。

### 4.2 从此节点继续
- 以当前节点为入口重建一条新 run。
- 上游已完成结果只读复用。
- 下游按新 run 重新执行。

### 4.3 局部重跑
- 对失败节点或其下游子图重新执行。
- 必须标记失效范围。

### 4.4 快照恢复
- 恢复到某一保存快照。
- 恢复后画布、契约、节点位置都应一致。

## 5. 调试资格
- 节点可调试的前提：
  - 节点存在
  - 节点配置完整
  - 必要输入可用
  - 当前 run 或快照提供足够上下文
- 不满足时返回 `debug_not_allowed`

## 6. 调试结果显示
- 必须显示：
  - 输入摘要
  - 输出摘要
  - 错误码
  - 运行时长
  - 使用的角色/模型/工具
- 调试结果不得覆盖正式工件，除非用户执行显式“采纳结果”动作。

## 7. 失效语义
- 当用户修改以下内容时，相关运行结果必须失效：
  - 节点配置
  - 边绑定
  - 阶段契约
  - 输入目录/输出目录
  - 角色包实例化配置
- 失效后应显示：
  - 哪些结果失效
  - 是否允许局部重跑

## 8. 测试 Oracle
- 调试与正式运行必须有明确隔离。
- “从此继续”和“局部重跑”不得静默覆盖正式结果。
- 快照恢复后，布局、节点、契约、入口点都必须一致。
