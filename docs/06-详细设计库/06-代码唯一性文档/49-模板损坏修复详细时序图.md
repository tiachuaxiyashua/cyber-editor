# 49 模板损坏修复详细时序图

## 1. 目标
固定模板损坏检测、阻断、修复与重新可用的完整流程。

## 2. 时序
1. 用户打开模板中心
2. Renderer 调 `template.list`
3. Main 在枚举模板时校验：
   - manifest schema
   - 版本字段
   - 必需目录结构
   - 信任状态
4. 若某模板损坏：
   - 标记 `damaged`
   - 返回 `damageReason`
5. Renderer 在模板列表和详情中显示损坏状态
6. 用户点击“修复模板”
7. Renderer 调 `template.repair`
8. Main 按类型选择修复策略：
   - 补齐缺失可推导字段
   - 重新生成索引/元数据
   - 要求重新导入
9. Main 返回：
   - `repaired`
   - `warnings`
   - `requiresReimport`
10. Renderer 刷新模板列表与详情
11. 模板恢复为 `healthy` 或 `warning`

## 3. 阻断规则
1. `damaged` 模板不得直接用于创建工程或开始编排。
2. `warning` 模板允许继续，但需显示风险提示。

## 4. 测试 Oracle
1. 损坏模板必须被显式标记，不能静默消失。
2. 修复后状态必须立即刷新。
3. 无法自动修复时必须给出重新导入入口。
