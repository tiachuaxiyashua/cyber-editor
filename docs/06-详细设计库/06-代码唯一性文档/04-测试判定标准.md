# 04 测试判定标准

## 1. 目标
- 本文档定义“什么叫测试通过”，不是只列测试名称。
- 用于约束另一套 AI 不会用更弱的断言蒙混过关。

## 2. M/S/A 测试 oracle

### 2.1 M 类
- 必须同时通过：
  - 正常路径
  - 至少一个失败路径
  - 至少一个恢复路径
- 例：
  - `F-049` 必须测“无输入不能确认”和“补齐后才能确认”
  - `F-056` 必须测“连接成功”和“连接失败”

### 2.2 S 类
- 必须同时通过：
  - 主价值路径
  - 对象关系正确
  - 状态转换正确
  - 输出落盘/落对象正确
- 例：
  - `F-052` 不能只测按钮可点，必须测蓝军/红军/裁判三段过程和工件产出
  - `F-064` 不能只测节点出现，必须测拖拽到画布的放置结果

### 2.3 A 类
- 必须通过：
  - 主要动作链
  - 主要反馈
  - 关键异常处理

## 3. Journey 级通过标准
- 欢迎页旅程
  - 最近工程
  - 最近模板
  - 新建工程
  - 开始编排
- 主工作台旅程
  - 打开文档
  - 编辑保存
  - 查找替换
  - 图文嵌入
- AI 旅程
  - 发送消息
  - 停止
  - 重试
  - 阶段草稿
  - guard
  - 审查
- 编排旅程
  - 新建 flow
  - 拖拽节点
  - 连线
  - 配角色/工件
  - 保存

## 4. 截图与运行证据
- UI 类功能不能只靠 DOM 断言。
- 必须同时有：
  - 行为断言
  - 关键截图
  - 必要时的文件系统/运行记录断言

## 5. 未完成功能的测试要求
- `部分完成` 功能必须至少有：
  - 当前已实现部分的测试
  - 明确缺口的负例或跳过说明
- 不允许把未完成功能写成“测试通过，只是后续优化”。

## 6. 打包与真实运行
- 任何声称“可用”的主路径最终都应至少在开发态和打包态各跑一次。
- 本地模型链路必须有一次真实 provider 运行证据，不能只做 mock。
