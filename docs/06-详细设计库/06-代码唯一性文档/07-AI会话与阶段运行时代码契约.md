# 07 AI 会话与阶段运行时代码契约

## 1. 目标
- 锁定会话、运行时、阶段 guard、审查子流程和 provider 激活行为。

## 2. 不允许变化的语义
- 会话是独立对象，不是消息数组别名。
- 每次发送、阶段草稿、审查、Flow 运行都必须创建独立 `run`。
- `ProviderProfile` 选中即激活，不允许“选中”和“激活”分裂成两个用户动作。
- 阶段确认必须由主进程重新校验 guard，不接受 renderer 本地 ready 作为最终依据。

## 3. 运行接受与事件流
- `session.sendMessage`
- `stage.generateDraft`
- `runtime.retry`
- `flow.run`

以上动作都只能返回 `runAccepted`，真正过程通过事件流更新：
- `queued`
- `running`
- `artifact_written`
- `warning`
- `error`
- `succeeded`
- `failed`
- `stopped`

## 4. guard 唯一规则
- `StageGuardStatus` 必须至少包含：
  - `ready`
  - `blockingReasons[]`
  - `checkItems[]`
- 确认阶段按钮是否可点，只取决于最新主进程 guard 结果。
- 没有用户输入、缺少工件、仍有 blocker issue、仍有关键任务运行中，必须阻断确认。

## 5. 审查子流程唯一规则
- 红蓝裁判不是随意多轮聊天，而是一个有工件输入输出的运行链。
- 至少产生：
  - 蓝军输出
  - 红军问题
  - 裁判汇总
  - 继续/停止信号
- 审查结果必须可见、可采纳、可忽略、可待处理。

## 6. Provider 与模型路由
- profile 被用户选中后立即成为当前激活 profile。
- 连接测试结果必须结构化返回：
  - `reachable`
  - `latencyMs`
  - `capabilities[]`
  - `error?`
- 命中模型必须在会话栏或流程面板可见。

## 7. 本地模型路径
- Ollama 真实运行不是可选项。
- 至少有一条主路径必须能用真实 Ollama 成功产出文本或工件。
- 本地模型失败时必须返回可恢复错误，而不是静默无输出。

## 8. 测试 oracle
- 发送消息必须可见 run 生命周期。
- 停止生成必须进入 `stopped` 而不是 `failed`。
- 选中 Provider 后无需二次激活即可生效。
- 缺输入时阶段确认必须被阻断。
- 真实 Ollama 路径必须至少跑一次成功。
