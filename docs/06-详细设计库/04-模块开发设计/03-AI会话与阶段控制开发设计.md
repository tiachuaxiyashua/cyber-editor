## 6. 数据与持久化
- 会话历史、run 记录、阶段状态分别存储
- 工件正文不等于会话消息
- review issues 存结构化结果

## 6.1 持久化流程
1. 消息发送先生成本地 optimistic 条目，但不视为持久化成功。
2. `RuntimeService.createRun` 先写 `run header`，再写事件流。
3. 结构化结果通过校验后，才允许写工件正文或 review issues。
4. 阶段确认记录必须与 guard 结果同时落盘，防止“已确认但无依据”。
5. 失败 run 只允许追加错误事件，不允许覆盖之前成功工件。

## 7. 关键流程
### 7.1 发送消息
1. 发送 optimistic message
2. 创建 run
3. ModelRouter 选模型
4. AIService 调用模型
5. 回写消息和事件流

### 7.2 阶段草稿生成
1. 先 guard
2. 通过后生成结构化结果
3. 校验/修复
4. 写工件
5. 刷新阶段状态

### 7.3 阶段确认
1. 重新计算 guard
2. 写确认记录
3. 阶段推进

## 8. 错误处理
- provider 不可达
- guard 不通过
- 结构化输出失败
- review 子流程失败
- run 中途取消

## 9. 开发顺序
1. session CRUD
2. runtime event stream
3. provider/profile 与 model router
4. guard engine
5. stage draft generation
6. review engine
