# 00 模块开发设计总则

## 1. 本层解决什么问题

本层只回答“程序员应该如何落代码”，不再重新定义产品价值，也不重复原子功能本身的用户行为。

它负责固定：

1. 页面和模块如何拆分
2. Renderer / Main / Service 如何分工
3. 状态、IPC、持久化和恢复如何组织
4. 开发顺序和验收口径如何安排
5. 哪些实现自由度允许，哪些不允许

## 2. 阅读前提

实现任何模块前，必须先阅读：

1. [04-详细需求基线.md](../../01-需求与PRD/04-详细需求基线.md)
2. [05-功能树.md](../../01-需求与PRD/05-功能树.md)
3. [06-功能清单.md](../../01-需求与PRD/06-功能清单.md)
4. 对应 UI 详细设计
5. 对应原子功能实现方案
6. 对应代码契约与唯一性文档

## 3. 与其他层的关系

- `02-原子功能实现方案` 回答“这个原子功能是什么、用户怎么走”
- `04-模块开发设计` 回答“程序员应该怎么写”
- `03-代码契约与唯一性` 回答“哪些地方不能自由发挥”

## 4. 每份开发设计文档必须包含

1. 作用域
2. 关联功能 ID
3. 页面与入口
4. 组件树
5. 状态归属
6. IPC 设计
7. 主进程服务拆分
8. 持久化策略
9. 开发顺序
10. 验收口径
11. 组件 Props 契约
12. Hook / state shape
13. 方法级 I/O

## 5. 不允许的写法

1. 只说“前端调用接口、后端保存数据”。
2. 不写状态归属。
3. 不写组件边界。
4. 不写先后顺序。
5. 不写失败路径。
6. 不写 Props 契约和 Hook 状态归属。
