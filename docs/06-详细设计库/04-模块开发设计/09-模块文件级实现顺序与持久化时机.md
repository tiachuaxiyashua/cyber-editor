## 3. 持久化时机
| 对象 | 何时写盘 | 写盘位置 | 失败时处理 |
|---|---|---|---|
| `project.json` | 创建工程成功时 | `<project>/project.json` | 整体创建失败，回滚新目录 |
| `flow.json` | 显式保存 flow | `<project>/flows/<id>/flow.json` 或 `<draft>/flows/<id>/flow.json` | 保留内存 draft，不覆盖旧文件 |
| `ui.json` | 显式保存 flow | `<project>/flows/<id>/ui.json` | 与 `flow.json` 同事务 |
| `contracts/*.json` | 显式保存 flow | `<project>/flows/<id>/contracts/` | 任一失败则本次保存整体失败 |
| `role package` | 安装成功时 | `role-packages/<id>/` | 安装失败删除半成品目录 |
| `template package` | 安装成功时 | `templates/<id>/` | 安装失败删除半成品目录 |
| `snapshot` | 运行前 / 显式快照 | `snapshots/<snapshotId>/` | 快照失败不阻塞编辑，但阻塞恢复入口 |

## 4. 写盘顺序
### 4.1 创建工程
1. 校验目标目录
2. 创建根目录
3. 写 `project.json`
4. 写 `artifacts/`
5. 写 `flows/`
6. 写 `exports/`
7. 写模板预置文件
8. 更新最近项目

### 4.2 保存 Flow
1. 校验 `flowDraft`
2. 生成临时目录
3. 写 `flow.json`
4. 写 `ui.json`
5. 写 `contracts/*.json`
6. 原子替换正式目录
7. 更新最近 flow

## 5. 回滚规则
1. 创建工程任一步失败，删除本次创建的空/半成品目录。
2. 保存 Flow 失败，不改动上一次成功版本。
3. 模板/角色包安装失败，必须删除临时目录并写错误事件。
4. 快照恢复失败，不改变当前 draft，只允许用户手动重试或放弃。

## 6. 验收标准
1. 程序员能按模块顺序直接拆分任务，不需要再猜先做什么。
2. 任一持久化对象都能定位“何时写盘、写到哪里、失败如何回滚”。
