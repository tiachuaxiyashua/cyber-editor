## 5. 目录与持久化
- 输入目录：Flow 配置
- 输出目录：Flow 配置
- 工件目录：模板/工程内 catalog
- 导出目录：由导出 run 决定

## 5.1 目录落盘流程
1. `artifact-catalog.json` 先于阶段契约写入。
2. `contracts/stages/*.json` 和 `contracts/nodes/*.json` 分目录写入。
3. `exports/mapping.json` 独立维护，不允许散落在角色包中。
4. 导出执行时创建 `exports/runs/<runId>.json`，随后写目标目录产物。

## 6. 关键流程
### 6.1 配置阶段契约
1. 选阶段
2. 选择必需工件
3. 选择校验规则
4. 保存到 flow

### 6.2 配置节点 IO
1. 选节点
2. 绑定输入工件/消息/信号
3. 绑定输出工件/消息/信号
4. 局部校验

### 6.3 导出
1. 先校验目录与契约
2. 创建 export run
3. 写入目标文件
4. 返回结果目录

## 7. 错误处理
- 缺工件：阻断
- 导出映射冲突：阻断
- 输出目录不可写：失败
- OpenSpec 结构不完整：失败

## 8. 开发顺序
1. Artifact catalog
2. Stage contract
3. Node IO
4. Export mapping
5. Delivery export
6. OpenSpec export

## 9. 测试点
- 自动化：
  - 契约校验
  - 导出目录存在
  - OpenSpec 结构正确
- 用户模拟：
  - 修改契约后 guard 变化正确
  - 导出失败能看到原因
