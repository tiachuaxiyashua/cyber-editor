# F-014 保存当前工程为模板

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：平台入口与模板 / 模板中心 / 保存
- MSABC 分类：S
- 当前状态：部分完成
- 关联页面：[新建工程与模板中心](../../04-UI设计/02-新建工程与模板中心.md)、[主工作台](../../04-UI设计/03-主工作台.md)、[编排页](../../04-UI设计/07-编排页.md)、[无工程编排模式](../../04-UI设计/10-无工程编排模式.md)
- 上游需求：`D-A2`、`D-C2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 用户必须能把当前工程或当前编排沉淀为可复用模板。
2. 模板是平台核心资产，不能只支持导入，不支持产出。

### 2.2 完成定义
1. 在工作台、编排页和无工程编排模式都能触发“保存为模板”。
2. 用户可以填写模板元数据。
3. 系统把当前 Flow、角色、工件目录、导出映射等打包保存。
4. 保存后模板立即出现在模板中心。

## 3. 页面入口与层级
1. 主工作台更多菜单
2. 编排页顶部工具栏或更多菜单
3. 无工程编排模式顶部动作

## 4. 用户操作流程
1. 用户点击“保存为模板”。
2. 弹出模板保存对话框。
3. 用户填写：
   - 模板名称
   - 描述
   - 标签
   - 类型
   - 版本
4. 系统打包模板。
5. 保存成功后跳转到模板详情或显示“去模板中心查看”。

## 5. 可见效果与状态
1. 保存中显示进度。
2. 保存成功后显示模板 ID 和保存位置。
3. 保存失败时显示具体失败原因和修复建议。

## 6. 数据模型
```json
{
  "templateId": "travel-guide-template",
  "sourceProjectId": "project_travel_001",
  "packIncludes": {
    "flows": true,
    "rolePackages": true,
    "artifactCatalog": true,
    "exportMapping": true
  }
}
```

## 7. 具体实现方案
### 7.1 Renderer
组件：
1. `SaveAsTemplateDialog`
2. `TemplatePackPreview`

### 7.2 Main / Service
服务：
1. `template-scaffold-save-service`
2. `template-registry`

Main 责任：
1. 收集当前工程或草稿中的模板资产。
2. 生成模板目录与 manifest。
3. 注册到模板中心。

## 8. 校验与阻断
1. 模板名称不能为空。
2. 当前工程无核心 Flow 时，阻止保存为模板。
3. 角色包缺失或导出映射缺失时，要么阻止，要么要求用户确认不打包该项。

## 9. 自动测试
### 9.1 单元
1. 打包清单生成
2. manifest 写入
3. 模板注册

### 9.2 端到端
1. 从编排页保存为模板。
2. 打开模板中心，确认新模板出现。
3. 用该模板重新创建工程或开始编排。

## 10. 用户模拟测试
1. 在编排页完成一个最小 Flow。
2. 点击保存为模板。
3. 填写信息并确认保存。
4. 进入模板中心确认模板可见并可复用。

## 11. 不允许的错误实现
1. 保存为模板只保存名称，不保存真实 Flow 和配置。
2. 只有工程能保存为模板，无工程编排草稿不能保存。
3. 保存成功但模板中心不出现。

## 12. 当前审计结论
- 审计状态：部分完成
- 审计说明：保存为模板仍缺少完整打包清单、注册闭环和跨入口一致性。
