# INF-041 Flow history/snapshot/restore

## 1. 基本信息
- 类型：内部功能
- 所属层级：编排层 / 历史恢复 / 版本
- MSABC 分类：A
- 当前状态：未完成
- 关联页面：编排页历史与恢复入口
- 共享实现基线：[编排与流程资产](README.md)

## 2. 责任与完成定义
### 2.1 服务责任
1. 为 Flow 保存历史版本和快照。
2. 提供查看快照、恢复快照和比较快照的能力。
3. 为自动布局、批量操作和危险编辑提供撤销级安全点。

### 2.2 完成定义
1. 每次显式保存都形成一个版本记录。
2. 危险动作前可生成临时快照。
3. 用户可以恢复到任意历史版本。
4. 恢复后节点位置、边关系、角色绑定和工件契约都一并恢复。

## 3. 输入与输出
### 3.1 输入
```json
{
  "flowId": "flow_software_factory_main",
  "snapshotReason": "before-auto-layout"
}
```

### 3.2 输出
```json
{
  "snapshotId": "snap_20260409_120001",
  "flowVersion": 12,
  "createdAt": "2026-04-09T12:00:01Z"
}
```

## 4. 上游与下游
- 上游：
  - Flow asset persistence
  - Canvas layout state store
- 下游：
  - 编排页历史抽屉
  - 恢复确认对话框

## 5. 核心接口
```ts
type FlowSnapshotEntry = {
  snapshotId: string;
  flowId: string;
  version: number;
  reason: string;
  createdAt: string;
  payloadPath: string;
};
```

## 6. 实现要求
1. 快照必须保存完整 Flow 草稿，不得只保存增量差异。
2. 恢复动作必须先做当前草稿保护。
3. 恢复后必须刷新画布和 Inspector，而不是只改内存对象。
4. 历史记录要支持无工程编排草稿和工程内 Flow 两种来源。

## 7. 校验与阻断
1. 快照文件损坏时不得执行恢复。
2. 正在运行的 Flow 恢复前必须先停止运行或创建分叉副本。
3. 恢复失败时必须保留原草稿。

## 8. 自动测试
### 8.1 单元
1. 快照创建
2. 快照恢复
3. 快照损坏检测

### 8.2 端到端
1. 拖动节点并保存。
2. 修改布局后创建快照。
3. 恢复到旧版本，确认布局和绑定关系一并回退。

## 9. 不允许的错误实现
1. 只保存节点列表，不保存位置和绑定关系。
2. 恢复时覆盖当前草稿而不给保护点。
3. 版本历史只存在 UI 列表，没有真实可恢复 payload。

## 10. 当前审计结论
- 审计状态：未完成
- 审计说明：Flow 历史、快照和恢复仍未形成可靠的全量快照与安全恢复链路。
