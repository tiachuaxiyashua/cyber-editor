# F-079 角色目标/设定/角色包配置编辑

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 角色 / 内容
- MSABC 分类：S
- 当前状态：部分完成
- 关联页面：[编排页](../../04-UI设计/07-编排页.md)
- 上游需求：`D-C2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 角色不是一句 prompt，而是可复用的角色包。
2. 用户定义角色时，应看到身份、人格、协作规则、服务对象，而不是一坨技术字段。

### 2.2 完成定义
1. 角色编辑页或 Inspector 必须分区编辑：
   - IDENTITY
   - SOUL
   - AGENTS
   - USER
   - Skills
   - MEMORY
2. 输出格式字段不得出现在角色编辑中。
3. 保存后落成角色包目录。

## 3. 用户操作流程
1. 用户在角色资产区点击 `新建角色`。
2. 系统创建角色草稿。
3. 用户依次填写：
   - 名称和专注领域
   - 人格与说话风格
   - 协作制度
   - 服务对象画像
4. 用户保存。
5. 角色包目录生成。

## 4. 角色包目录结构
```text
roles/<role-id>/
  role.json
  IDENTITY.md
  SOUL.md
  AGENTS.md
  USER.md
  Skills/
  MEMORY/
    MEMORY.md
```

## 5. 可见效果与状态
1. 每个分区必须有独立标题与说明。
2. 若缺关键文件，角色卡片显示警告。
3. 角色详情中应显示当前包状态：
   - 完整
   - 缺失文件
   - 技能失效

## 6. 具体实现方案
### 6.1 Renderer
1. `RoleEditor`
2. `RoleSectionTabs`
3. `RolePackageStatus`

### 6.2 Main / Service
1. `role-package-loader`
2. `role-package-validator`
3. `flow-asset-persistence`

Main 责任：
1. 读写角色包目录
2. 校验完整性
3. 返回角色包状态

## 7. 校验与阻断
1. `role.json` 缺失时阻止保存为可用角色。
2. `AGENTS.md` 缺失时，多 Agent Flow 中标记为不完整。
3. `SOUL.md` 和 `USER.md` 允许先为空草稿，但保存时需显示不完整状态。

## 8. 自动测试
1. 角色包目录生成
2. 角色包重开恢复
3. 缺文件告警

## 9. 用户模拟测试
1. 新建一个角色。
2. 只填名称与目标，保存。
3. 检查角色状态为“不完整”。
4. 补齐 SOUL/AGENTS/USER 后再保存。
5. 状态变为完整。

## 10. 不允许的错误实现
1. 把角色定义压成单个 JSON 表单。
2. 在角色里配置最终导出格式。
3. 角色缺文件却仍显示正常可用。
