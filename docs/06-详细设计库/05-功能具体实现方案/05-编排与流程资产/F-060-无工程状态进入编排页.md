# F-060 无工程状态进入编排页

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 入口与模式 / 无工程
- MSABC 分类：S
- 当前状态：未完成
- 关联页面：[欢迎页](../../04-UI设计/01-欢迎页.md)、[无工程编排模式](../../04-UI设计/10-无工程编排模式.md)、[编排页](../../04-UI设计/07-编排页.md)
- 上游需求：`D-C2`、`D-N3`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 用户必须能在没有工程时进入正式的编排工作面，而不是临时预览页。
2. 该模式承载小白“先用流程”与高手“先搭流程”的共同入口。

### 2.2 完成定义
1. 无工程编排模式是正式页面，不依赖工程 bootstrap。
2. 页面中可创建、保存、导入、导出、绑定工程。
3. 无工程状态下不显示工程专属文件树和工程路径。
4. 从欢迎页、模板中心、最近编排都能进入该模式。

## 3. 页面入口与层级
1. 主入口：欢迎页 `开始编排`
2. 次入口：模板中心 `开始编排`
3. 再入入口：最近编排列表
4. 页面容器类型：主内容替换页 `P1`

## 4. 用户操作流程
1. 用户进入无工程编排模式。
2. 系统载入草稿或创建新草稿。
3. 用户编辑 Flow。
4. 用户执行：
   - 保存草稿
   - 保存为模板
   - 绑定工程
   - 导出 Flow 包

## 5. 可见效果与状态
1. 顶部状态区显示：
   - `无工程编排`
   - 草稿名称
   - 未保存/已保存
2. 若草稿来源于模板，显示模板名和版本。
3. 页面必须提供返回欢迎页入口。

## 6. 具体实现方案
### 6.1 Renderer
1. `OrchestrationDraftShell`
2. `DraftStatusBar`
3. `DraftActionsToolbar`

### 6.2 Main / Service
1. `draft-registry-service`
2. `flow-asset-persistence`
3. `template-registry-service`

## 7. 校验与阻断
1. 草稿打开失败时不得进入空白损坏页。
2. 草稿损坏时必须允许修复、另存或删除。
3. 绑定工程前必须校验草稿可序列化。

## 8. 自动测试
1. 从欢迎页进入无工程编排
2. 从模板中心进入无工程编排
3. 最近编排重开
4. 草稿损坏恢复

## 9. 用户模拟测试
1. 不建工程直接进入编排。
2. 增加几个节点并保存草稿。
3. 关闭页面后从最近编排重开。
4. 再绑定工程，确认成功切入工作台。

## 10. 不允许的错误实现
1. 用一个伪工程替代无工程模式。
2. 只允许首次进入，不允许最近编排恢复。
3. 无工程模式下仍要求工程目录。

## 11. 当前审计结论
- 审计状态：未完成
- 审计说明：无工程编排仍未形成独立、稳定、可恢复的正式模式。
