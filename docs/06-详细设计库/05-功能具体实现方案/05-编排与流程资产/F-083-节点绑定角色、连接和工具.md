# F-083 节点绑定角色、连接和工具

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 连接与工具 / 绑定
- MSABC 分类：S
- 当前状态：部分完成
- 关联页面：[编排页](../../04-UI设计/07-编排页.md)
- 上游需求：`D-C2`、`D-C3`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 节点是否可执行，取决于它具体绑定了哪个角色、哪个连接、哪个工具。
2. 如果绑定关系不可见或不可校验，用户无法判断 Flow 为什么跑不起来。
3. 节点绑定必须体现兼容性和最终生效结果，而不是只保存几个 ID。

### 2.2 完成定义
1. 选中节点后，Inspector 显示“角色 / 连接 / 工具”三段绑定区。
2. 每个区都展示：
   - 当前绑定对象
   - 可选对象
   - 禁用原因
   - 最终生效结果
3. 保存后绑定关系写入 Flow。
4. 运行前会校验绑定是否完整且健康。

## 3. 页面入口与层级
1. 入口页面：编排页设计态
2. 入口动作：选中节点
3. 层级：`P1 编排页 -> P2 画布节点 -> P3 Inspector 绑定区`

## 4. 用户操作流程
1. 用户点击一个角色节点或工具节点。
2. 右侧 Inspector 展示绑定区。
3. 用户依次选择角色、连接、工具。
4. 若某对象不可选，系统显示原因。
5. 保存后，节点卡片上显示绑定摘要。

## 5. 可见效果与状态
1. Inspector 中每个绑定区必须显示：
   - 当前绑定对象名称
   - 健康状态
   - 兼容性状态
2. 节点卡片上显示精简摘要：
   - 角色名
   - 工具数量或工具名
   - 连接名
3. 绑定不完整时，节点卡片显示“未配置”状态。

## 6. 数据模型
```json
{
  "nodeId": "node_red_review",
  "bindings": {
    "roleId": "role_red_reviewer",
    "connectorId": "conn_local_ollama",
    "toolIds": ["tool_read_artifact", "tool_write_artifact"]
  },
  "effectiveStatus": "ready"
}
```

## 7. 具体实现方案
### 7.1 Renderer
组件：
1. `NodeBindingsPanel`
2. `RoleBindingSelect`
3. `ConnectorBindingSelect`
4. `ToolBindingSelect`
5. `BindingHealthSummary`

Renderer 责任：
1. 根据节点类型动态调整需要的绑定区。
2. 过滤不兼容对象并显示禁用原因。
3. 将最终生效摘要反馈到节点卡片。

### 7.2 Main / Service
服务：
1. `role-package-loader`
2. `connector-registry`
3. `capability-registry`
4. `flow-validation-engine`

Main 责任：
1. 保存节点绑定。
2. 计算绑定健康状态和兼容性。
3. 在运行前进行最终校验。

## 8. 校验与阻断
1. 角色节点必须绑定角色；工具节点必须绑定工具；需要模型的节点必须绑定连接。
2. 绑定到损坏角色、失败连接、不可用工具时阻止运行。
3. 运行前必须校验最终生效实例，而不是只校验原始 ID 是否存在。

## 9. 自动测试
### 9.1 单元
1. 节点类型到所需绑定区的映射
2. 兼容性过滤与禁用原因
3. 最终生效状态计算

### 9.2 端到端
1. 为角色节点绑定角色和连接。
2. 为工具节点绑定工具。
3. 保存并重开，确认绑定仍在。
4. 切断连接健康状态，确认节点变为阻断态。

## 10. 用户模拟测试
1. 选中一个角色节点。
2. 在 Inspector 依次选择角色和连接。
3. 检查节点卡片上是否出现绑定摘要。
4. 故意将连接改为失败状态，确认节点显示阻断提示。

## 11. 不允许的错误实现
1. 节点绑定只在 Inspector 可见，节点卡片没有任何摘要。
2. 绑定列表不区分兼容性，所有对象都能选。
3. 运行前不再做校验，直到运行失败才告诉用户。
