# F-061 设计态与运行态切换

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 入口与模式 / 模式切换
- MSABC 分类：S
- 当前状态：未完成
- 关联页面：[编排页](../../04-UI设计/07-编排页.md)
- 上游需求：`D-C2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 设计流程和运行流程是两种不同认知任务，必须分开。
2. 没有模式分离，页面一定会变成噪音堆叠。

### 2.2 完成定义
1. 编排页必须有显式模式切换。
2. 设计态只露出结构编辑能力。
3. 运行态只露出运行状态、调试、重跑、blocker 和工件结果。
4. 切换模式时保留当前 Flow、当前视口和当前选中对象。

## 3. 用户操作流程
1. 用户在编排页顶部看到模式切换器。
2. 用户选择 `设计态` 或 `运行态`。
3. 页面区域按模式变化：
   - 设计态：节点库、资产编辑、Inspector 配置
   - 运行态：运行记录、节点状态、工件状态、从此继续

## 4. 可见效果与状态
1. 设计态：
   - 节点库可见
   - 结构编辑工具可见
   - 运行调试区隐藏或弱化
2. 运行态：
   - 运行记录和状态面板可见
   - 节点配置表单只读或折叠
   - 当前活跃节点高亮

## 5. 具体实现方案
### 5.1 Renderer
1. `OrchestrationModeToggle`
2. `DesignModeShell`
3. `RunModeShell`

### 5.2 Main / Service
1. `runtime-run-store`
2. `node-debug-engine`

## 6. 状态模型
```json
{
  "uiMode": "design",
  "selectedNodeId": "node_001",
  "viewport": { "x": 120, "y": 80, "zoom": 0.9 }
}
```

## 7. 校验与阻断
1. 运行态下不得允许结构编辑导致图大幅漂移。
2. 设计态下不得显示误导性的运行成功状态。

## 8. 自动测试
1. 模式切换后视口保留
2. 模式切换后选中节点保留
3. 运行态不再显示设计态专属表单

## 9. 用户模拟测试
1. 在设计态选中一个节点。
2. 切到运行态。
3. 确认选中节点和视口不丢。
4. 再切回设计态，确认布局不变。

## 10. 不允许的错误实现
1. 只是颜色变化，不是真正的信息层级变化。
2. 两种模式内容全部同时显示。
3. 切模式导致节点位置或视口重置。
