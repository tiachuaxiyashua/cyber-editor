# 16 错误码与恢复策略

## 1. 目标
- 固定用户可见失败类型、恢复方式和是否可重试。
- 防止另一套 AI 把失败都折叠成模糊 toast。

## 2. 错误对象统一结构
```json
{
  "error": {
    "code": "string",
    "message": "string",
    "recoverable": true,
    "suggestedAction": "retry|fix_input|choose_other_path|contact_user",
    "details": {}
  }
}
```

## 3. 项目与文件
| code | 场景 | 用户提示 | 恢复策略 |
|---|---|---|---|
| `invalid_project_name` | 工程名非法 | 工程名包含非法字符或为空 | 高亮输入框，禁止继续 |
| `project_root_exists` | 目录已存在且冲突 | 目标目录已存在同名工程 | 允许改名或改路径 |
| `project_manifest_invalid` | manifest 损坏 | 工程结构不完整 | 阻止打开并提供修复说明 |
| `document_conflict` | 外部修改冲突 | 文档已被外部修改 | 打开冲突对话框 |
| `unsupported_format` | 导入不支持 | 当前格式无法导入 | 提示支持的格式列表 |

## 4. 模板与技能
| code | 场景 | 用户提示 | 恢复策略 |
|---|---|---|---|
| `template_invalid` | 模板结构不合法 | 模板缺少必要文件 | 阻止安装并显示缺失项 |
| `trust_denied` | 来源不可信 | 未通过信任校验 | 用户确认后可继续或取消 |
| `template_in_use` | 模板被引用 | 模板仍被工程或 flow 使用 | 禁止删除，提示引用关系 |
| `skill_invalid` | 技能结构不合法 | 技能缺少必要 manifest | 阻止安装 |
| `skill_in_use` | 技能被引用 | 技能仍被 role/flow 使用 | 禁止删除 |

## 5. Provider / AI
| code | 场景 | 用户提示 | 恢复策略 |
|---|---|---|---|
| `provider_unavailable` | Provider 不可用 | 当前模型配置无法连接 | 打开诊断面板 |
| `provider_activate_failed` | 激活失败 | 无法切换到该配置 | 保持原配置 |
| `structured_parse_failed` | 结构化解析失败 | 输出格式不符合要求 | 自动修复一次，失败则进入人工处理 |
| `repair_exhausted` | 修复耗尽 | 自动修复未成功 | 标记 run 失败，允许重试 |
| `guard_blocked` | guard 未通过 | 当前阶段不能继续 | 展示阻断原因列表 |

## 6. 编排层
| code | 场景 | 用户提示 | 恢复策略 |
|---|---|---|---|
| `flow_invalid` | flow 草稿非法 | 流程存在未完成配置 | 定位到错误节点 |
| `node_not_found` | 节点不存在 | 目标节点已失效 | 回到 flow 选择态 |
| `debug_not_allowed` | 当前节点不可调试 | 当前节点缺少必要输入 | 显示缺失项 |
| `snapshot_restore_failed` | 快照恢复失败 | 快照已损坏或不兼容 | 允许选择其他快照 |
| `run_blocked` | 运行被阻止 | 输入目录/输出目录/契约未满足 | 打开运行前检查列表 |

## 7. 知识底座
| code | 场景 | 用户提示 | 恢复策略 |
|---|---|---|---|
| `index_status_failed` | 索引状态异常 | 无法读取索引状态 | 允许刷新重试 |
| `refresh_failed` | 增量刷新失败 | 索引刷新失败 | 支持重试和全量重建 |
| `context_pack_failed` | 上下文包失败 | 无法生成可用上下文包 | 降级为关键词搜索 |
| `citation_not_found` | 引文来源缺失 | 来源信息已失效 | 提示重新索引 |

## 8. 恢复策略硬约束
- `recoverable=true` 的错误必须提供用户可点击的恢复动作。
- `recoverable=false` 的错误必须阻断当前链路，不能伪装成成功。
- 所有自动重试都必须有上限。
- 自动修复失败必须显性记录在运行历史中。

## 9. 测试 Oracle
- 每个高风险错误码都必须有至少一条自动测试。
- 用户可见错误必须有稳定文案或稳定语义标签可断言。
- 失败时不得出现“看起来成功但数据没落盘”的假阳性状态。
