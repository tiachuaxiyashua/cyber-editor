# 33 快照恢复冲突规则

## 1. 目标
定义 Flow 历史快照恢复时如何处理当前草稿冲突。

## 2. 冲突来源
- 当前草稿未保存
- 当前草稿已保存但落后于快照
- 快照引用的角色包/子流程/模板版本已变化

## 3. 恢复策略
### 3.1 安全恢复
- 条件：当前草稿无脏状态
- 行为：直接替换当前 draft

### 3.2 需确认恢复
- 条件：当前草稿有脏状态
- 行为：弹出确认：
  - 保存当前后再恢复
  - 放弃当前并恢复
  - 取消

### 3.3 引用资产版本冲突
- 条件：快照引用资产版本与当前已安装版本不同
- 行为：
  - 保留快照记录的版本元数据
  - 标记 `compat_warning`
  - 不自动替换外部资产

## 4. 禁止行为
1. 恢复快照时不得静默丢弃当前脏草稿。
2. 恢复快照时不得自动改写引用模板/角色包本体。

## 5. 测试 Oracle
1. 有脏状态时恢复快照必须弹确认。
2. 版本冲突时必须有警告标记。
3. 恢复后节点位置与草稿结构必须回到快照值。
