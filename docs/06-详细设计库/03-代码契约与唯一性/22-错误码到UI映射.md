# 22 错误码到 UI 映射

## 1. 目标
- 固定错误码在 UI 上的出现位置和表现方式。
- 防止另一套 AI 把所有错误都塞进同一个 toast。

## 2. 映射规则
- 字段级错误：显示在表单字段下方。
- 对象级错误：显示在对象面板或对象卡片附近。
- 页面级错误：显示在页面主内容区。
- 运行级错误：显示在流程面板或运行抽屉。
- 全局错误：只用于真正跨页面的系统问题。

## 3. 具体映射

### 3.1 欢迎页 / 新建工程
| 错误码 | UI 位置 | 表现 |
|---|---|---|
| `invalid_project_name` | 工程名称输入框下 | 红色字段错误 |
| `project_root_exists` | 路径表单区顶部 | 阻断型表单错误 |
| `template_invalid` | 模板详情区 | 模板不可用状态条 |
| `trust_denied` | 模板导入对话框 | 可确认的风险提示 |

### 3.2 文件树与文档区
| 错误码 | UI 位置 | 表现 |
|---|---|---|
| `document_conflict` | 文档区上方/冲突对话框 | 明确的冲突处理弹层 |
| `unsupported_format` | 导入面板或对话框 | 原位提示支持格式 |
| `path_not_found` | 文件树对象行 | 行内错误或 toast + 刷新建议 |

### 3.3 AI 会话与阶段控制
| 错误码 | UI 位置 | 表现 |
|---|---|---|
| `provider_unavailable` | 会话输入区上方 | 阻断型错误条 |
| `structured_parse_failed` | 运行记录项内 | 可展开错误详情 |
| `repair_exhausted` | 运行记录项内 | 失败状态 + 重试按钮 |
| `guard_blocked` | 流程面板 guard 区 | 阻断原因列表 |

### 3.4 编排页
| 错误码 | UI 位置 | 表现 |
|---|---|---|
| `flow_invalid` | Inspector + 运行前检查面板 | 定位到错误节点 |
| `run_blocked` | 运行抽屉前检查区 | 阻断型清单 |
| `debug_not_allowed` | 调试入口附近 | 灰置原因 tooltip + 详情 |
| `snapshot_restore_failed` | 快照对话框 | 对话框内错误提示 |

### 3.5 技能/连接/模型中心
| 错误码 | UI 位置 | 表现 |
|---|---|---|
| `skill_invalid` | 安装结果行 | 行内失败状态 |
| `skill_in_use` | 删除确认对话框 | 阻断并列出引用 |
| `provider_activate_failed` | Profile 列表顶部 | 阻断提示条 |
| `provider_unreachable` | 诊断面板 | 诊断状态块 |

### 3.6 知识底座
| 错误码 | UI 位置 | 表现 |
|---|---|---|
| `index_status_failed` | 索引状态面板 | 状态卡错误 |
| `refresh_failed` | 刷新按钮附近 | 可重试错误提示 |
| `context_pack_failed` | 上下文包区域 | 降级提示 |
| `citation_not_found` | 引文详情抽屉 | 来源缺失提示 |

## 4. 禁止实现
- 不允许所有错误都只显示为右下角 toast。
- 不允许阻断型错误只写日志不提示用户。
- 不允许对象级错误跳到无关页面显示。

## 5. 测试 Oracle
- 每个高风险错误码都必须命中固定 UI 区域。
- 同一错误码在相同页面中必须有稳定表现方式。
- 用户应能从错误提示直接看到下一步恢复动作。
