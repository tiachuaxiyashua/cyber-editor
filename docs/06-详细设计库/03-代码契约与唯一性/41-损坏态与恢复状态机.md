# 41 损坏态与恢复状态机

## 1. 目标
统一系统中“损坏态”的定义和恢复路径。

## 2. 适用对象
- project manifest
- flow draft
- template manifest
- role package
- artifact catalog
- knowledge index

## 3. 通用状态
- `healthy`
- `warning`
- `damaged`
- `repairing`
- `recovered`
- `irrecoverable`

## 4. 进入 damaged 的条件
1. 必需字段缺失且无法默认补齐
2. schema 版本不兼容
3. 引用目标不存在
4. 关键文件损坏无法解析

## 5. 恢复策略
### 5.1 自动补齐
- 适用于：缺少可推导默认字段

### 5.2 用户确认修复
- 适用于：存在信息丢失风险

### 5.3 全量重建
- 适用于：索引、缓存、派生数据

### 5.4 不可恢复
- 适用于：源文件正文损坏且无快照

## 6. 测试 Oracle
1. 缺字段但可补齐时进入 `warning -> recovered`。
2. 无法解析的核心文件必须进入 `damaged`。
3. 不可恢复时必须给出人工修复提示。
