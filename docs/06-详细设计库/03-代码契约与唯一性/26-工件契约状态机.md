# 26 工件契约状态机

## 1. 目标
1. 固定工件目录、节点 IO、阶段输出契约和导出映射的状态变化。
2. 防止不同实现者把“最终输出是什么、写到哪里、什么时候算完成”做成完全不同的系统。

## 2. 工件目录状态机
```text
catalog_empty
  -> catalog_defined
catalog_defined
  -> catalog_dirty
catalog_dirty
  -> catalog_saved
catalog_saved
  -> catalog_defined
```

约束：
- `catalog_defined` 必须至少包含：
  - artifactId
  - artifactType
  - relativePath
  - lifecycleType
- `lifecycleType` 至少区分：`final`、`intermediate`、`runtime_only`。

## 3. Flow 输入/输出目录状态机
```text
dir_unset
  -> input_set
input_set
  -> output_set
output_set
  -> io_ready
io_ready
  -> io_blocked
```

约束：
- 输入目录和输出目录必须独立保存。
- 任何运行前都必须检查 `io_ready`。
- 不允许默认把工程根目录同时当输入和输出而不告知用户。

## 4. 阶段输出契约状态机
```text
stage_contract_empty
  -> stage_contract_partial
stage_contract_partial
  -> stage_contract_ready
stage_contract_ready
  -> stage_contract_blocked
stage_contract_blocked
  -> stage_contract_ready
```

`stage_contract_ready` 必须同时满足：
- 阶段必需工件列表存在
- 每个工件有来源节点或来源流程
- blocker 规则存在
- 完成判定存在

## 5. 节点 IO 契约状态机
```text
node_io_empty
  -> node_input_defined
node_input_defined
  -> node_output_defined
node_output_defined
  -> node_message_defined
node_message_defined
  -> node_signal_defined
node_signal_defined
  -> node_io_ready
node_io_ready
  -> node_io_blocked
```

约束：
- 角色不定义最终输出目录或导出格式。
- 节点必须显式声明：
  - 读哪些工件
  - 写哪些工件
  - 收哪些消息
  - 发哪些消息
  - 发哪些控制信号

## 6. 工件完成状态机
```text
not_started
  -> producing
producing
  -> produced_intermediate
  -> produced_final
  -> failed
produced_intermediate
  -> validated
  -> invalidated
produced_final
  -> validated
  -> invalidated
validated
  -> exported
```

约束：
- `produced_intermediate` 不等于可导出。
- `validated` 前不得进入最终导出。
- 任意上游关键结果变更后，必须允许进入 `invalidated`。

## 7. 导出映射状态机
```text
mapping_empty
  -> mapping_partial
mapping_partial
  -> mapping_ready
mapping_ready
  -> export_blocked
  -> exporting
exporting
  -> export_succeeded
  -> export_failed
```

`mapping_ready` 必须同时满足：
- 至少一个导出目标格式
- 每个导出目标有工件来源
- 非导出工件明确标记排除
- 目标相对路径存在

## 8. 阶段确认与工件状态联动
```text
guard_checking
  -> guard_blocked_missing_artifacts
  -> guard_blocked_invalid_artifacts
  -> guard_ready
```

约束：
- 缺工件与工件无效必须分开显示。
- `guard_ready` 依赖工件状态，不允许只看聊天是否完成。

## 9. 导出后状态机
```text
export_succeeded
  -> export_viewable
export_viewable
  -> export_reused
  -> export_invalidated
```

约束：
- 导出后的交付物必须可追溯到来源工件。
- 来源工件变更后，旧导出应标记 `invalidated` 或“已过期”。

## 10. 错误实现示例
1. 角色里直接配置 PDF 导出格式。
2. 节点没有声明输出工件也允许运行。
3. 中间消息被直接当成正式交付文件。
4. 来源工件变更后，旧导出仍显示最新可用。
