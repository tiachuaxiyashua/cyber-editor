# 48 快照恢复详细时序图

## 1. 目标
固定从快照列表选择恢复，到草稿替换、冲突确认、UI 回写的完整顺序。

## 2. 时序
1. 用户在编排页打开历史/快照面板
2. Renderer 调用 `flow.snapshot.list`
3. Main 返回快照列表和 metadata
4. 用户选择一个快照并点击“恢复”
5. Renderer 检查当前 `flowDraft.dirty`
6. 若 dirty：
   - 打开确认弹窗
   - 选项：
     - 保存当前后恢复
     - 放弃当前后恢复
     - 取消
7. Renderer 调用 `flow.snapshot.restore`
8. Main 校验：
   - 快照存在
   - 快照 schema 有效
   - 关联子流程/角色包引用可解析
9. Main 读取快照内容并构造新的 `FlowDraft`
10. Main 返回：
   - `restoredDraft`
   - `compatWarnings`
   - `restoredRevisionId`
11. Renderer 完整替换当前 draft
12. Renderer 恢复视口、选择态和 Inspector 指向
13. Renderer 将旧运行结果标为 stale

## 3. 错误路径
1. 快照缺失：
   - Main 返回 `SNAPSHOT_NOT_FOUND`
   - UI 保持原草稿
2. 快照损坏：
   - 返回 `SNAPSHOT_DAMAGED`
   - 提供删除或重试入口
3. 引用资产冲突：
   - 返回 `compatWarnings`
   - 不阻止恢复，但标记 warning

## 4. 测试 Oracle
1. 脏草稿恢复前必须出现确认。
2. 恢复后当前节点布局必须与快照一致。
3. 恢复失败不得污染现有 draft。
