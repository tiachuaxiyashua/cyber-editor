# 47 工件失效传播规则

## 1. 目标
定义当工件、节点或契约变化时，哪些结果需要失效，失效如何传播。

## 2. 触发源
- 工件正文修改
- 节点配置修改
- 阶段契约修改
- 导出映射修改
- 角色包版本变化

## 3. 传播规则
1. 工件正文变化：
   - 所有读取该工件的节点结果失效
2. 节点配置变化：
   - 本节点结果失效
   - 所有依赖其输出工件的下游节点失效
3. 阶段契约变化：
   - 当前阶段 guard 立即重新计算
4. 导出映射变化：
   - 导出结果失效
5. 角色包版本变化：
   - 使用该角色包的节点进入 `warning` 或 `stale`

## 4. UI 约束
1. 失效对象必须有显式标记。
2. 运行历史不得伪装为最新结果。

## 5. 测试 Oracle
1. 修改工件后，依赖节点必须进入 stale。
2. 修改导出映射后，旧导出结果不能继续标记为最新。
