# 20 编排层运行语义表

## 1. 目标
- 固定编排层各节点类型在运行时的语义。
- 防止另一套 AI 把节点仅做成视觉卡片，没有真正统一执行语义。

## 2. 通用规则
- 每个节点都必须有：
  - `inputContracts`
  - `outputContracts`
  - `preconditions`
  - `successCondition`
  - `failurePolicy`
- 每个节点运行后都必须产生结构化事件。
- 节点默认状态：`idle -> ready -> running -> success|failed|blocked`

## 3. 节点语义

### 3.1 start
- 无输入。
- 启动后仅发出控制信号。
- 不写工件。

### 3.2 end
- 接收上游控制信号。
- 当且仅当所有必需前置完成时结束 Flow。

### 3.3 agent
- 读取输入工件、消息、信号。
- 按角色包 + 节点覆盖配置实例化 agent。
- 通过 ModelRouter 选模型。
- 可写正式工件，也可写临时消息。
- 不得直接决定导出结构。

### 3.4 tool
- 只调用已注册能力。
- 输入参数必须过 schema 校验。
- 工具失败必须进入失败策略。

### 3.5 condition
- 读取一个明确的布尔条件来源。
- 必须定义：
  - 条件表达式
  - 真分支
  - 假分支
- 不允许“条件为空时默认真”。

### 3.6 loop
- 必须定义：
  - 进入条件
  - 继续条件
  - 最大轮次
  - 超时
  - 达到上限后的策略
- 每轮必须记录轮次号。
- 不得出现无限循环默认行为。

### 3.7 parallel_split
- 必须显式定义分支集合。
- 每条分支必须绑定控制边。
- 可附带共享消息或共享工件只读引用。

### 3.8 parallel_join
- 必须定义汇合策略：
  - all_success
  - any_success
  - quorum
- 必须定义失败策略：
  - fail_fast
  - wait_all
  - skip_failed

### 3.9 subflow
- 必须引用一个明确的 subflow 资产。
- 可定义输入映射与输出映射。
- 子流程运行历史属于父 run 的子记录。

### 3.10 artifact
- 通过 `artifactPath`、`inputArtifactPaths` 和 `outputArtifactPaths` 声明工件读写关系。
- 只读工件不存在时按失败策略处理。
- 写指定工件时必须受工件目录、节点输出契约和导出映射约束。

### 3.11 approval
- 进入阻塞态，等待用户动作。
- 未确认前不得自动继续。
- 必须形成 `pendingApprovals`、`waiting-approval` 状态和恢复记录。

## 4. 通信语义
- `artifact`：正式或临时工件。
- `message`：临时沟通包。
- `signal`：控制信号。
- `control`：流程走向控制。
- 不允许用 message 代替 control。
- 不允许用 role 定义输出目录或导出格式。
- 当前代码中 control 主要由边和 `branch` 表达，artifact/message/signal 主要由节点数据字段表达；不要再创建第二套未接入 validator 的通道字段。

## 5. 并行与循环的特殊约束
- 并行分支间通信必须显式声明：
  - 是否共享只读工件
  - 是否交换消息
  - 是否能发送中断信号
- 循环节点必须显式声明：
  - 何时继续
  - 何时退出
  - 退出后如何汇总结果

## 6. 测试 Oracle
- 任何节点都不能只“显示成功”而不产出事件。
- 并行、循环、子流程都必须有可重复验证的运行语义。
- 未配置完整的节点必须在运行前进入 `blocked`。
