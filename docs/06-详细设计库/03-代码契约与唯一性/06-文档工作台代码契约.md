# 06 文档工作台代码契约

## 1. 目标
- 锁定主工作台、文件树与文档区的代码边界。
- 防止另一套 AI 做成“只有一个编辑框”的弱工作台。

## 2. 不允许变化的结构
- 工作台固定为：
  - 顶部对象级工具栏
  - 左侧活动栏
  - 左侧主侧栏
  - 中间内容区
  - 右侧 AI 会话栏
  - 底部流程面板
- 中间内容区至少支持：
  - Markdown 文档
  - 图形工件嵌入
  - 表格工件入口
  - 多标签
  - 分屏或新窗口

## 3. 文档打开唯一模型
- 文件树点击文档 -> `document.open`
- 打开结果必须带：
  - 文档内容
  - 版本号
  - 脏状态
  - 视图模式
  - 引用关系快照
- 标签页不是独立数据源，只是 `openDocuments[]` 的 UI 投影。

## 4. 保存唯一规则
- 编辑后进入 `dirty`
- 保存只能通过 `document.save`
- `document.save` 返回后必须同步：
  - 新版本号
  - 新的 bootstrap 衍生数据
  - 引用关系刷新结果
- 视图切换不得清脏。

## 5. 引用关系唯一规则
- 正向引用、反向引用、引用对比都来自主进程索引，不得由 renderer 现算。
- 保存文档、导入文档、删除文档后，引用索引必须刷新。
- 对比关系必须是结构化结果，不是 renderer 侧字符串拼接。

## 6. 多标签/分屏/新窗口
- 多标签是默认能力。
- 分屏和新窗口共享同一工程状态源。
- 关闭分屏或子窗口不得导致主窗口标签状态丢失。

## 7. 冲突与恢复
- 外部文件冲突必须进入显式状态：
  - `conflict`
  - `save_error`
- 用户必须能选择：
  - 保留本地草稿
  - 重新加载外部版本
  - 手动比较后再决定

## 8. 测试 oracle
- 打开两个文档并切换标签，内容与脏状态不得串。
- 文档保存后引用关系必须更新。
- 外部变更冲突必须阻断静默覆盖。
- 分屏/新窗口关闭后主窗口状态必须可恢复。
