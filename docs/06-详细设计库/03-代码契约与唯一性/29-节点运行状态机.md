# 29 节点运行状态机

## 1. 目标
固定单个节点在 flow run 中的运行状态，不允许不同实现随意增删语义。

## 2. 状态集合
- `idle`
- `ready`
- `blocked`
- `running`
- `waiting_input`
- `success`
- `failed`
- `skipped`
- `cancelled`

## 3. 跃迁
1. `idle -> ready`
   - 条件：上游依赖满足、前置控制信号到达
2. `ready -> blocked`
   - 条件：配置缺失、目录缺失、工件契约不满足、guard 不满足
3. `ready -> running`
   - 条件：全部前置满足且开始执行
4. `running -> waiting_input`
   - 条件：人工确认节点或需要外部输入
5. `running -> success`
   - 条件：输出写入成功且 successCondition 满足
6. `running -> failed`
   - 条件：错误未被恢复策略吃掉
7. `running -> skipped`
   - 条件：条件节点判定该分支不执行
8. `running -> cancelled`
   - 条件：用户手动停止或上游取消信号到达

## 4. 事件要求
每次跃迁必须发运行事件：
- `node_ready`
- `node_blocked`
- `node_started`
- `node_waiting_input`
- `node_succeeded`
- `node_failed`
- `node_skipped`
- `node_cancelled`

## 5. UI 约束
1. 节点卡片必须能显示当前状态徽标。
2. `blocked` 节点必须能在 Inspector 中看到阻断原因。
3. `failed` 节点必须能触发重试或从此继续。

## 6. 测试 Oracle
1. 未配置完整的节点不能进入 `running`。
2. 条件分支未命中时必须是 `skipped`，不是 `success`。
3. 手动停止后，运行中的节点必须进入 `cancelled`。
