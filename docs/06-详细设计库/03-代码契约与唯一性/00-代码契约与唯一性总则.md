# 00 代码契约与唯一性总则

## 1. 文档定位
- 本目录用于约束“另一套 AI 或另一名程序员如何写出高度一致的代码”，不是需求层说明。
- 需求、功能树、功能清单负责约束产品；本目录负责约束代码边界、接口形态、状态机和判定标准。

## 2. 契约与唯一性目标
- 对 `M/S/A` 功能，允许存在的差异：
  - 内部函数名
  - 文件拆分方式
  - 样式实现细节
  - 局部状态管理写法
- 对 `M/S/A` 功能，不允许存在的差异：
  - 页面层级和主路径对象关系
  - IPC/服务边界
  - 状态机核心节点与跃迁
  - 数据契约字段集合
  - 阻断条件与错误分类
  - 自动测试的通过标准

## 4. 使用规则
- 任何 `M/S/A` 原子功能文档如果与本目录冲突，以本目录为准。
- 代码实现前必须先核对：
  - 是否落在既定的 Renderer / Main / Service 边界中
  - 是否遵守既定状态机
  - 是否遵守既定 JSON/对象契约
  - 是否已有明确测试 oracle

## 5. 禁止事项
- 不允许把关键业务状态只保存在 renderer 临时状态里。
- 不允许让 renderer 绕过主进程直接伪造成功结果。
- 不允许把“当前实现碰巧能跑通”当成对契约的替代。
- 不允许把未完成功能通过文案遮盖成“看起来可用”。
- 不允许用“矩阵存在”替代原子级 oracle、状态机、时序和恢复细节。

## 6. 范围
- 本目录优先约束以下高风险域：
  - 双主入口与模板中心
  - 主工作台与文档区
  - AI 会话与阶段控制
  - 编排页与 Flow 资产
  - 工件目录、阶段契约与导出映射
  - 技能/连接/模型中心
  - 多窗口、响应式和打包回归
