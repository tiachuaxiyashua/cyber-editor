# 45 回滚策略与损坏态修复流程

## 1. 目标
定义 happy path 之外，失败后如何回滚和修复。

## 2. 回滚原则
1. 写盘前失败：不改变现有有效文件。
2. 写盘中失败：仅保留临时文件，不替换正式文件。
3. 多步操作失败：以最后一个有效快照为回滚点。

## 3. 场景
### 3.1 Flow 保存失败
- 回滚：保持旧 revision，不更新当前正式文件
- 修复：修 schema / 目录后重试保存

### 3.2 导出失败
- 回滚：删除未完成的临时导出目录
- 修复：修正映射后重导出

### 3.3 模板更新失败
- 回滚：保留旧模板版本为 current
- 修复：重新安装或修 manifest

### 3.4 索引重建失败
- 回滚：保留旧索引并标 `stale`
- 修复：清缓存后全量重建

## 4. 测试 Oracle
1. 中途失败不得污染正式文件。
2. 回滚后用户仍能回到最后有效状态。
