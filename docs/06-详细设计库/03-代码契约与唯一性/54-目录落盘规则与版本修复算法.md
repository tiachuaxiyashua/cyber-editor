# 54 目录落盘规则与版本修复算法

## 1. 目录落盘规则
### 1.1 工程目录
```text
<project>/
  project.json
  artifacts/
    in/
    out/
  flows/
    <flowId>/
      flow.json
      ui.json
      contracts/
  exports/
  role-packages/
  templates/
  snapshots/
```

### 1.2 模板目录
```text
templates/<templateId>/
  manifest.json
  package.json
  flows/
  role-packages/
  artifacts/
```

### 1.3 角色包目录
```text
role-packages/<rolePackageId>/
  role.json
  IDENTITY.md
  SOUL.md
  AGENTS.md
  USER.md
  Skills/
  MEMORY/
    MEMORY.md
```

## 2. 版本升级策略
1. 先读 `version`
2. 若当前代码支持的最小版本高于对象版本，则执行迁移
3. 迁移顺序固定：
   - 填缺字段
   - 重命名旧字段
   - 生成默认嵌套对象
   - 写回新版本

## 3. 缺字段修复算法
```text
for each object:
  load schema defaults
  for each required field:
    if missing:
      inject default
  for each deprecated field:
    map to new field
  if required nested object still invalid:
    mark object broken
```

## 4. 修复后写回规则
1. 自动修复只允许写临时文件
2. 修复校验通过后替换正式文件
3. 修复失败则保留原文件并生成 `*_repair_report.json`

## 5. 方法级 I/O 示例
### `RuntimeAssetService.saveFlow`
输入
```json
{
  "projectId": "p1",
  "flowDraft": {
    "id": "flow-main",
    "kind": "flow",
    "name": "主流程",
    "nodes": [],
    "edges": [],
    "meta": {
      "inputDirectory": "artifacts/in",
      "outputDirectory": "artifacts/out"
    },
    "ui": {
      "viewport": { "x": 0, "y": 0, "zoom": 1 }
    }
  }
}
```
输出
```json
{
  "savedAt": "2026-04-10T10:00:00Z",
  "flowPath": "flows/flow-main/flow.json",
  "uiPath": "flows/flow-main/ui.json",
  "contractPaths": ["flows/flow-main/contracts/stage-contract.json"]
}
```

### `TemplateRegistryService.installFromRemote`
输入
```json
{
  "sourceUrl": "https://example.com/templates/gstack-software-factory.zip"
}
```
输出
```json
{
  "templateId": "gstack-software-factory",
  "installedVersion": "1.0.0",
  "installPath": "templates/gstack-software-factory"
}
```
