# F-081 连接资产管理

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 连接与工具 / 连接
- MSABC 分类：A
- 当前状态：部分完成
- 关联页面：[编排页](../../01-UI详细设计/07-编排页.md)、[技能与连接中心](../../01-UI详细设计/08-技能与连接中心.md)
- 上游需求：`D-C3`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. Flow 中的远程服务、本地服务和模型服务都必须以可复用连接资产存在。
2. 连接是团队和流程级资产，不能每个节点各自填一遍地址和密钥。
3. 用户需要在绑定前知道连接是否可用、是否已授权、是否受信任。

### 2.2 完成定义
1. 连接资产列表支持浏览、创建、编辑、复制、删除。
2. 每个连接显示类型、来源、授权状态、最后测试结果。
3. 连接详情支持测试连接。
4. 节点绑定连接时只能选择“健康且兼容”的连接。

## 3. 页面入口与层级
1. 入口页面：
   - 编排页设计态的“连接”资产区
   - 技能与连接中心
2. 层级：
   - `P1 编排页/连接中心`
   - `P2 连接列表`
   - `P3 连接详情与测试`

## 4. 用户操作流程
1. 用户进入连接资产区。
2. 新建连接，选择连接类型：
   - 本地 MCP
   - 远程 MCP
   - 本地 HTTP 服务
   - OpenAI-compatible 模型服务
3. 填写连接参数。
4. 点击“测试连接”。
5. 测试成功后保存，连接进入可绑定状态。

## 5. 可见效果与状态
1. 连接列表项显示：
   - 名称
   - 类型
   - 授权状态
   - 健康状态
   - 最后测试时间
2. 详情区显示：
   - 连接参数
   - 支持的能力摘要
   - 最近错误
3. 健康状态枚举：
   - 正常
   - 未测试
   - 授权缺失
   - 失败
   - 不兼容

## 6. 数据模型
```json
{
  "connectorId": "conn_local_ollama",
  "name": "本地 Ollama",
  "type": "openai-compatible",
  "baseUrl": "http://127.0.0.1:11434/v1",
  "authMode": "none",
  "health": "healthy",
  "lastCheckedAt": "2026-04-09T12:00:00Z"
}
```

## 7. 具体实现方案
### 7.1 Renderer
组件：
1. `ConnectorAssetList`
2. `ConnectorEditor`
3. `ConnectorHealthBadge`
4. `ConnectorTestResultPanel`

Renderer 责任：
1. 提供统一表单，不在不同页面复制出多套字段。
2. 根据连接类型切换字段集。
3. 测试结果显示为结构化状态，而非只显示一行 toast。

### 7.2 Main / Service
服务：
1. `connector-registry`
2. `permission-governance`

Main 责任：
1. 保存连接配置。
2. 触发真实连接诊断。
3. 计算连接健康状态与兼容性。

## 8. 校验与阻断
1. URL 缺失或格式错误时禁止保存。
2. 同名连接允许，但 `connectorId` 必须唯一。
3. 测试失败的连接可保存为草稿，但节点绑定时默认过滤掉。
4. 远程连接缺少授权时，状态必须是“授权缺失”，不能伪装成普通失败。

## 9. 自动测试
### 9.1 单元
1. 连接类型与字段映射
2. 健康状态映射
3. 节点绑定过滤规则

### 9.2 端到端
1. 创建本地 Ollama 连接并测试。
2. 创建错误 URL 的远程连接，确认失败状态可见。
3. 节点绑定时确认仅健康连接可选。

## 10. 用户模拟测试
1. 新建一个本地 Ollama 连接。
2. 测试成功后保存。
3. 打开某个节点绑定连接，确认该连接可选。
4. 新建一个错误 URL 连接，确认其在节点绑定列表中不可选。

## 11. 不允许的错误实现
1. 连接只是文本配置项，没有健康状态和授权状态。
2. 测试连接只做前端假动作，不发真实请求。
3. 节点可以绑定失败连接。
