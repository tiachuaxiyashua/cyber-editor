# F-069 并行分叉与并行汇合配置

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 流程语义 / 并行
- MSABC 分类：S
- 当前状态：未完成
- 关联页面：[编排页](../../01-UI详细设计/07-编排页.md)
- 上游需求：`D-C2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 多角色并行是编排页区别于简单流程图工具的关键能力。
2. 用户必须能看见“哪些分支同时跑、何时汇合、失败后怎么办”。

### 2.2 完成定义
1. 用户可创建并行分叉节点和并行汇合节点。
2. 用户可清楚看见分支数量和分支命名。
3. 汇合节点可配置等待策略和失败策略。
4. 并行路径可进入真实运行态，不只是画图。

## 3. 页面入口与层级
1. 入口：编排页设计态
2. 编辑对象：
   - 并行分叉节点
   - 并行汇合节点
3. Inspector 必须有专门的并行配置区

## 4. 用户操作流程
1. 用户拖入一个并行分叉节点。
2. 用户从分叉节点拉出多个分支。
3. 用户给每个分支命名。
4. 用户拖入一个汇合节点并连接各分支。
5. 在汇合节点中配置：
   - 全部完成后继续
   - 任一失败即停止
   - 允许部分失败继续

## 5. 可见效果与状态
1. 分叉节点必须显示分支数量。
2. 汇合节点必须显示当前等待的分支数。
3. 设计态下能看出哪些边属于并行域。
4. 运行态下能看出：
   - 哪些分支在运行
   - 哪些分支已完成
   - 哪些分支失败

## 6. 数据模型
```json
{
  "splitNodeId": "split_001",
  "branches": [
    { "branchId": "blue", "label": "蓝军分支" },
    { "branchId": "red", "label": "红军分支" }
  ],
  "joinNodeId": "join_001",
  "joinPolicy": "all_success",
  "failurePolicy": "stop_all"
}
```

## 7. 具体实现方案
### 7.1 Renderer
1. 在分叉节点 Inspector 提供分支管理表。
2. 在汇合节点 Inspector 提供汇合策略选择。
3. 在画布中对并行分支边做视觉分组。

### 7.2 Main / Service
建议服务：
1. `parallel-runtime`
2. `flow-validation-engine`

Main 责任：
1. 验证分叉后每个分支都能到达汇合节点或终点。
2. 运行时并发调度分支。
3. 汇合节点根据策略判断是否继续。

## 8. 校验与阻断
1. 分叉后若某分支未连接到有效下游，阻止运行。
2. 汇合节点未绑定分支时阻止运行。
3. 汇合策略未设置时阻止运行。

## 9. 自动测试
### 9.1 单元
1. 并行结构校验
2. 汇合策略校验

### 9.2 端到端
1. 构建双分支并行 Flow
2. 保存并重开
3. 验证结构不丢

## 10. 用户模拟测试
1. 创建并行分叉。
2. 建立两个分支。
3. 用汇合节点合并。
4. 切到运行态，确认分支状态可见。

## 11. 不允许的错误实现
1. 只是画两条边，没有并行语义。
2. 汇合节点不校验缺失分支。
3. 运行态下看不出分支状态。
