# F-059 编排页入口

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 入口 / 页面
- MSABC 分类：S
- 当前状态：已完成
- 关联页面：[欢迎页](../../01-UI详细设计/01-欢迎页.md)、[主工作台](../../01-UI详细设计/03-主工作台.md)、[编排页](../../01-UI详细设计/07-编排页.md)、[无工程编排模式](../../01-UI详细设计/10-无工程编排模式.md)
- 上游需求：`D-A1`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 编排页是产品核心，不是隐藏附页。
2. 用户必须能从工程态和无工程态都进入编排页。

### 2.2 完成定义
1. 欢迎页有“创建编排”主入口。
2. 主工作台有进入编排页的一级入口。
3. 无工程编排模式和工程内编排模式都能进入同一套编排页。
4. 用户始终知道当前是“工程内编排”还是“无工程编排”。

## 3. 页面入口与层级
1. 欢迎页 -> 创建编排
2. 主工作台左侧活动栏 -> 编排
3. 模板中心 -> 从模板直接开始编排

## 4. 用户操作流程
1. 用户从任一入口点击进入编排页。
2. 系统根据上下文决定：
   - 打开工程内 Flow
   - 打开无工程编排草稿
3. 编排页头部显示当前模式和当前 Flow 名称。

## 5. 可见效果与状态
1. 页面头部必须显示：
   - 当前模式
   - 当前 Flow 名称
   - 保存状态
2. 进入编排页后，画布必须成为视觉中心。

## 6. 具体实现方案
### 6.1 Renderer
组件：
1. `OrchestrationEntryAction`
2. `OrchestrationModeBadge`
3. `OrchestrationWorkspace`

### 6.2 Main / Service
服务：
1. `flow-asset-persistence`
2. `template-scaffold-save-service`

Main 责任：
1. 判断当前上下文并返回正确 Flow。
2. 支持无工程草稿与工程内 Flow 两套读取路径。

## 7. 校验与阻断
1. 不允许只有工程内入口，没有欢迎页直接编排入口。
2. 不允许进入编排页后看不出当前模式。

## 8. 自动测试
### 8.1 端到端
1. 从欢迎页进入编排页。
2. 从主工作台进入编排页。
3. 从模板中心进入编排页。
4. 验证头部模式正确。

## 9. 用户模拟测试
1. 首次打开应用，直接点击创建编排。
2. 进入编排页后确认模式为“无工程编排”。
3. 再从一个已有工程进入编排页，确认模式切换为“工程内编排”。

## 10. 不允许的错误实现
1. 编排页只能通过某个隐藏图标进入。
2. 编排页和普通页面没有模式区分。
3. 进入编排页后仍保留大量与编排无关的页面噪声。

## 11. 当前审计结论
- 审计状态：已完成
- 审计说明：编排页入口、欢迎页直接进入编排、主工作台进入编排和编排页可见性已有对应 UI 路径与测试证据；复杂编排运行能力仍按各自 F/INF 条目单独判定，不由本入口条目承诺完成。
