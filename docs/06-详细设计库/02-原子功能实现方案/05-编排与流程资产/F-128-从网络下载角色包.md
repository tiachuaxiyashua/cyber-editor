# F-128 从网络下载角色包

## 1. 功能定义
用户可从网络角色注册表下载角色包，并将其安装为本地可用角色包。

- MSABC 分类：A
- 当前状态：部分完成

## 1.1 代码反哺状态
- 已实现：preload 暴露 `installRoleFromUrl()`、`installRoleFromPath()`、`listRoleCatalog()`；IPC 通道为 `roles:list-catalog`、`roles:install-url` 和 `roles:install-path`。
- 已实现：`RolePackageRegistryService.loadCatalog()` 支持内置目录、本地目录和远程目录；`inspectPackageFromUrl()` 通过 `remote-fetch-guard` 下载并交给资源治理审查；`installFromUrl()` 要求 review 结果需要人工批准时必须显式 `approved=true`。
- 已实现：`src/shared/role-package.ts` 校验 `role.json`、`IDENTITY.md`、`AGENTS.md` 为必需文件，`SOUL.md`、`USER.md`、`MEMORY/MEMORY.md`、`Skills/skills.json` 为可选文件；文件路径会经过安全段校验。
- 已有证据：`tests/unit/remote-resource-registry.test.ts` 覆盖远程角色目录、远程 URL 安装需要审批、解析失败和 `builtin://` 安装；`tests/unit/register-resource-ipc.test.ts` 覆盖 `roles:install-url` 先走 `completeGovernedInstall` 再变更注册表。
- 仍未完成：编排页内角色资产区的网络下载入口和真实 UI e2e 远程 URL 安装证据不足；当前 e2e 主要覆盖资源中心本地角色包导入。

## 2. 入口
- 编排页角色资产区的“下载角色包”
- 技能与连接中心的“角色包”分页

## 3. 支持内容
- 远程目录浏览
- 直接 URL 安装
- 来源、版本、兼容性与信任状态展示

## 4. 方法级 IO
### IPC
- `roles:list-catalog`
- `roles:install-url`
- `roles:install-path`

请求：
```json
{
  "url": "https://example.com/roles/clarifier-role-package.json"
}
```

响应：
```json
{
  "id": "clarifier-role",
  "installed": true,
  "source": "remote"
}
```

## 5. 动作时序
1. 用户点击下载角色包。
2. 打开来源选择或 URL 输入对话框。
3. Main 调用 `RolePackageRegistryService.inspectPackageFromUrl()` 下载并交给资源治理审查。
4. 成功后写入角色包注册目录。
5. 刷新角色资产列表。

## 6. 校验
- 角色包必需文件：
  - `role.json`
  - `IDENTITY.md`
  - `AGENTS.md`
- 角色包可选但建议包含：
  - `SOUL.md`
  - `USER.md`
  - `MEMORY/MEMORY.md`
  - `Skills/skills.json`
- 必须声明兼容版本。

## 7. 错误处理
- 网络不可达：可重试。
- 包结构不合法：阻断安装。
- 已安装但版本更低：提示更新。

## 8. 自动化测试
- mock 远程包并安装成功。
- 包字段缺失时阻断并提示。
- 安装成功后角色列表刷新。

## 显式测试 Oracle
### 最小输入样例
1. 远程角色包 URL：`https://example.com/roles/clarifier-role-package.json`。
2. 角色包至少包含 `role.json`、`IDENTITY.md`、`AGENTS.md`；推荐包含 `SOUL.md`、`USER.md`、`MEMORY/MEMORY.md`、`Skills/skills.json`。

### 主动作
1. 用户点击下载角色包。
2. 打开来源选择或 URL 输入对话框。
3. Main 调用 `RolePackageRegistryService.inspectPackageFromUrl()` 下载、解析并生成治理审查。
4. 成功后写入角色包注册目录。
5. 刷新角色资产列表。

### 成功判定
1. mock 远程包可以安装成功。
2. 安装成功后角色列表刷新。
3. 来源、版本、兼容性与信任状态可见。

### 文件与状态判定
1. IPC 提供 `roles:list-catalog` 和 `roles:install-url`。
2. 安装请求至少包含 `url`。
3. 未批准高风险或 review 包时，响应必须是 `review-required`，不得写入注册表。
4. 成功安装后本地角色包注册目录出现对应条目。
5. 单元测试必须覆盖远程 catalog、远程 URL 安装审批、解析失败和内置 URL 安装。

### 错误与边界判定
- 网络不可达：可重试。
- 包结构不合法：阻断安装。
- 已安装但版本更低：提示更新。
