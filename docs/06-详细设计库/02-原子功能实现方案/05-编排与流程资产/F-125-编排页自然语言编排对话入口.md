# F-125 编排页自然语言编排对话入口

## 1. 功能定义
在编排页顶部提供专用 AI 编排对话入口。用户可以用自然语言描述要搭建的流程，或要求 AI 对当前 Flow 做增量修改。

- MSABC 分类：S
- 当前状态：部分完成

## 1.1 代码反哺状态
- 已实现链路：`OrchestrationWorkspace.tsx` 通过 `onConversationTargetChange` 把当前 Flow 设为 `orchestration-flow` 对话目标，`App.tsx` 在 `sendMessage()` 中按该目标分流到 `window.api.planConversationFlow`、`buildConversationFlowDraft`、`patchConversationFlow` 和 `applyConversationFlowPatch`。
- 已实现预览：`flowConversationPreview` 以 `data-testid="flow-conversation-preview"` 展示草稿或补丁预览，用户点击“应用草稿/应用修改”后才写入工程 Flow 或无工程草稿。
- 已有证据：`tests/unit/conversation-flow-service.test.ts` 覆盖启发式计划、模型 JSON 计划和 patch 应用；`tests/e2e/real-user-deepseek-solo-company.spec.ts` 覆盖编排对话生成 patch 预览并应用到画布。
- 仍未完成：文档中原本定义的独立顶部 `AI 编排` 按钮、逐项局部接受、运行中只读阻断和专门的空输入 UI oracle 尚未形成完整自动化证据，因此不能标记为已完成。

## 2. 触发与入口
- 已实现入口：编排页画布操作区的“打开流程对话”按钮会打开右侧上下文会话，并把当前 Flow 绑定为对话目标。
- 已实现输入区：右侧上下文会话和编排页的 `.orchestration-chat-composer` 负责输入自然语言。
- 未完成入口：独立顶部 `AI 编排` 按钮、空画布快捷入口和命令面板 `打开 AI 编排` 仍是目标设计，不能作为当前完成证据。

## 3. 用户操作
1. 用户打开编排页。
2. 点击 `打开流程对话`。
3. 右侧上下文会话面板打开，并显示当前 Flow 目标。
4. 输入自然语言。
5. 发送消息后查看草稿或补丁预览。

## 4. 期望效果
- 对话面板显示本次输入、AI 解释和待应用结果摘要。
- 若当前无 Flow，则返回一份新的 Flow 草稿预览。
- 若当前已有 Flow，则返回一份补丁预览。
- 未经用户确认，不允许自动改写当前 Flow。

## 5. 局部组件与对象边界
- Renderer 组件：
  - `OrchestrationWorkspace`
  - `ContextPane`
  - `flowConversationPreview` 模态框
- Shared 对象：
  - `FlowPlan`
  - `FlowPatch`
- Main 服务：
  - `ConversationFlowService`

## 6. 方法级 IO
### Renderer
- `openConversation(): void`
- `sendMessage(): Promise<void>`
- `applyFlowConversationPreview(): Promise<void>`
- `dismissFlowConversationPreview(): void`

输入：
- `message: string`
- `activeFlowId?: string`
- `flowDraftSummary?: string`

输出：
- `flowConversationPreview.mode = "draft" | "patch"`
- `flowConversationPreview.draft` 或 `flowConversationPreview.preview`

### IPC
- `conversation-flow:plan`
- `conversation-flow:draft`
- `conversation-flow:patch`
- `conversation-flow:apply-patch`

请求：
```json
{
  "prompt": "帮我做一个从需求澄清到 QA 复盘的软件交付流程",
  "flow": {
    "id": "current-flow",
    "nodes": [],
    "edges": []
  }
}
```

响应：
```json
{
  "flowConversationPreview": {
    "mode": "draft",
    "prompt": "帮我做一个从需求澄清到 QA 复盘的软件交付流程",
    "draft": {
      "nodes": [],
      "edges": []
    }
  }
}
```

## 7. 动作时序
1. 用户点击 `打开流程对话`。
2. Renderer 打开右侧上下文会话面板，并绑定当前 Flow。
3. 用户提交文本。
4. Renderer 根据当前 Flow 是否为 bootstrap minimal flow，调用 `conversation-flow:draft` 或 `conversation-flow:patch`。
5. Main 侧生成 `FlowPlan`、`PlatformFlowAsset` 草稿或 `FlowPatch`。
6. Renderer 展示草稿或补丁预览。
7. 用户选择应用或取消；局部接受仍是目标能力。

## 8. 错误与阻断
- 输入为空：本地阻断，不发请求。
- 当前 Flow 处于运行中：提示仅允许只读分析，不允许应用补丁。
- AI 生成补丁不可解析：进入错误态，允许重试。

## 9. 自动化测试
- 打开编排页，点击 `打开流程对话`，右侧会话面板出现。
- 输入自然语言后，调用对应 IPC。
- bootstrap minimal Flow 时返回 `flowConversationPreview.mode = "draft"`。
- 已有非空 Flow 时返回 `flowConversationPreview.mode = "patch"`。
- 不点确认时，画布不变。

## 10. 用户模拟测试
- 小白用户输入一句自然语言后，能看懂 AI 生成了什么。
- 高手用户能看见新增/修改/删除的节点、边、角色建议。

## 11. 不允许的错误实现
- 把自然语言编排放到设置页。
- 用户一发送消息就直接改写当前 Flow。
- 只返回纯文本说明，不返回结构化补丁。

## 显式测试 Oracle
### 最小输入样例
1. 用户在编排页输入：`帮我做一个从需求澄清到 QA 复盘的软件交付流程`。
2. 当前可处于无活跃 Flow 或已有 Flow 两种上下文。

### 主动作
1. 用户打开编排页。
2. 点击 `打开流程对话`。
3. 右侧上下文会话面板打开。
4. 输入自然语言。
5. 发送消息并查看草稿或补丁预览。

### 成功判定
1. 对话面板显示用户输入、AI 解释和待应用结果摘要。
2. 无活跃 Flow 时返回新 Flow 草稿预览。
3. 已有 Flow 时返回补丁预览。
4. 未经用户确认，当前 Flow 不被自动改写。

### 文件与状态判定
1. Renderer 提供 `openConversation()`、`sendMessage()`、`applyFlowConversationPreview()` 和 `dismissFlowConversationPreview()`。
2. IPC 调用 `conversation-flow:plan`、`conversation-flow:draft`、`conversation-flow:patch` 或 `conversation-flow:apply-patch`。
3. 请求至少包含 `prompt`；patch 分支必须携带当前 `flow`。
4. 响应写入 `flowConversationPreview`，未经用户点击应用不得保存到 `saveFlow()` 或 `saveDraftFlow()`。

### 错误与边界判定
- 输入为空：本地阻断，不发请求。
- 当前 Flow 处于运行中：提示仅允许只读分析，不允许应用补丁。
- AI 生成补丁不可解析：进入错误态，允许重试。
