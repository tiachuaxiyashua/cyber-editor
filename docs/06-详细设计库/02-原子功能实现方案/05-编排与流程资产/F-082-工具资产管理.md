# F-082 工具资产管理

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 连接与工具 / 工具
- MSABC 分类：A
- 当前状态：部分完成
- 关联页面：[编排页](../../04-UI设计/07-编排页.md)、[技能与连接中心](../../04-UI设计/08-技能与连接中心.md)
- 上游需求：`D-C3`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 工具是能力层的原子动作，必须可复用、可诊断、可绑定。
2. 用户要知道某个工具是脚本工具、MCP 工具还是内置工具。
3. 没有工具资产管理，节点绑定会退化成随意填字符串。

### 2.2 完成定义
1. 工具资产列表支持创建、编辑、复制、删除、测试。
2. 每个工具显示类型、参数 schema、权限边界、健康状态。
3. 脚本工具必须支持指定命令、参数 schema、工作目录、白名单目录、超时。
4. 节点绑定工具时只允许选择可用工具。

## 3. 页面入口与层级
1. 入口页面：
   - 编排页设计态的“工具”资产区
   - 技能与连接中心
2. 层级：
   - `P1 编排页/连接中心`
   - `P2 工具列表`
   - `P3 工具详情与测试`

## 4. 用户操作流程
1. 用户进入工具资产区。
2. 选择新建工具类型：
   - 受控本地脚本
   - MCP 工具引用
   - 内置工具引用
3. 填写工具信息与权限边界。
4. 点击“测试工具”运行一次最小测试。
5. 保存后在节点中进行绑定。

## 5. 可见效果与状态
1. 工具列表项固定显示：
   - 名称
   - 类型
   - 参数 schema 摘要
   - 最后测试状态
2. 工具详情区显示：
   - 执行命令或引用来源
   - 超时设置
   - 可访问目录
   - 危险等级
3. 工具测试失败时必须显示结构化错误信息。

## 6. 数据模型
```json
{
  "toolId": "tool_render_markmap",
  "type": "script",
  "command": "node tools/render-markmap.mjs",
  "timeoutMs": 30000,
  "allowedPaths": ["./workspace", "./temp"],
  "inputSchemaRef": "schemas/render-markmap-input.json",
  "health": "healthy"
}
```

## 7. 具体实现方案
### 7.1 Renderer
组件：
1. `ToolAssetList`
2. `ToolEditor`
3. `ToolSchemaPreview`
4. `ToolTestResultPanel`

Renderer 责任：
1. 将工具类型差异收敛为统一表单壳层。
2. 用 schema 预览帮助用户理解输入参数。
3. 在危险工具上显示显式警告。

### 7.2 Main / Service
服务：
1. `script-tool-adapter`
2. `capability-registry`
3. `permission-governance`

Main 责任：
1. 真正保存工具配置。
2. 执行工具测试。
3. 校验路径白名单和权限边界。

## 8. 校验与阻断
1. 本地脚本工具必须声明命令、超时和可访问目录。
2. 未声明 input schema 的脚本工具不得进入“健康”状态。
3. 危险目录或越权命令必须阻断。
4. 工具测试失败仍可保存为草稿，但节点绑定时默认不可选。

## 9. 自动测试
### 9.1 单元
1. 脚本工具 schema 校验
2. 白名单路径校验
3. 绑定可见性过滤

### 9.2 端到端
1. 创建受控本地脚本工具。
2. 测试工具成功后保存。
3. 节点绑定工具时确认其可选。
4. 创建缺少 schema 的工具，确认处于异常状态。

## 10. 用户模拟测试
1. 新建一个脚本工具并填写命令、目录、schema。
2. 测试工具，确认状态变为正常。
3. 在节点中绑定它。
4. 再新建一个危险路径工具，确认系统阻断。

## 11. 不允许的错误实现
1. 工具没有 schema，只有一个名字。
2. 工具测试只是保存成功提示，没有真实执行。
3. 节点绑定工具时能选到未通过测试的工具。

## 12. 当前审计结论

- 审计说明：当前工具资产仍缺 schema、白名单和测试结果驱动的可绑定闭环。
