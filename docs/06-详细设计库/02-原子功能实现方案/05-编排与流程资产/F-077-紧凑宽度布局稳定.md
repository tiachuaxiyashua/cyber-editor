# F-077 紧凑宽度布局稳定

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 布局 / 响应式
- MSABC 分类：A
- 当前状态：未完成
- 关联页面：[编排页](../../04-UI设计/07-编排页.md)
- 上游需求：`D-C4`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 用户会通过拖拽窗口、分屏和显示器缩放让编排页进入紧凑宽度。
2. 专业编辑器不能只在默认尺寸下可用。

### 2.2 完成定义
1. 在 `1440`、`1280`、`1024`、`900`、`800` 宽度下，编排页都不出现重叠、遮挡、竖排、假死。
2. 当宽度不足时，面板通过折叠和优先级降级让出空间，而不是让文字堆叠。
3. 设计态和运行态都要通过同一套紧凑宽度规则。

## 3. 响应式断点规则
1. `>= 1440px`
   - 完整三栏
2. `1280px - 1439px`
   - 三栏保留，但左右面板进入紧凑宽度
3. `1024px - 1279px`
   - 允许单侧面板折叠，画布优先
4. `900px - 1023px`
   - 默认只保留一侧面板展开
5. `< 900px`
   - 不承诺最佳体验，但必须可滚动、可关闭面板、不卡死

## 4. 可见效果与状态
1. 标题和按钮不允许竖排。
2. 节点库、资产栏、Inspector 允许切页或折叠，但不允许互相覆盖。
3. 画布始终保持最小可交互区。
4. 运行面板只在必要时展开，不得把主画布完全遮住。

## 5. 具体实现方案
### 5.1 Renderer
组件：
1. `ResponsiveOrchestrationLayout`
2. `CompactModeSwitch`
3. `PanePriorityController`

Renderer 责任：
1. 监听窗口尺寸变化。
2. 在不同断点切换布局策略。
3. 为被收起的面板提供显式恢复入口。

### 5.2 Main / Service
服务：
1. `ui-responsive-layout-engine`
2. `settings-layout-persistence`

Main 责任：
1. 记录用户在紧凑宽度下的布局偏好。
2. 在重新打开时恢复到相近断点下的最后状态。

## 6. 校验与阻断
1. 任一断点下如果元素重叠，视为不合格。
2. 若断点切换导致某面板被自动折叠，必须显示恢复入口。
3. 不允许在窄宽度下出现无法滚动、无法点击的遮挡。

## 7. 自动测试
### 7.1 端到端
1. 在 `1440/1280/1024/900/800` 五组宽度下截图。
2. 在各宽度下测试左右面板拖拽后再截图。
3. 在各宽度下切换设计态/运行态。

### 7.2 审核指标
1. 标题行高度
2. 工具栏是否换成多行但不重叠
3. Inspector 是否仍可输入

## 8. 用户模拟测试
1. 把窗口拖到接近 1024 宽。
2. 确认画布仍然可用，且至少一侧面板有明确折叠逻辑。
3. 再缩到 900 宽，确认不会出现竖排标题和覆盖层挡满页面。

## 9. 不允许的错误实现
1. 只在默认宽度截一张图就算通过。
2. 窄宽度下文本竖排、控件堆叠、按钮遮挡。
3. 自动折叠后没有任何恢复入口。

## 10. 当前审计结论
- 审计状态：未完成
- 审计说明：紧凑宽度稳定性仍缺完整断点规则和正式回归矩阵。
