# F-064 拖拽节点进入画布

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：编排与流程资产 / 节点库 / 拖拽
- MSABC 分类：S
- 当前状态：未完成
- 关联页面：[编排页](../../01-UI详细设计/07-编排页.md)
- 上游需求：`D-C2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 编排页如果不能拖拽节点进入画布，就不算专业编辑器。
2. 小白用户通过拖拽小卡片理解“流程是搭出来的”。
3. 高手用户通过拖拽快速完成复杂布局。

### 2.2 完成定义
1. 节点库以小卡片方式展示可用节点。
2. 用户可将节点卡片直接拖入画布。
3. 放下后节点立刻出现在投放位置。
4. 新节点默认进入选中状态，并打开右侧 Inspector。
5. 位置写入当前 Flow 草稿，后续编辑不丢失。

## 3. 页面入口与层级
1. 入口页面：编排页设计态
2. 主操作对象：节点库卡片
3. 目标区域：画布

## 4. 用户操作流程
1. 用户在左侧节点库看到节点小卡片。
2. 用户按住卡片拖拽到画布。
3. 画布出现投放高亮。
4. 用户松手后节点被创建。
5. 右侧 Inspector 显示该节点配置。

## 5. 可见效果与状态
1. 节点卡片默认显示：
   - 图标
   - 名称
   - 简短说明
2. 拖拽中：
   - 鼠标跟随预览
   - 画布显示可投放区域
3. 投放成功：
   - 节点高亮
   - Inspector 自动切换
4. 投放失败：
   - 画布显示失败反馈
   - 不生成半成品节点

## 6. 数据模型
```json
{
  "nodeId": "node_role_001",
  "nodeType": "role",
  "position": { "x": 640, "y": 280 },
  "status": "unconfigured"
}
```

## 7. 具体实现方案
### 7.1 Renderer
1. `NodePalette`
2. `PaletteCard`
3. `CanvasDropLayer`
4. `OrchestrationCanvas`

Renderer 责任：
1. 提供 draggable 数据
2. 计算投放坐标
3. 将投放动作提交给 Flow draft state
4. 更新当前选中节点

### 7.2 Main / Service
建议服务：
1. `flow-asset-persistence`
2. `canvas-layout-state-store`

Main 责任：
1. 在保存时持久化节点位置与节点结构
2. 恢复时按最后布局还原

## 8. 校验与阻断
1. 不允许拖到非法区域后静默创建。
2. 不允许创建后不写入 Flow 草稿。
3. 不允许投放后节点未选中、Inspector 不切换。

## 9. 自动测试
### 9.1 单元
1. 投放坐标计算
2. 节点创建 payload

### 9.2 端到端
1. 从节点库拖入角色节点
2. 验证节点出现
3. 验证 Inspector 切换
4. 保存后重开验证位置仍在

## 10. 用户模拟测试
1. 打开编排页。
2. 从节点库拖一个角色节点到画布中央。
3. 检查节点是否落在放下位置。
4. 再拖一个工具节点到旁边。
5. 切换到其他资产再切回，确认位置不丢。

## 11. 不允许的错误实现
1. 用“点击新增”假装等价于拖拽。
2. 只能从文本列表创建节点。
3. 节点投放后位置被后续普通编辑重置。
