# F-090 导出映射配置

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：模板工件与导出 / 导出 / 映射
- MSABC 分类：A
- 当前状态：未完成
- 关联页面：[编排页](../../01-UI详细设计/07-编排页.md)、[流程面板](../../01-UI详细设计/06-流程面板.md)
- 上游需求：`D-C1`、`D-C2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 最终交付结构必须由模板和编排决定，不由产品写死。
2. 用户需要明确知道“哪些工件会导出成什么、导到哪里”。

### 2.2 完成定义
1. 用户能按导出格式配置 `RuntimeTemplateExportMapping`。
2. 支持至少：
   - `markdown`
   - `text`
   - `pdf`
   - `openspec`
   - `custom`
3. 每个导出格式都可配置启用状态、工件路径集合、输出目录模式、文件名模式和转换策略。
4. 允许把中间工件排除在最终导出之外。
5. 若模板未显式声明某个格式的映射，则运行时按 `exportProfile` 和 `stageDocuments` 自动生成默认映射。
6. 运行导出前先校验映射完整性。

## 3. 用户操作流程
1. 用户打开导出映射资产。
2. 选择一个导出格式页签，如 `markdown`、`text`、`pdf`、`openspec` 或 `custom`。
3. 为该格式配置 `enabled` 与 `artifactPaths`。
4. 配置 `outputPathPattern`、`fileNamePattern` 和 `transformProfile`。
5. 保存后，流程面板中的导出入口使用该映射。

## 4. 数据模型
```json
{
  "markdown": {
    "enabled": true,
    "artifactPaths": [
      "01-requirements/01-原始需求.md",
      "01-requirements/02-需求澄清.md"
    ],
    "outputPathPattern": "exports/markdown",
    "fileNamePattern": "delivery-package.md",
    "transformProfile": "markdown"
  },
  "openspec": {
    "enabled": true,
    "artifactPaths": [
      "01-requirements/03-功能树.md",
      "02-solution/01-技术方案.md"
    ],
    "outputPathPattern": "03-openspec/exports",
    "fileNamePattern": "openspec",
    "transformProfile": "openspec"
  }
}
```

当前代码口径：
- 映射类型为 `RuntimeTemplateExportMapping`，单个格式条目类型为 `RuntimeTemplateExportMappingEntry`。
- 导出格式开关来自 `RuntimeTemplateExportProfile`。
- `software-factory` 当前只显式覆写了 `openspec.outputPathPattern = 03-openspec/exports`，其余格式走运行时默认值。

## 5. 具体实现方案
### 5.1 Renderer
1. `ExportMappingEditor`
2. `ExportTargetTabs`
3. `ExportArtifactTable`

### 5.2 Main / Service
1. `export-mapping-service`
2. `delivery-export-service`
3. `openspec-exporter`

## 6. 校验与阻断
1. 某个导出格式 `enabled=true` 但 `artifactPaths` 为空时，允许保存，但导出前必须警告为空。
2. 引用不存在工件时阻止保存。
3. `outputPathPattern` 非法时阻止保存。
4. `fileNamePattern` 为空时阻止保存。
5. `transformProfile` 必须与当前运行时支持的导出策略一致。
6. OpenSpec 格式若缺必需工件，阻止导出。

## 7. 自动测试
1. 映射保存与恢复
2. 空映射告警
3. OpenSpec 必需工件校验

## 8. 用户模拟测试
1. 配置一个 `pdf` 导出映射。
2. 只包含 2 个工件。
3. 运行导出后确认仅导出这 2 个结果。
4. 再配置一个损坏映射，确认系统阻止导出。

## 9. 不允许的错误实现
1. 导出仍然固定写死读取几个文件。
2. 映射只显示不参与实际导出。
3. 中间工件无法排除。
4. 继续使用 `target/outputDirectory/items[]` 这类旧对象模型。

## 10. 当前审计结论
- 审计状态：未完成
- 审计说明：导出映射仍未成为一等配置对象，当前仍不足以支撑任意模板输出结构。
