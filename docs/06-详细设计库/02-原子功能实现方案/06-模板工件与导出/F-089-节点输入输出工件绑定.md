# F-089 节点输入输出工件、消息与信号绑定

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：模板工件与导出 / 输出契约 / 节点
- MSABC 分类：S
- 当前状态：未完成
- 关联页面：[编排页](../../01-UI详细设计/07-编排页.md)
- 上游需求：`D-C2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 节点要真正可运行，必须知道读什么、写什么、发什么。
2. 多 Agent 协作必须建立在节点 IO 上，而不是角色自由发挥。

### 2.2 完成定义
1. 节点 Inspector 支持配置：
   - 输入工件
   - 输出工件
   - 输入消息
   - 输出消息
   - 输出控制信号
2. 保存后这些配置写入 Flow。
3. 运行时严格按这些配置检查和执行。

## 3. 用户操作流程
1. 用户选中一个节点。
2. 在 Inspector 分别配置 5 类输入输出。
3. 保存后重新打开 Flow，配置仍存在。
4. 运行节点时，运行面板能看见实际读写结果。

## 4. 数据模型
```json
{
  "nodeId": "judge_001",
  "inputArtifacts": ["review/blue-draft.md", "review/red-issues.md"],
  "outputArtifacts": ["review/judge-summary.md"],
  "inputMessages": ["runtime/blue_packet.json", "runtime/red_packet.json"],
  "outputMessages": ["runtime/judge_packet.json"],
  "outputSignals": ["continue_review"]
}
```

## 5. 具体实现方案
### 5.1 Renderer
1. `NodeIOEditor`
2. `ArtifactBindingTable`
3. `MessageBindingTable`
4. `SignalBindingTable`

### 5.2 Main / Service
1. `node-io-contract-service`
2. `artifact-catalog-service`
3. `parallel-runtime`

## 6. 校验与阻断
1. 不允许引用不存在工件。
2. 不允许发送未声明信号。
3. 不允许把输出格式配置在角色上替代节点 IO。

## 7. 自动测试
1. 节点 IO 保存与恢复
2. 无效工件阻断
3. 信号枚举校验

## 8. 用户模拟测试
1. 为一个裁判节点配置输入工件和输出工件。
2. 再配置输入消息和输出信号。
3. 保存并重开确认仍存在。
4. 删掉一个工件后确认系统报错。

## 9. 不允许的错误实现
1. 只有工件，没有消息和信号层。
2. 运行时无视节点 IO 配置。
3. 节点 IO 只在内存里，不写盘。

## 10. 当前审计结论
- 审计状态：未完成
- 审计说明：节点 IO 仍不足以支撑多 Agent 协作和流程控制。
