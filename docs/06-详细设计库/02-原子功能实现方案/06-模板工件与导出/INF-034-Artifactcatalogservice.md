# INF-034 Artifact catalog service

## 1. 基本信息
- 类型：内部功能
- 所属层级：编排层 / 工件模型 / 目录
- MSABC 分类：S
- 当前状态：部分完成
- 关联页面：编排页工件资产区、阶段面板、导出面板
- 共享实现基线：[模板工件与导出](README.md)

## 2. 责任与完成定义
### 2.1 服务责任
1. 管理模板和 Flow 允许的工件目录。
2. 维护工件定义、位置、类型、状态。
3. 为节点 IO、阶段契约和导出映射提供工件事实来源。

### 2.2 完成定义
1. 工件目录以统一结构输出。
2. 不同页面和服务从同一工件目录读取。
3. 工件新增、删除、重命名能同步影响节点 IO 和导出映射。

## 3. 核心接口
1. `listArtifacts(flowId)`
2. `getArtifact(artifactId)`
3. `updateArtifactCatalog(flowId, patch)`

## 4. 数据结构
```ts
type ArtifactDescriptor = {
  artifactId: string;
  path: string;
  kind: 'markdown' | 'table' | 'diagram' | 'json' | 'folder';
  stageOwner?: string;
};
```

## 5. 实现要求
1. 工件目录必须支持文件和目录两级对象。
2. 路径、类型、阶段归属都要结构化。
3. 导出层不得绕过工件目录自行拼文件列表。

## 6. 自动测试
1. 工件目录新增与删除。
2. 工件改名后节点 IO 引用刷新。
3. 导出映射读取工件目录。

## 7. 不允许的错误实现
1. 工件目录只是 UI 列表，不进入运行时。
2. 节点 IO 和导出映射各自维护一份工件清单。
3. 工件删除后引用不失效。

## 8. 当前审计结论
- 审计状态：部分完成
- 审计说明：工件目录服务仍缺统一引用刷新和跨层共享的主链路。
