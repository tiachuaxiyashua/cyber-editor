# F-040 外部变更检测与冲突处理

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：文档编辑与知识关系 / 保存链路 / 冲突
- MSABC 分类：A
- 当前状态：已完成
- 关联页面：[文件树与文档区](../../01-UI详细设计/04-文件树与文档区.md)
- 共享实现基线：[文档编辑与知识关系](README.md)

## 2. 完成定义
- 当当前打开文档被外部程序修改时，工作台必须检测到。
- 如果本地无未保存修改，可直接提示用户是否刷新。
- 如果本地有未保存修改，必须弹冲突对话框，提供清晰选择。

## 3. 页面入口与层级
- 页面：`P2 文件树与文档区`
- 触发方式：文件系统监控被动触发
- 弹层层级：`P4 冲突对话框`

## 4. 用户操作与系统反馈
1. 用户打开文档并进行编辑。
2. 外部程序改写同一文件。
3. 系统检测变化：
   - 文档头部显示冲突提示条。
   - 弹出冲突对话框。
4. 用户可选择：
   - `重新加载外部版本`
   - `保留当前草稿并覆盖外部版本`
   - `稍后处理`
5. 选择 `稍后处理`：
   - 文档继续显示冲突标识。
   - 阶段确认等高风险动作应被 guard 阻断。

## 5. 数据与状态
- `externalVersionHash`
- `localDraftHash`
- `conflictStatus`
- `conflictResolutionChoice`

## 6. 实现要求
### Renderer
- 冲突对话框必须 portal 到应用根层，避免被画布或侧栏遮挡。
- 对话框文案必须直接告诉用户“会丢什么”。

### Main / Service
- 文件监控在主进程。
- 对比逻辑在文档服务或比较服务。

## 7. 校验与异常
- 外部变化是图片、导图资源时，只刷新资源预览，不弹正文冲突框。
- 同一文档冲突未处理前，自动保存暂停。

## 8. 自动测试
- e2e：
  - 外部改文件后出现冲突对话框。
  - 选择重新加载，正文刷新。
  - 选择保留当前草稿并覆盖，落盘后以当前草稿为准。
- unit：
  - 冲突比较逻辑。

## 9. 用户模拟测试
1. 打开文档并修改一行。
2. 用系统外部编辑器改同一文件。
3. 回到应用确认弹出冲突框。
4. 依次测试三种选择，确认结果各不相同且可预期。

## 10. 审计结论
- 审计状态：实现级文档已补齐。
- 审计备注：冲突处理不是单纯“提示一下”，而是要阻断后续误操作，这一点对另一套 AI 是强约束。
