# F-039 手动保存、自动保存与脏状态提示

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：文档编辑与知识关系 / 保存链路 / 保存
- MSABC 分类：M
- 当前状态：已完成
- 关联页面：[文件树与文档区](../../01-UI详细设计/04-文件树与文档区.md)
- 共享实现基线：[文档编辑与知识关系](README.md)

## 2. 完成定义
- 文档修改后，标签页和头部都显示脏状态。
- `Ctrl+S` 可立即手动保存。
- 自动保存按统一策略触发，但不能打断输入法和连续编辑。
- 保存成功后脏状态清除。

## 3. 页面入口与层级
- 页面：`P2 文件树与文档区`
- 主入口：
  - `Ctrl+S`
  - 文档头部保存图标
- 被动入口：
  - 自动保存策略

## 4. 用户操作与系统反馈
1. 用户修改正文。
2. 文档标签出现脏点，头部保存图标高亮。
3. 用户按 `Ctrl+S`：
   - 进入保存中状态。
   - 成功后脏点消失。
4. 若用户停顿达到自动保存阈值：
   - 系统自动保存。
   - 不弹模态。
5. 保存失败：
   - 保留脏状态。
   - 通知区显示失败原因。

## 5. 数据与状态
- `draftContent`
- `lastSavedAt`
- `isDirty`
- `isSaving`
- `saveError`

## 6. 实现要求
### Renderer
- 自动保存倒计时不可见，但保存中可在状态栏体现。
- 多标签并行编辑时，脏状态按标签独立维护。

### Main / Service
- 保存必须走统一文档服务。
- 保存成功后，如引用图或知识索引受影响，需触发刷新链路。

## 7. 校验与异常
- 保存时检测路径合法、权限、冲突。
- 失败不能清脏状态。
- 外部冲突存在时，自动保存停止，需用户先处理冲突。

## 8. 自动测试
- e2e：
  - 修改后出现脏点。
  - `Ctrl+S` 后脏点消失。
  - 自动保存后内容落盘。
- 回归：
  - 多标签各自脏状态独立。

## 9. 用户模拟测试
1. 修改文档一行文字。
2. 确认标签出现脏点。
3. 按 `Ctrl+S`。
4. 关闭并重开文档，确认内容已保存。

## 10. 审计结论
- 审计状态：实现级文档已补齐。
- 审计备注：保存链路必须与引用刷新、索引刷新保持一致，不能只写盘不刷新衍生状态。
