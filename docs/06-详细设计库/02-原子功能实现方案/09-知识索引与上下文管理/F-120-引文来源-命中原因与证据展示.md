# F-120 引文来源、命中原因与证据展示

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：文档知识底座与上下文管理 / 检索 / 来源
- MSABC 分类：A
- 当前状态：部分完成

## 2. 当前代码事实

当前主链路已经存在：

1. `src/main/services/provenance-service.ts`
   - 将 retrieval hits、上下文文档、固定文档、滚动摘要、继续运行、规则和已提升知识转换为 `ProvenanceRecord[]`。
   - 同时生成兼容旧字段的 provenance token。
2. `RuntimeService.buildHarnessPrompt()`
   - 在构造 prompt 时生成 `provenanceRecords`。
3. `RuntimeService.buildContextPack()`
   - 将 `retrievalHits`、`provenanceRecords`、`knowledgeIndexBuiltAt` 和 `budgetPlan` 写入 context pack。
4. `AppShellSections.ContextPane`
   - 展示“命中原因”和“来源证据”。
   - 支持打开来源文档。

## 3. 用户路径

1. 用户发送 AI 消息或运行 Flow。
2. 运行时构造 context pack。
3. 每个检索命中生成可读 reason。
4. Provenance service 生成来源证据。
5. 右侧上下文面板展示：
   - 命中文档标题
   - 命中原因
   - score
   - matchedBy 标签
   - 来源证据记录
   - 打开原文按钮

## 4. Provenance 类型

| `kind` | 来源 | 含义 |
|---|---|---|
| `conversation-summary` | 会话压缩 | 滚动摘要进入上下文 |
| `context-document` | 固定或显式上下文文档 | 用户或系统选入的原文 |
| `knowledge-hit` | 混合检索结果 | 召回命中 |
| `recent-change` | 最近文档变更或运行来源 | 与上下文相关的变更证据 |
| `run-resume` | 恢复运行 | 继续上一次运行 |
| `effective-rule` | 规则沉淀 | 生效规则 |
| `promoted-knowledge` | 知识提升 | 已接受的知识节点 |

## 5. 当前差距

1. 来源证据可以打开源文档，但尚未精确到行号或段落位置。
2. 证据已进入 context pack，但还没有独立导出为审计报告的 UI 动作。
3. 打包态专项证据尚未单独记录，因此状态保持为“部分完成”。

## 7. 不允许的错误实现

1. 不允许 AI 输出中出现引用但 context pack 没有来源证据。
2. 不允许只保存字符串 token 而丢失结构化 provenance。
3. 不允许 UI 只显示文件名，不显示命中原因。
