# F-118 关键词、语义与引用扩展混合检索

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：文档知识底座与上下文管理 / 检索 / 混合检索
- MSABC 分类：S
- 当前状态：部分完成

## 2. 当前代码事实

当前主链路由 `src/main/services/hybrid-retrieval-service.ts` 承接：

1. 每次检索先调用 `KnowledgeIndexService.refresh(rootPath, 'incremental')`，保证索引可用。
2. 查询文本被分词为 token。
3. 检索包含三路召回：
   - `keyword`：标题、摘要和关键词直接命中。
   - `semantic`：基于 token overlap 的轻量语义重叠分数。
   - `reference`：固定上下文和引用关系扩展。
4. 结果按 score 排序，返回 `RetrievalHit[]`。
5. 每条命中包含 `matchedBy[]`、`reason`、`score`、`relatedChangeRecordIds[]`。

## 3. 用户路径

1. 用户在 AI 会话中发送消息，或编排运行时构造角色 prompt。
2. `RuntimeService.buildHarnessPrompt()` 调用 hybrid retrieval。
3. 检索命中写入 context pack。
4. 右侧上下文面板显示：
   - 命中文档
   - 命中原因
   - score
   - matchedBy 标签
   - 关联最近变更数量
5. 用户可打开来源、固定或排除命中文档。

## 4. 数据契约

| 字段 | 含义 |
|---|---|
| `unitId` | 知识索引单元 ID |
| `path` | 命中文档路径 |
| `title` | 文档标题 |
| `excerpt` | 摘要 |
| `score` | 综合分数 |
| `matchedBy[]` | `keyword / semantic / reference` |
| `reason` | 用户可读命中原因 |
| `relatedChangeRecordIds[]` | 与该文档相关的最近变更 |
| `pinned` | 是否由用户固定上下文强制加入 |

## 5. 当前差距

1. 当前 `semantic` 是轻量 token overlap，不是向量 embedding 语义检索。
2. 召回结果已进入 context pack 和 UI，但尚未提供独立“检索中心”页面。
3. 打包态专项证据尚未单独记录，因此状态保持为“部分完成”。

## 7. 不允许的错误实现

1. 不允许只做全文字符串扫描却标记为混合检索。
2. 不允许命中结果没有 `matchedBy` 和 `reason`。
3. 不允许把被用户排除的文档重新加入 context pack。
