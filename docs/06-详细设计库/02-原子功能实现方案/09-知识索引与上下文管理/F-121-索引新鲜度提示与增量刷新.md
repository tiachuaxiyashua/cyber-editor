# F-121 索引新鲜度提示与增量刷新

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：文档知识底座与上下文管理 / 索引 / 新鲜度
- MSABC 分类：A
- 当前状态：部分完成

## 2. 当前代码事实

当前主链路已经存在：

1. `KnowledgeIndexService.getStatus()`
   - 对比当前工程知识文件与持久化索引单元。
   - 文档新增、删除、修改时间晚于索引时间时进入 `stale`。
2. `KnowledgeIndexService.refresh(rootPath, 'incremental')`
   - 只重建 stale 文档。
   - 未过期文档复用已有 unit。
3. `HybridRetrievalService.retrieve()`
   - 每次检索前执行 incremental refresh。
4. `ContextPane`
   - 显示 `staleDocumentPaths` 的前若干项。
   - 提供手动刷新按钮。

## 3. 用户路径

1. 用户打开工程并完成一次索引或 AI 运行。
2. 用户或外部工具修改工程文档。
3. 用户刷新工作台或触发 bootstrap。
4. `knowledgeIndexState.status` 变为 `stale`。
5. 右侧面板展示过期文档标签。
6. 用户点击“刷新索引”。
7. 主进程执行 manual refresh；检索路径执行 incremental refresh。
8. 状态恢复 ready。

## 4. 判定规则

| 情况 | 状态 |
|---|---|
| 没有索引文件 | `missing` |
| 有 `lastError` | `error` |
| 当前文件不存在对应 unit | `stale` |
| 当前文件 `modifiedAt > unit.modifiedAt` | `stale` |
| unit 指向的文件已删除 | `stale` |
| 无错误且无 stale 文档 | `ready` |

## 5. 当前差距

1. 已有 stale 判定和增量刷新，但文件 watcher 事件尚未直接驱动索引状态实时变化。
2. 刷新失败不会覆盖旧索引的目标已经在设计中固定，但 UI 恢复入口仍需补强。
3. 打包态专项证据尚未单独记录，因此状态保持为“部分完成”。

## 7. 不允许的错误实现

1. 不允许文档修改后仍显示 ready。
2. 不允许增量刷新失败后清空旧索引。
3. 不允许用户看不见哪些文档导致 stale。
