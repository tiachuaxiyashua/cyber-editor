# F-122 模板来源、版本、信任与兼容性展示

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：平台入口与模板 / 模板中心 / 元数据
- MSABC 分类：A
- 当前状态：未完成
- 关联页面：[新建工程与模板中心](../../01-UI详细设计/02-新建工程与模板中心.md)、[欢迎页](../../01-UI详细设计/01-欢迎页.md)
- 上游需求：`D-A2`、`D-C2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 模板是平台资产，用户在使用前必须知道其来源、版本、可信度和兼容性。
2. 没有这些元数据，模板中心会退化成无法判断风险的文件列表。
3. 模板元数据必须直接服务于“能不能用”和“值不值得信任”两个决策。

### 2.2 完成定义
1. 模板列表项显示来源和健康摘要。
2. 模板详情区显示：
   - 来源
   - 当前版本
   - 最低兼容版本
   - 信任状态
   - 更新时间
3. 不兼容或损坏模板不允许被用于创建工程或直接开始编排。
4. 未验证模板要显式显示风险提示。

## 3. 页面入口与层级
1. 入口页面：
   - 欢迎页最近模板区域
   - 新建工程与模板中心
2. 层级：
   - `P1 欢迎页/模板中心`
   - `P2 模板列表`
   - `P3 模板详情`

## 4. 用户操作流程
1. 用户进入模板中心。
2. 选择一个模板。
3. 右侧详情区查看元数据。
4. 若模板状态允许，再点击：
   - 创建工程
   - 直接开始编排
5. 若模板状态不允许，系统只显示原因与修复入口。

## 5. 可见效果与状态
1. 列表卡片或列表项必须显示来源徽标：
   - 内置
   - 本地导入
   - 远程下载
2. 详情区必须显示状态徽章：
   - 已信任
   - 未验证
   - 不兼容
   - 损坏
3. 高风险模板用警示色，但不能把整个模板卡片做成报错样式。

## 6. 数据模型
```json
{
  "templateId": "software-factory",
  "source": "builtin",
  "version": "1.4.0",
  "minAppVersion": "0.2.0",
  "trustLevel": "trusted",
  "health": "healthy",
  "updatedAt": "2026-04-09T10:00:00Z"
}
```

## 7. 具体实现方案
### 7.1 Renderer
组件：
1. `TemplateSourceBadge`
2. `TemplateStatusBadge`
3. `TemplateMetadataPanel`

Renderer 责任：
1. 统一来源、信任和兼容性视觉语义。
2. 在模板列表和详情区共用同一套枚举映射，不允许两套文案。

### 7.2 Main / Service
服务：
1. `template-registry`
2. `template-metadata-trust-resolver`

Main 责任：
1. 解析模板 manifest。
2. 计算兼容性和信任状态。
3. 向 Renderer 返回统一的模板元数据对象。

## 8. 校验与阻断
1. 模板缺少版本号时，默认视为“未验证”而不是“正常”。
2. 模板最低兼容版本高于当前应用版本时，创建入口禁用。
3. 损坏模板的主 CTA 全部替换为修复动作。

## 9. 自动测试
### 9.1 单元
1. 版本兼容计算
2. 信任状态映射
3. 来源映射

### 9.2 端到端
1. 打开模板中心查看内置模板元数据。
2. 导入未验证模板，确认状态为“未验证”。
3. 导入不兼容模板，确认创建入口禁用。

## 10. 用户模拟测试
1. 进入模板中心。
2. 分别点击一个内置模板和一个本地导入模板。
3. 确认详情区能区分来源、版本、信任状态。
4. 对不兼容模板尝试创建，确认被阻止。

## 11. 不允许的错误实现
1. 模板中心只显示名字，没有元数据。
2. 信任状态只写在日志里，不在 UI 中显示。
3. 不兼容模板仍允许直接使用。
