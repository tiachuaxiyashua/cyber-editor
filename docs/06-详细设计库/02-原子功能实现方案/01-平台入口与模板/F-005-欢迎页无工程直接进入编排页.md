# F-005 欢迎页无工程直接进入编排页

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：平台入口与模板 / 双主入口 / 开始编排
- MSABC 分类：S
- 当前状态：未完成
- 关联页面：[欢迎页](../../01-UI详细设计/01-欢迎页.md)、[无工程编排模式](../../01-UI详细设计/10-无工程编排模式.md)、[编排页](../../01-UI详细设计/07-编排页.md)
- 上游需求：`D-C2`、`D-N3`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 小白用户不需要先理解“工程目录”是什么，也能先拿现成流程开始组织想法。
2. 高手用户可以先设计 Flow、Subflow、角色和工件，再决定是否绑定工程。
3. 这条路径是 Cyber Editor 与“普通文档编辑器”最大的差异之一，不能只是隐藏入口。

### 2.2 完成定义
以下条件同时成立才算完成：
1. 欢迎页首屏存在与“新建工程”同级的 `开始编排` 主按钮。
2. 点击后进入无工程编排模式，而不是创建一个临时工程。
3. 无工程编排模式打开后能立刻创建草稿 Flow，并显示草稿状态。
4. 用户后续可以：
   - 保存草稿
   - 导出 Flow 包
   - 保存为模板
   - 绑定工程
5. 返回欢迎页后，该草稿会进入最近编排列表。

## 3. 页面入口与层级
1. 入口页面：欢迎页 `P0`
2. 打开方式：点击欢迎页主操作按钮 `开始编排`
3. 目标页面：无工程编排模式 `P1`
4. 页面替换范围：替换欢迎页主内容区，保留应用顶层壳
5. 返回目标：
   - 用户主动返回：回到欢迎页
   - 用户绑定工程成功：进入主工作台
6. 状态保留：
   - 若草稿已保存，返回欢迎页后必须保留最近编排卡片
   - 若草稿未保存，返回时必须弹出离开确认

## 4. 用户操作流程
### 4.1 小白路径
1. 用户启动应用，看到欢迎页。
2. 用户在首屏主要操作区看到两个并列按钮：
   - `新建工程`
   - `开始编排`
3. 用户点击 `开始编排`。
4. 系统立即进入无工程编排模式，并创建一个默认空白草稿：
   - 默认名称：`未命名流程草稿`
   - 默认状态：`未保存`
5. 画布出现默认起点节点和空白工件区。

### 4.2 高手路径
1. 用户从欢迎页点击 `开始编排`。
2. 用户直接在无工程编排模式中创建或导入 Flow。
3. 用户在后续任意时刻点击：
   - `保存为模板`
   - `绑定工程`
   - `导出 Flow 包`

## 5. 可见效果与状态
### 5.1 欢迎页状态
1. 默认态：
   - `开始编排` 作为首层主动作
   - 文案必须说明“无需先创建工程”
2. Hover 态：
   - 显示简短说明：`先搭流程，再决定是否绑定工程`
3. 禁用态：
   - 只有在应用尚未完成基础启动时才允许短暂禁用

### 5.2 无工程编排模式状态
1. 顶部状态必须显示：
   - `无工程编排`
   - `草稿`
   - `未保存/已保存`
2. 首次进入时不能显示“工程路径”“工程文件树”等工程专属信息。
3. 页面必须提供显式动作：
   - 保存草稿
   - 保存为模板
   - 绑定工程
   - 导出 Flow 包

## 6. 数据模型
### 6.1 最近编排草稿
```json
{
  "draftId": "draft_001",
  "title": "未命名流程草稿",
  "updatedAt": "2026-04-09T12:00:00Z",
  "sourceTemplateId": null,
  "hasBoundProject": false,
  "storagePath": "workspace/drafts/draft_001.flow.json"
}
```

### 6.2 无工程编排会话状态
```json
{
  "mode": "orchestration-draft",
  "draftId": "draft_001",
  "projectId": null,
  "dirty": true
}
```

## 7. 具体实现方案
### 7.1 Renderer
建议至少拆出以下模块：
1. `WelcomePage`
2. `StartOrchestrationButton`
3. `OrchestrationDraftShell`

Renderer 责任：
1. 在欢迎页首屏渲染并列主按钮。
2. 触发 `startOrchestrationDraft` IPC。
3. 成功后切换到无工程编排模式页面。
4. 显示草稿状态和离开确认。

### 7.2 Main / Service
建议服务：
1. `draft-registry-service`
2. `flow-asset-persistence-service`
3. `recent-entries-service`

Main 责任：
1. 创建新的 draft 记录。
2. 初始化空白 Flow 文件。
3. 更新最近编排列表。
4. 处理草稿恢复、删除、绑定工程。

### 7.3 IPC 契约
#### `orchestration:start-draft`
输入：
```json
{
  "sourceTemplateId": null
}
```
输出：
```json
{
  "draftId": "draft_001",
  "flowPath": "workspace/drafts/draft_001.flow.json",
  "mode": "orchestration-draft"
}
```

## 8. 校验与阻断
1. 草稿创建失败时，不允许切入无工程编排模式空壳页。
2. 若最近编排记录指向的草稿文件不存在，欢迎页最近编排项必须显示损坏状态，并允许移除。
3. 无工程编排模式中，若用户直接关闭页面且有未保存更改，必须弹确认。

## 9. 自动测试
### 9.1 单元
1. 草稿记录创建
2. 最近编排写入
3. 无工程状态切换

### 9.2 端到端
1. 从欢迎页点击 `开始编排`
2. 验证进入无工程编排模式
3. 验证首个草稿已创建
4. 返回欢迎页，验证最近编排可见

### 9.3 回归
1. 首次启动
2. 第二次启动恢复最近草稿
3. 草稿文件损坏
4. 绑定工程后从最近编排列表消失或迁移到最近工程逻辑

## 10. 用户模拟测试
1. 启动应用。
2. 不创建工程，直接点 `开始编排`。
3. 观察是否进入无工程编排模式，而不是跳出目录选择器。
4. 在画布上增加一个节点。
5. 返回欢迎页。
6. 确认最近编排列表出现刚才的草稿。

## 11. 不允许的错误实现
1. 把“开始编排”藏到更多菜单或命令面板里。
2. 点击“开始编排”后偷偷创建一个伪工程目录。
3. 无工程编排模式仍然显示工程文件树或工程路径。
4. 草稿不进最近编排，只能靠隐藏文件恢复。
