# F-005 欢迎页无工程直接进入编排页

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：平台入口与模板 / 双主入口 / 开始编排
- MSABC 分类：S
- 当前状态：部分完成
- 关联页面：[欢迎页](../../01-UI详细设计/01-欢迎页.md)、[无工程编排模式](../../01-UI详细设计/10-无工程编排模式.md)、[编排页](../../01-UI详细设计/07-编排页.md)
- 上游需求：`D-C2`、`D-N3`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 小白用户不需要先理解“工程目录”是什么，也能先拿现成流程开始组织想法。
2. 高手用户可以先设计 Flow、Subflow、角色和工件，再决定是否绑定工程。
3. 这条路径是 Cyber Editor 与“普通文档编辑器”最大的差异之一，不能只是隐藏入口。

### 2.2 完成定义
以下条件同时成立才算完成：
1. 欢迎页首屏存在与“新建工程”同级的 `开始编排` 主按钮。
2. 点击后进入无工程编排模式，而不是创建一个临时工程。
3. 无工程编排模式打开后能立刻创建草稿 Flow，并显示草稿状态。
4. 用户后续可以：
   - 保存草稿
   - 导出 Flow 包
   - 保存为模板
   - 绑定工程
5. 返回欢迎页后，该草稿会进入最近编排列表。

## 3. 页面入口与层级
1. 入口页面：欢迎页 `P0`
2. 打开方式：点击欢迎页主操作按钮 `开始编排`
3. 目标页面：无工程编排模式 `P1`
4. 页面替换范围：替换欢迎页主内容区，保留应用顶层壳
5. 返回目标：
   - 用户主动返回：回到欢迎页
   - 用户绑定工程成功：进入主工作台
6. 状态保留：
   - 若草稿已保存，返回欢迎页后必须保留最近编排卡片
   - 若草稿未保存，返回时必须弹出离开确认

## 4. 用户操作流程
### 4.1 小白路径
1. 用户启动应用，看到欢迎页。
2. 用户在首屏主要操作区看到两个并列按钮：
   - `新建工程`
   - `开始编排`
3. 用户点击 `开始编排`。
4. 系统立即进入无工程编排模式，并创建一个默认空白草稿：
   - 默认名称：`未命名流程草稿`
   - 默认状态：`未保存`
5. 画布出现默认起点节点和空白工件区。

### 4.2 高手路径
1. 用户从欢迎页点击 `开始编排`。
2. 用户直接在无工程编排模式中创建或导入 Flow。
3. 用户在后续任意时刻点击：
   - `保存为模板`
   - `绑定工程`
   - `导出 Flow 包`

## 5. 可见效果与状态
### 5.1 欢迎页状态
1. 默认态：
   - `开始编排` 作为首层主动作
   - 文案必须说明“无需先创建工程”
2. Hover 态：
   - 显示简短说明：`先搭流程，再决定是否绑定工程`
3. 禁用态：
   - 只有在应用尚未完成基础启动时才允许短暂禁用

### 5.2 无工程编排模式状态
1. 顶部状态必须显示：
   - `无工程编排`
   - `草稿`
   - `未保存/已保存`
2. 首次进入时不能显示“工程路径”“工程文件树”等工程专属信息。
3. 页面必须提供显式动作：
   - 保存草稿
   - 保存为模板
   - 绑定工程
   - 导出 Flow 包

## 6. 数据模型
### 6.1 最近编排草稿

```json
{
  "draftId": "draft_001",
  "title": "未命名流程草稿",
  "updatedAt": "2026-04-09T12:00:00Z",
  "sourceTemplateId": null,
  "hasBoundProject": false,
  "storagePath": "workspace/drafts/draft_001.flow.json"

```

### 6.2 无工程编排会话状态
```json
{
  "mode": "orchestration-draft",
  "draftId": "draft_001",
  "projectId": null,
  "dirty": true
}
```

## 7. 具体实现方案
### 7.1 当前 Renderer owner
当前实现未拆出独立 `OrchestrationDraftShell`，真实 owner 是：

1. `src/renderer/App.tsx`
   - 欢迎页 `开始编排` 入口。
   - 无工程 `draftPlatform`、`draftRuntimeTemplate`、`draftFlowHistories`、`draftSnapshotId` 状态。
   - 草稿自动保存、返回欢迎页、继续编排、保存到本地模板、绑定工程。
2. `src/renderer/components/OrchestrationWorkspace.tsx`
   - 无工程模式复用正式编排页，而不是临时预览页。
3. `src/renderer/components/ProjectTemplateDialog.tsx` 与 `SaveTemplateDialog.tsx`
   - 承接绑定工程和保存模板动作。

### 7.2 当前 Main / Service owner
当前真实 owner 是：

1. `src/main/ipc/register-resource-ipc.ts`
   - `drafts:save`
   - `drafts:get`
   - `drafts:remove`
2. `src/main/services/store.ts`
   - `saveDraftSnapshot()`
   - `getDraftSnapshot()`
   - `removeDraftSnapshot()`
   - `recentDrafts` 最近编排列表。
3. `src/main/services/template-registry-service.ts`
   - 草稿保存为本地模板后的注册表更新。
4. `src/main/services/project-service.ts`
   - 绑定工程时按草稿模板包初始化工程。

### 7.3 当前 IPC 契约
无工程草稿当前不是通过 `orchestration:start-draft` 创建，而是由 Renderer 基于内置/模板资产组装草稿状态，再通过以下 IPC 持久化：

| IPC | 输入 | 输出 |
|---|---|---|
| `drafts:save` | `DraftOrchestrationSnapshot` | `AppSettings` |
| `drafts:get` | `id` | `DraftOrchestrationSnapshot \| null` |
| `drafts:remove` | `id` | `AppSettings` |

## 8. 校验与阻断
1. 草稿创建失败时，不允许切入无工程编排模式空壳页。
2. 若最近编排记录指向的草稿文件不存在，欢迎页最近编排项必须显示损坏状态，并允许移除。
3. 无工程编排模式中，若用户直接关闭页面且有未保存更改，必须弹确认。

## 9. 自动测试
### 9.1 单元
1. 草稿记录创建
2. 最近编排写入
3. 无工程状态切换

### 9.2 端到端
1. 从欢迎页点击 `开始编排`
2. 验证进入无工程编排模式
3. 验证首个草稿已创建
4. 返回欢迎页，验证最近编排可见

### 9.3 回归
1. 首次启动
2. 第二次启动恢复最近草稿
3. 草稿文件损坏
4. 绑定工程后从最近编排列表消失或迁移到最近工程逻辑

## 10. 用户模拟测试
1. 启动应用。
2. 不创建工程，直接点 `开始编排`。
3. 观察是否进入无工程编排模式，而不是跳出目录选择器。
4. 在画布上增加一个节点。
5. 返回欢迎页。
6. 确认最近编排列表出现刚才的草稿。

## 11. 不允许的错误实现
1. 把“开始编排”藏到更多菜单或命令面板里。
2. 点击“开始编排”后偷偷创建一个伪工程目录。
3. 无工程编排模式仍然显示工程文件树或工程路径。
4. 草稿不进最近编排，只能靠隐藏文件恢复。

## 12. 当前审计结论
- 审计状态：部分完成
- 已有闭环：欢迎页 `开始编排` 可进入正式编排页；草稿可自动保存并进入最近编排；最近编排可继续；草稿可保存为本地模板；草稿可绑定为工程；草稿 Flow 可导出 JSON。`tests/e2e/platform-mvp.spec.ts` 已覆盖欢迎页进入、最近草稿继续、保存模板和绑定工程主路径。
- 剩余缺口：草稿模式暂不支持导入 Flow；草稿损坏恢复只具备可用性过滤，缺少显式修复/另存/删除 UI 闭环；无工程导出 Flow 包缺少打包态专项证据；离开未保存草稿的确认和最近编排异常态仍需补强。
