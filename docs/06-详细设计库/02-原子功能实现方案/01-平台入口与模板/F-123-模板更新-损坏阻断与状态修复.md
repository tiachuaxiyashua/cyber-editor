# F-123 模板更新、损坏阻断与状态修复

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：平台入口与模板 / 模板中心 / 生命周期
- MSABC 分类：A
- 当前状态：未完成
- 关联页面：[新建工程与模板中心](../../01-UI详细设计/02-新建工程与模板中心.md)
- 上游需求：`D-A2`、`D-C2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 模板可能损坏、过旧、缺文件或需要更新，平台必须提前拦截而不是等用户点进去后报错。
2. 用户需要明确的修复路径，而不是一条无法行动的错误提示。

### 2.2 完成定义
1. 模板支持生命周期状态：
   - 正常
   - 可更新
   - 损坏
   - 不兼容
2. 损坏模板和不兼容模板被阻断使用。
3. 可更新模板提供更新入口。
4. 损坏模板提供重新导入、重新下载或移除入口。

## 3. 页面入口与层级
1. 入口页面：模板中心
2. 层级：
   - `P2 模板列表`
   - `P3 模板详情`
   - `P4 修复确认对话框`

## 4. 用户操作流程
1. 用户打开模板中心。
2. 看到某模板状态为“可更新”或“损坏”。
3. 点进模板详情。
4. 系统提供对应动作：
   - 更新模板
   - 重新导入
   - 重新下载
   - 移除模板
5. 执行完成后状态刷新。

## 5. 可见效果与状态
1. “损坏”模板必须禁用主要 CTA。
2. “可更新”模板保留主要 CTA，但显式提示有新版本。
3. “不兼容”模板显示阻断信息和兼容版本要求。

## 6. 数据模型
```json
{
  "templateId": "video-script-lab",
  "health": "broken",
  "repairActions": ["reimport", "remove"],
  "updateAvailable": false
}
```

## 7. 具体实现方案
### 7.1 Renderer
组件：
1. `TemplateLifecycleActions`
2. `TemplateRepairDialog`

Renderer 责任：
1. 依据生命周期状态渲染不同操作区。
2. 在执行修复动作期间锁定重复点击。

### 7.2 Main / Service
服务：
1. `template-registry`
2. `template-metadata-trust-resolver`

Main 责任：
1. 启动时做模板完整性快检。
2. 支持更新、重新导入和移除动作。
3. 刷新生命周期状态。

## 8. 校验与阻断
1. 缺少关键文件视为损坏。
2. 更新失败时保留旧版本，不允许把模板变成半更新状态。
3. 修复动作失败必须可重试。

## 9. 自动测试
### 9.1 单元
1. 完整性检测
2. 生命周期状态转换
3. 修复动作结果映射

### 9.2 端到端
1. 伪造损坏模板，确认创建入口被禁用。
2. 对可更新模板执行更新，确认状态刷新。
3. 对损坏模板执行移除，确认列表更新。

## 10. 用户模拟测试
1. 人为删除模板关键文件。
2. 重新进入模板中心，确认模板进入损坏态。
3. 尝试直接创建，确认系统阻止。
4. 执行重新导入，确认状态恢复。

## 11. 不允许的错误实现
1. 损坏模板仍然允许直接创建工程。
2. 更新动作覆盖旧模板后失败，导致模板彻底不可用。
3. 修复动作只有删除，没有恢复路径。
