# F-011 模板中心入口与返回路径

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：平台入口与模板 / 模板中心 / 入口
- MSABC 分类：A
- 当前状态：部分完成
- 关联页面：[欢迎页](../../01-UI详细设计/01-欢迎页.md)、[新建工程与模板中心](../../01-UI详细设计/02-新建工程与模板中心.md)、[无工程编排模式](../../01-UI详细设计/10-无工程编排模式.md)
- 上游需求：`D-A1`、`D-A2`

## 2. 用户价值与完成定义
### 2.1 用户价值
1. 模板中心是双主路径的公共资产入口，不能藏在难以发现的位置。
2. 用户必须清楚自己是“从欢迎页进入模板中心”还是“在新建工程流程中进入模板中心”。

### 2.2 完成定义
1. 模板中心至少有三条显式入口：
   - 欢迎页
   - 新建工程页
   - 无工程编排模式
2. 每条入口都有清晰返回路径。
3. 进入模板中心时，来源上下文被保留。

## 3. 页面入口与层级
1. 欢迎页 -> 模板中心
2. 新建工程页 -> 模板中心
3. 无工程编排模式 -> 模板中心

返回规则：
1. 从欢迎页进入，返回欢迎页。
2. 从新建工程页进入，返回新建工程页并保留已填信息。
3. 从无工程编排进入，返回无工程编排页并保留当前草稿。

## 4. 用户操作流程
1. 用户在任一入口点击“模板中心”。
2. 系统记录 `entrySource`。
3. 用户浏览模板。
4. 用户选择：
   - 创建工程
   - 直接开始编排
   - 返回
5. 返回时恢复来源页状态。

## 5. 可见效果与状态
1. 模板中心顶部显示当前上下文，例如：
   - “从欢迎页进入”
   - “从新建工程进入”
2. 返回按钮文案随来源变化：
   - 返回欢迎页
   - 返回新建工程
   - 返回当前编排草稿

## 6. 数据模型
```json
{
  "entrySource": "new-project",
  "returnState": {
    "projectName": "视频脚本整理",
    "targetDirectory": "E:/workspace"
  }
}
```

## 7. 具体实现方案
### 7.1 Renderer
组件：
1. `TemplateCenterEntryLink`
2. `TemplateCenterHeader`
3. `TemplateCenterBackAction`

Renderer 责任：
1. 把入口来源写入路由状态。
2. 返回时恢复来源页的临时状态。

### 7.2 Main / Service
服务：
1. `recent-project-template-store`

Main 责任：
1. 不需要直接参与路由，但要支持模板中心读取最近模板和模板元数据。

## 8. 校验与阻断
1. 不允许模板中心成为单向死胡同。
2. 不允许从新建工程页进入模板中心后丢失已填表单。

## 9. 自动测试
### 9.1 端到端
1. 从欢迎页进入模板中心再返回。
2. 从新建工程页进入模板中心再返回，确认表单仍在。
3. 从无工程编排模式进入模板中心再返回，确认草稿仍在。

## 10. 用户模拟测试
1. 从欢迎页进入模板中心并返回。
2. 在新建工程中填一半数据后进入模板中心再返回。
3. 确认前一页状态不丢。

## 11. 不允许的错误实现
1. 模板中心只有一个固定入口。
2. 返回路径全部回欢迎页。
3. 进入模板中心后来源上下文丢失。

## 12. 当前审计结论
- 审计状态：部分完成
- 审计说明：模板中心当前仍缺少统一入口语义和严格的返回路径恢复规则。
