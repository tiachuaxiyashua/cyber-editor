# F-052 红蓝裁判审查子流程

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：AI会话与阶段控制 / 过程可视化 / 审查
- MSABC 分类：S
- 当前状态：部分完成
- 关联页面：[流程面板](../../01-UI详细设计/06-流程面板.md)、[AI会话栏](../../01-UI详细设计/05-AI会话栏.md)
- 共享实现基线：[AI会话与阶段控制](README.md)

## 2. 完成定义
- 红蓝裁判必须是一个可见的子流程，不是一次黑盒调用。
- 至少包含三个角色节点：
  - 蓝军
  - 红军
  - 裁判
- 子流程运行后至少产出：
  - `blue-draft`
  - `red-issues`
  - `judge-summary`

## 3. 页面入口与层级
- 页面：`P3 流程面板`
- 主入口：阶段动作区 `启动审查`
- 深层入口：编排页中的审查子流程节点

## 4. 用户操作与系统反馈
1. 用户点击启动审查。
2. 流程面板出现红蓝裁判进度块。
3. 依次显示：
   - 蓝军完成
   - 红军完成
   - 裁判完成
4. 裁判结论若要求继续审查，流程面板显示“再来一轮”。

## 5. 数据与状态
- `reviewRounds[]`
- `blueOutputRef`
- `redIssueRef`
- `judgeSummaryRef`
- `continueReviewSignal`

## 6. 实现要求
### Renderer
- 每一轮审查必须可折叠展开。
- 用户能从每轮结果直接打开对应工件。

### Main / Service
- 审查引擎负责三角色顺序执行和循环控制。
- 角色之间通过工件/消息/信号通信，不允许直接拼一段大 prompt 黑箱处理。

## 7. 校验与异常
- 任一角色失败时整轮标记失败，不写成功结论。
- 当前状态为“部分完成”，表示存在主路径，但轮次控制、工件化和信号化仍未全部收口。

## 8. 自动测试
- e2e：
  - 启动审查后出现三角色过程。
  - 审查工件可打开。
- unit：
  - 轮次控制与继续审查信号。

## 9. 用户模拟测试
1. 在某阶段启动审查。
2. 确认过程依次显示蓝军、红军、裁判。
3. 打开三份输出工件查看内容。

- 审计状态：实现级文档已补齐，功能本身仍部分完成。
