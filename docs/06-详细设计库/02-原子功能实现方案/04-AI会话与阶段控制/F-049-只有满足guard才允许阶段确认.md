# F-049 只有满足 guard 才允许阶段确认

## 1. 基本信息
- 类型：用户可见功能
- 所属层级：AI会话与阶段控制 / 阶段控制 / 确认
- MSABC 分类：S
- 当前状态：未完成
- 关联页面：[流程面板](../../04-UI设计/06-流程面板.md)
- 共享实现基线：[AI会话与阶段控制](README.md)

## 2. 完成定义
- 阶段确认按钮只有在以下条件同时满足时才可点击：
  - 当前阶段必需工件存在
  - guard 无阻塞项
  - 当前没有运行中的关键任务
  - 审查问题中不存在未处理 blocker
- 任一条件不满足时，按钮禁用并展示明确原因。

## 3. 页面入口与层级
- 页面：`P3 流程面板`
- 主入口：阶段卡底部 `确认本阶段`

## 4. 用户操作与系统反馈
1. 用户查看当前阶段。
2. 当 guard 未满足时：
   - 按钮禁用。
   - 按钮旁或上方显示阻断原因摘要。
3. 全部满足后：
   - 按钮进入可用态。
4. 点击确认：
   - 弹轻确认层，说明即将推进到下一阶段。
   - 确认后更新阶段状态。

## 5. 数据与状态
- `canConfirmStage`
- `blockingReasons[]`
- `requiredArtifactsSatisfied`
- `runningCriticalTask`
- `reviewBlockersOpen`

## 6. 实现要求
### Renderer
- 禁用态不能只变灰，必须可见阻断原因入口。
- 轻确认层不是可跳过 guard 的后门，只在已满足时出现。

### Main / Service
- 最终确认权在主进程 guard engine。
- Renderer 不能自行判断为可确认后就直接推进状态。

## 7. 校验与异常
- 即使用户通过快捷键触发确认，也必须再次走主进程校验。
- 当前状态为“未完成”，表示现有实现还没有把所有边界条件都真正接入确认门禁。
