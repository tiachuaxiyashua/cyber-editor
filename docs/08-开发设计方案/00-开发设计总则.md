# 00 开发设计总则

## 1. 这层文档解决什么问题
这层文档只回答“程序员应该如何落代码”，不再讨论产品价值，也不再逐条重复原子功能定义。

它负责固定：
1. 页面和模块如何拆分
2. Renderer / Main / Service 如何分工
3. 状态存放在哪里
4. IPC 如何组织
5. 开发顺序如何安排
6. 哪些实现方式允许，哪些不允许

## 2. 阅读前提
实现任何模块前，必须先阅读：
1. [01-需求.md](../01-需求.md)
2. [02-功能树.md](../02-功能树.md)
3. [03-功能清单.md](../03-功能清单.md)
4. 对应页面 UI 文档
5. 对应原子功能文档
6. 对应代码唯一性文档

## 3. 与其他层的关系
- `05-功能具体实现方案` 回答“这个原子功能是什么”
- `08-开发设计方案` 回答“程序员应该怎么写”
- `06-代码唯一性文档` 回答“哪些地方不能自由发挥”

## 4. 每份开发设计文档必须包含
1. 作用域
2. 关联功能 ID
3. 页面与入口
4. 组件树
5. 状态归属
6. IPC 设计
7. 主进程服务拆分
8. 持久化策略
9. 开发顺序
10. 验收口径
11. 组件 Props 契约
12. Hook / state shape
13. 方法级 I/O

## 5. 不允许的写法
1. 只说“前端调用接口、后端保存数据”。
2. 不写状态归属。
3. 不写组件边界。
4. 不写先后顺序。
5. 不写失败路径。
6. 不写 Props 契约和 Hook 状态归属。
