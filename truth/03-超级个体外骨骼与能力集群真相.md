# 超级个体外骨骼与能力集群真相

> 状态：当前真相。
>
> 本文档不是抛弃 `01-从0开始的未来愿景脑暴.md` 与 `02-Codex的第二视角脑暴.md`，而是在它们基础上重新校准方向后的综合真相。前两份文档仍是重要概念来源；后续重构以本文档的整合判断为准。

## 0. 当前判断

未来模型会变强，但这不会消灭外骨骼系统的意义。

原因不是“模型不够聪明”，而是：

```text
单体智能再强，也不等于能力集群。
个体模型再强，也不等于多人、多模型、多工具、多环境的可控协作系统。
```

因此本项目不应定位为：

```text
给弱模型补能力的工作流平台
```

而应定位为：

```text
面向超级个体与超级个体集群的能力外骨骼。
```

它的核心使命是：

```text
识别人类说不清的张力与野心
  -> 生成可选择的能力增强方案
  -> 调度模型、工具、技能、角色、人类与其他超级个体
  -> 交付可见、可控、可验证、可复利的世界变化
```

第三文档不是断代，而是收敛。


## 0.2 本次脑暴本身就是 Probe

这次沟通不是普通需求收集。

它本身就是系统未来应具备的 `Probe / 张力显影` 的一个样本：

```text
用户表达担忧：
  “模型会不会内化一切？”
  “成长是不是伪命题？”
  “外骨骼是否还有意义？”

系统应做的不是直接回答 yes/no，
而是不断追问、反驳自己、吸收用户修正，
最终显影出更深层的真实意图：

用户真正想要的不是一个 AI 工作流工具，
而是一套能把人类长板、短板、精力、野心、工具、模型和他人能力组织起来的第二身体与能力集群。
```

这意味着未来产品第一能力不是“让用户输入清晰任务”，而是把用户说不清的东西逐步显影成：

- 他真正想摆脱什么消耗。
- 他真正想放大什么能力。
- 他真正害怕什么失控。
- 他真正想成为什么样的人。
- 他需要一个工具、团队、流程、实验室、第二身体，还是多个超级个体的协作网络。

## 1. 为什么“模型内化”不会消灭这个方向

模型会内化大量通用能力：

- 通用规划。
- 常见工具调用。
- 常见工作流设计。
- 常见角色扮演。
- 常见技能使用。
- 常见代码、文案、研究和分析模式。

但模型很难完全内化以下东西：

- 用户此刻说不清的真实张力。
- 用户长期想成为的更强形态。
- 用户所在环境的真实状态。
- 用户项目、工具、账号、文件、权限和组织关系。
- 多个模型、工具、人类之间的协作协议。
- 执行证据、失败记录、责任边界和复盘结构。
- 不同超级个体之间的能力拼接、冲突处理和成果合并。

更关键的是，即使单个模型未来很强，仍然存在硬限制：

| 限制 | 说明 |
|---|---|
| 吞吐限制 | 一个智能体不能无限并行研究、执行、评审、试错。 |
| 注意力限制 | 战略、执行、红队、质检放在同一上下文里会互相污染。 |
| 视角限制 | 单模型可以模拟多视角，但真实分离的角色、模型、人类更利于对抗和验证。 |
| 现实限制 | 文件、权限、运行环境、组织关系不在模型参数里。 |
| 协作限制 | 多个强个体协作需要共享协议、证据链、边界和合并机制。 |

所以外骨骼的长期价值不是替模型思考，而是把智能组织成更大的能力结构。

类比：

```text
手机永远很强，但台式机仍然存在。
单张显卡永远很强，但显卡集群更强。
单个超级个体会越来越强，但超级个体集群一定更强。
```

### 1.1 趋势、现状与基础目的的三重校准

当前判断必须同时服从三件事：

| 维度 | 判断 |
|---|---|
| 未来趋势 | 基础模型会内化更多通用推理、规划、工具使用和多步执行能力；厂商平台会持续提供 Agent、Skills、Tracing、Guardrails、Connectors、MCP 类外部能力协议。 |
| 当前现状 | 单模型仍存在上下文、吞吐、可验证性、权限、私有环境、多人协作、长期执行和责任边界问题；真实产出仍需要外部文件、工具、证据、沙盒和审计。 |
| 基础目的 | 本项目不是为了保住一个旧工具形态，而是为了让人类更强：长板更长、短板可桥接、精力被释放、能力边界被扩展、多个超级个体可协作。 |

所以正确方向不是和模型竞争“谁更聪明”，而是成为强模型时代仍然需要的：

```text
能力组织层 / 第二身体层 / 超级个体协作层。
```

## 2. 北极星

本系统的北极星不是“自动化”，也不是“工作流”，更不是“角色 prompt 管理器”。

北极星是：

```text
让人类把模糊痛点、未成形野心、长板、短板、环境资源和外部智能，
组织成可行动、可协作、可复利的能力集群。
同时把与思考和价值判断无关的体力型执行劳动交给系统，
释放人类最稀缺的精力、注意力和创造力。
```

换句话说：

- 让用户的长板更长。
- 让用户不被精力上限限制创造价值。
- 让用户不被自己不懂的短板阻断创造价值。
- 让用户不再被低认知、高摩擦、重复性的体力型执行劳动消耗。
- 让用户能借助模型、工具、技能和他人能力扩展能力边界。
- 让多个增强后的超级个体可以像算力集群一样协作。

系统不是为了让用户变成“更会使用 AI 软件的人”。

系统是为了让用户变成：

```text
更强的创作者
更强的老板
更强的研究员
更强的产品人
更强的工程师
更强的组织者
更强的跨领域行动者
```

### 2.1 你真正想要的具体形象

如果把当前被显影出的意图具象化，它不是一个页面、一个流程图，也不是一个聊天框。

它更像：

```text
一具文件原生的第二身体
+ 一个会追问本质的产品经理/心理咨询师/刑侦专家入口
+ 一个由大模型统领、小模型猛干、工具执行、人类裁决的能力集群
+ 一套可变镜头，让人类随时看见张力、可能性、组织、进展、决策、证据和风险
+ 一个能和其他超级个体互联的协作协议
```

粗略形象：

```text
                    Human
          will / taste / veto / responsibility
                       │
                Tension Field
                       │
             Probe：追问 / 显影 / 类比 / 证据
                       │
              Possibility Map：展开可选未来
                       │
              Promise：系统承诺增强什么能力
                       │
        ┌──────────────┼──────────────┐
        │              │              │
  Orchestrator     Second Body       Lenses
  大模型统领        感官/肌肉/免疫      人类观察与控制
        │              │              │
        ▼              ▼              ▼
 Verifiable Moves  Tools/Skills   Evidence Trail
 小模型/规则猛干    执行体力劳动     可验证、可复盘
        │              │              │
        └──────────────┼──────────────┘
                       ▼
              Capability Organism
                       │
                 Federation
              多个超级个体级联
```

这就是“具体形象”：不是让用户学会操作更复杂的软件，而是让用户感觉自己多长出一套可见、可控、可协作、可进化的身体。

## 3. 人类在系统中的位置

人类不是 prompt 工程师。

人类也不是无限审批机。

人类在系统里的核心角色是：

```text
意志 / 品味 / 目标感 / 价值判断 / 授权 / 否决权
```

系统不应该要求人类先把任务说清楚。真实用户常常只有：

- 痛点。
- 烦躁。
- 隐约的不满。
- 未成形的野心。
- 对现状的排斥。
- 对某种未来自己的向往。

因此第一能力仍然是主动识别，但应从“意图识别”升级为：

```text
张力显影。
```

张力显影要识别：

- 用户真正被什么消耗。
- 用户真正想放大的能力是什么。
- 用户害怕失去什么控制权。
- 用户想保留哪些亲自决策。
- 用户想把哪些短板外包给系统。
- 用户的长板在哪里，如何进一步放大。
- 用户真正想成为哪类更强的人。

## 4. 不是外脑，而是能力外骨骼

“外脑”容易走错方向。

它容易变成：

- 替用户沉淀偏好。
- 替用户做判断。
- 越学越封闭。
- 被用户已有认知限制。
- 让系统陷入决策地狱。

更准确的方向是：

```text
能力外骨骼。
```

外骨骼不是替用户成为另一个脑子，而是：

- 扩展感官：发现用户看不到的风险、机会、证据和模式。
- 扩展手臂：执行用户没精力做的任务。
- 扩展体力：承接重复、繁琐、等待、搬运、核对、整理、提交、监控等非思考性劳动。
- 扩展团队：临时组织角色、模型、工具、专家和协作者。
- 扩展实验室：低成本试错，验证方向。
- 扩展免疫系统：发现错误、越权、质量下降和重复失败。
- 扩展记忆：记住环境、失败路径、决策依据和可复用资产。

### 4.1 第二身体

`第二身体` 是比“外脑”更准确的具象。

普通工具是手里的锤子，第二身体是能和人类意志协同的外部器官系统：

| 器官 | 职责 |
|---|---|
| 感官 | 发现世界变化、项目状态、用户状态、风险和机会。 |
| 神经 | 关联信息、形成判断、调度能力、提醒人类。 |
| 大脑外协 | 使用大模型进行张力显影、可能性展开、战略判断、组织设计和综合裁决。 |
| 肌肉 | 调用工具、脚本、小模型和受控 Agent，承接体力型执行劳动。 |
| 反射 | 对高频、低风险、可回滚动作自动响应。 |
| 免疫 | 发现越权、错误、幻觉、质量下降和不可信输入。 |
| 记忆 | 沉淀环境事实、失败路径、决策依据、能力种子和可复用经验。 |
| 睡眠 | 后台整理、压缩、遗忘、生成改进提案，但不偷偷越权行动。 |
| 疼痛 | 把重复失败、成本异常、质量下降、过多人工介入变成可感知信号。 |
| 意志 | 始终来自人类，系统只能承诺、建议、执行和反馈。 |

这个概念保留 `02` 的核心直觉：用户理想中不是“打开一个软件”，而是“多长出一套感官、一组手臂、一支团队、一个实验室和一个受自己灵魂约束的第二神经系统”。

## 5. 能力增强的五种形态

### 5.1 长板放大

用户本来就擅长的能力，系统应让它更强。

例子：

- 创作者：灵感捕获、结构化、风格迭代、分发节奏。
- 产品人：用户洞察、机会评估、原型生成、反馈闭环。
- 研究员：证据网络、假设管理、反例搜索、综述生成。
- 工程师：架构推演、代码执行、测试验证、回归证据。
- 老板：战略台账、风险雷达、组织调度、授权控制。

这里系统不是“代替用户”，而是把用户原本的能力变成更高带宽、更少摩擦、更可复用的系统。

### 5.2 短板桥接

用户不懂、不擅长、没时间、没精力的部分，系统应提供外部能力。

例子：

- 不懂设计，但可以调度设计审查与原型生成。
- 不懂法律，但可以调度合规检查与风险提示。
- 不懂运维，但可以调度环境诊断与部署验证。
- 不擅长表达，但可以把模糊想法转成清晰方案。
- 不擅长收尾，但可以维持证据、清单、验收与复盘。

短板桥接不等于让用户永远依赖系统。它应同时提供：

- 直接产出。
- 可理解解释。
- 可学习路径。
- 风险提示。
- 人类介入点。

### 5.3 精力解放

用户的创造力经常不是被“不会思考”限制，而是被大量与思考无关的体力型执行劳动消耗。

这里的“体力劳动”不只指现实世界的搬运，也包括数字世界中的低认知、高摩擦、重复性动作：

- 收集资料。
- 批量整理文件。
- 跑命令、等结果、复制日志。
- 填表、改格式、对齐命名。
- 截图、上传、下载、归档。
- 监控状态、发现失败、重新尝试。
- 按清单核对产物。
- 在多个系统之间搬运信息。
- 生成例行报告和进度摘要。
- 处理不需要价值判断的事务性沟通。

这类劳动的特点是：

| 特点 | 说明 |
|---|---|
| 低判断 | 不需要用户的品味、战略或价值裁决。 |
| 高消耗 | 很占时间、注意力和耐心。 |
| 易出错 | 重复动作越多，越容易漏、错、忘。 |
| 可验证 | 通常有明确输入、输出、清单或状态。 |
| 可交给系统 | 适合工具、脚本、小模型、规则程序或受控 Agent 执行。 |

系统必须把这类劳动视为一等公民，而不是“顺手自动化”。

原因很简单：

```text
释放用户精力本身就是能力增强。
```

当系统承接体力型执行劳动时，人类可以把精力保留给：

- 判断方向。
- 形成品味。
- 做关键取舍。
- 创造概念。
- 连接人。
- 承担责任。
- 定义什么值得做。

这类能力应遵循：

- 默认低风险优先。
- 能批量就批量。
- 能后台就后台。
- 能验证就自动验证。
- 高风险动作必须进入授权。
- 过程要有状态和证据，而不是让用户反复追问。

### 5.4 边界拓展

系统不应只完成用户已经知道要做的事。

它还应扩展用户的想象边界：

- 你以为你要自动化，也许你需要的是诊断系统。
- 你以为你要流程，也许你需要的是团队。
- 你以为你要工具，也许你需要的是承诺协议。
- 你以为你要更快，也许你需要的是更少决策。
- 你以为你要执行，也许你需要先验证方向。

这要求系统必须有 `Possibility Map`，而不是直接把用户输入变成任务。

### 5.5 超级个体级联

当多个增强后的人类协作时，价值不是简单相加。

系统需要支持：

- 能力声明：每个超级个体能提供什么能力。
- 边界声明：什么能做，什么不能做。
- 证据声明：凭什么相信产物。
- 交付协议：输入、输出、验收、责任。
- 冲突处理：分歧如何暴露、裁决和记录。
- 能力组合：如何把多个能力拼成更大的结果。

这部分是未来最重要的方向之一：

```text
单人外骨骼 -> 超级个体 -> 超级个体集群 -> 能力网络
```

## 6. 当前核心原语

这些不是最终架构，但现在应作为第三文档的真相原语。

| 原语 | 当前定义 |
|---|---|
| `Tension Field` | 用户带来的痛点、欲望、恐惧、约束、资源、野心和身份张力。 |
| `Probe` | 主动显影张力的对话、观察、追问、类比和证据收集机制。 |
| `Possibility Map` | 多种解决形态的展开，不急于收敛成工作流。 |
| `Promise` | 系统与人类之间的持续承诺，定义系统帮用户增强什么能力。 |
| `Second Body` | 第二身体隐喻，把感官、神经、肌肉、反射、免疫、记忆、睡眠、疼痛和意志分开建模。 |
| `Capability Organism` | 可迁移、可适配、可评估、可学习的一组角色、技能、工具、记忆种子和运行轨迹。 |
| `Crew / Swarm` | 围绕一次 Promise 临时组织起来的模型、工具、角色、人类和能力。 |
| `Orchestrator Brain` | 大模型或大模型团队承担统领职责：设计动作集合、调度执行、抽样审计、整合结论。 |
| `Execution Muscle` | 承接低认知、高摩擦、重复性体力型执行劳动的执行肌肉。 |
| `Verifiable Move` | 输入小、输出小、可检查、可并行、失败成本低的最小动作。 |
| `Evidence Trail` | 对外可解释的证据、决策、风险、产物和验证轨迹。 |
| `Lens` | 面向人类的可变观察镜头，而不是固定页面。 |
| `Trust Gradient` | 不同能力从观察、提案、草稿、沙盒到代理执行的授权等级。 |
| `Human Bandwidth` | 对人类精力、打断频率、决策方式和解释深度的建模。 |
| `Pain Signal` | 重复失败、低质量、阻塞、越权、过多介入等系统疼痛信号。 |
| `Mutation Proposal` | 系统发现改进空间后生成的能力、流程、评估或组织变更提案。 |
| `Federation` | 多个超级个体、组织或能力包之间的互联协作协议。 |

## 7. Promise 应是中心对象

工作流的中心是流程。

人的中心不是流程，而是：

```text
系统承诺帮我变强什么？
```

因此 `Promise` 比 `Workflow` 更接近中心对象。

一个 Promise 应描述：

```yaml
promise:
  human_tension: "我想把模糊野心变成可执行的产品方向"
  capability_growth:
    strengthen:
      - "产品判断"
      - "机会识别"
    compensate:
      - "用户研究不足"
      - "执行收尾不足"
    expand:
      - "从单人想法扩展到团队验证"
  system_commitment:
    - "主动追问并显影真实张力"
    - "生成至少三种可能方案"
    - "组织研究、质疑、原型、评审能力"
    - "记录关键证据与决策"
  human_control:
    - "最终方向裁决"
    - "高风险动作授权"
    - "审美与价值判断"
  success_signals:
    - "用户不再停留在模糊焦虑"
    - "至少一个方向进入可验证实验"
    - "产物能被第三方理解并继续推进"
```

围绕 Promise 再生成：

- 组织形态。
- 能力包。
- 技能选择。
- 原子动作。
- 评估标准。
- 记忆策略。
- 人类介入点。
- 可分享切片。

## 8. 能力有机体，而不是模板

下载技能会越来越容易。

但下载技能不等于获得能力。

通用技能只是种子，真正的能力还需要：

- 适配用户环境。
- 适配用户目标。
- 适配项目状态。
- 适配权限边界。
- 适配质量标准。
- 适配已有工具和协作者。
- 经过运行、验证、失败和修正。

因此可分享对象不应只是模板，而应是：

```text
Capability Organism / 能力有机体
```

一个能力有机体可以包含：

- 角色组合。
- 技能包。
- 工具声明。
- 文件协议。
- 记忆种子。
- 评估标准。
- 示例输入输出。
- 示例运行轨迹。
- 失败经验。
- 适配指南。
- 风险边界。

导入后，系统不应直接信任它，而应经过：

```text
导入 -> 沙盒运行 -> 本地适配 -> 评估 -> 授权 -> 纳入可用能力
```

## 9. 大小模型协作的真实边界

大小模型协作不是口号。

必须把工作拆到 `Verifiable Move` 级别，协作才成立。

### 9.1 大模型适合

- 张力显影。
- 可能性展开。
- 战略判断。
- 复杂综合。
- 组织设计。
- 关键取舍。
- 反事实推理。
- 高层评审。

### 9.2 中模型适合

- 草拟方案。
- 局部评审。
- 信息整理。
- 结构化重写。
- 中等复杂度判断。
- 多候选比较。

### 9.3 小模型适合

- 抽取。
- 分类。
- 打标签。
- 格式化。
- 查重。
- schema 检查。
- 引用初筛。
- 小范围改写。

### 9.4 规则程序适合

- 确定性校验。
- 文件扫描。
- 差异比较。
- 格式转换。
- 测试执行。
- 权限检查。

### 9.5 人类适合

- 价值判断。
- 审美判断。
- 最终裁决。
- 高风险授权。
- 身份方向选择。
- 对“我想成为谁”的判断。

### 9.6 大模型统领小模型

“大模型统领小模型”不能停留在口号。

它应具体化为：

```text
大模型：理解张力、设计策略、拆出可验证动作、分配执行者、抽样审计、整合结论。
小模型：执行窄输入、窄输出、可验证、低失败成本的动作。
规则程序：做确定性检查、文件操作、测试执行和状态采集。
人类：裁决方向、授权风险、定义价值和承担责任。
```

更具体地说：

| 环节 | 负责人 | 输出 |
|---|---|---|
| 显影张力 | 大模型 + 人类 | `Tension Field` |
| 展开可能性 | 大模型 | `Possibility Map` |
| 形成承诺 | 大模型 + 人类 | `Promise` |
| 设计动作集合 | 大模型 | `Verifiable Move Set` |
| 执行动作 | 小模型 / 工具 / 规则程序 | 小产物、状态、日志、证据 |
| 抽样审计 | 大模型 / 中模型 / 规则程序 | 质量判断、异常点 |
| 整合结果 | 大模型 | 结论、产物、下一步 |
| 裁决与授权 | 人类 | 批准、拒绝、调整方向 |

这更接近显卡集群里的调度关系：

```text
大模型不是亲自做所有计算，
而是把世界切成可调度、可验证、可并行的 kernel，
交给小模型、工具和规则程序猛干。
```

### 9.7 可验证动作是集群协作的最小接口

`Verifiable Move` 是本系统避免多智能体空转的关键。

一个 Move 必须尽量满足：

- 输入小。
- 输出小。
- 可机器检查。
- 可并行。
- 失败成本低。
- 可重试。
- 可审计。
- 可归因到执行者。
- 可被抽样复核。

示例：

```text
从一段话中抽取所有明确约束。
判断一个输出是否满足 schema。
给 10 个候选标题打标签。
检查一个引用是否真的支持某句话。
把一段需求改写成用户故事。
判断一句话是事实、推测还是价值判断。
从运行日志中找出第一个失败点。
核对一个文件是否包含指定章节。
```

没有 Move，所谓“多智能体协作”容易变成热闹剧场。

有了 Move，大小模型、规则程序、工具和人类才能围绕同一套输入输出和验收标准协作。

## 10. 防止决策地狱

系统如果持续成长但缺少约束，会制造决策地狱。

必须内置以下机制：

| 机制 | 作用 |
|---|---|
| `Possibility Map` | 先展开可能性，但必须限制候选数量和比较维度。 |
| `Human Bandwidth` | 根据用户精力决定提问数量、解释深度和打断频率。 |
| `Default Policy` | 低风险问题可按默认策略推进，高风险问题必须等待。 |
| `Decision Batch` | 把多个低紧急度问题合并成一次决策。 |
| `Evidence Trail` | 只展示可行动证据，不暴露内部推理噪声。 |
| `Reversible First` | 优先执行可回滚、低成本动作。 |
| `Timebox` | 对探索和争论设定时间盒，避免无限发散。 |
| `Dissent Slot` | 保留反方意见，但不让反方无限拖慢执行。 |

原则：

```text
系统要扩展用户能力边界，而不是消耗用户决策带宽。
```

## 11. 防止认知封闭

外骨骼如果只学习用户偏好，会让用户变强但变窄。

必须避免：

- 越来越迎合用户旧习惯。
- 越来越确认用户已有判断。
- 越来越排斥陌生领域。
- 越来越把本地记忆当真理。
- 越来越难引入外部能力。

因此系统需要：

- 外部资料校准。
- 反方观点。
- 多模型分歧。
- 外部专家或能力包导入。
- 失败样本。
- 反直觉方案。
- 不做方案。
- 对用户目标的温和挑战。

这不是为了否定用户，而是为了防止系统成为用户认知的回音室。

## 12. 文件原生的意义

文件原生不是复古。

它的价值是：

- 可读。
- 可迁移。
- 可版本控制。
- 可审计。
- 可被不同模型接管。
- 可被人类直接理解和修改。
- 不被某个 UI 或平台锁死。

未来 UI 只是镜头：

- 意图镜头。
- 可能性镜头。
- 组织镜头。
- 进展镜头。
- 决策镜头。
- 证据镜头。
- 记忆镜头。
- 体力劳动镜头。
- 联邦协作镜头。

真相应尽量落在文件协议中，UI 负责投影、编辑、授权和状态展示。

### 12.1 可变镜头不是页面导航

`Lens / 镜头` 继承 `02` 的关键判断：UI 的核心不是管理对象，而是让人类从不同角度看见同一个能力系统。

| 镜头 | 看见什么 |
|---|---|
| 张力镜头 | 痛点、欲望、恐惧、约束、隐喻、真实目标。 |
| 可能性镜头 | 可选解决形态、代价、风险、不做方案、反直觉方案。 |
| Promise 镜头 | 系统承诺增强什么能力，人类保留什么控制权。 |
| 组织镜头 | 当前调度的角色、模型、工具、技能、人类和外部协作者。 |
| 体力劳动镜头 | 哪些低认知执行劳动正在后台处理，进度、阻塞和证据是什么。 |
| Move 镜头 | 哪些可验证动作被拆出，谁在执行，验收标准是什么。 |
| 进展镜头 | 正在跑什么、阻塞什么、谁负责、下一步是什么。 |
| 决策镜头 | 哪些选择需要人类裁决，默认策略是什么。 |
| 证据镜头 | 为什么系统相信某个结论，证据链是否足够。 |
| 记忆镜头 | 什么被沉淀、什么被遗忘、什么仍是临时上下文。 |
| 疼痛镜头 | 重复失败、成本异常、低质量、越权风险和人工介入过多的位置。 |
| 进化镜头 | 系统想如何通过 Mutation Proposal 改进自己。 |
| 联邦镜头 | 哪些超级个体或能力包参与协作，边界、信任和贡献是什么。 |

用户不应该被扔进一堆配置表。

用户应该能够根据当下需要切换镜头：

```text
我现在想看风险。
我现在想看证据。
我现在想看谁在干活。
我现在想看我需要做什么决定。
我现在想看系统为什么认为这个方向值得继续。
```

## 13. 超级个体联邦

本项目不能只面向单用户。

未来更大的价值来自多个超级个体协作。

一个超级个体不是“一个人 + 一个聊天机器人”，而是：

```text
人类意志
+ 个体外骨骼
+ 私有环境记忆
+ 能力包
+ 工具权限
+ 执行证据
+ 可协作接口
```

多个超级个体协作时，需要联邦协议：

- 能力发现：我能提供什么。
- 需求发布：我需要什么。
- 边界声明：我不能做什么。
- 信任等级：你能自动接入到什么程度。
- 成果交付：输出是什么，证据是什么。
- 冲突解决：分歧如何暴露和裁决。
- 隐私保护：哪些记忆和文件不能外传。
- 贡献追踪：谁贡献了什么能力和产物。

这会把系统从个人效率工具推进到：

```text
能力网络。
```

## 14. 与现有平台的差异

本项目不应正面竞争：

- n8n 式自动化画布。
- LangChain 式开发框架。
- 单纯 Agent Builder。
- 单纯技能市场。
- 单纯知识库。
- 单纯项目管理工具。

它们都可能成为系统的一部分，但不是系统的中心。

中心应是：

```text
人类能力增强与能力集群协作。
```

如果未来模型厂商提供更强 Agent，本系统仍可存在，因为它负责：

- 本地文件真相。
- 用户张力显影。
- Promise 契约。
- 能力有机体适配。
- 多模型/多工具/多人协作。
- 执行证据。
- 授权与信任梯度。
- 超级个体联邦。

## 15. 反模式

必须避免：

1. 把系统做成工作流编辑器。
2. 把角色做成 prompt cosplay。
3. 把技能做成一堆不可验证的上下文文本。
4. 把成长做成用户偏好堆积。
5. 把记忆做成聊天记录。
6. 把自动化当成目标，而不是能力增强的副产物。
7. 把 UI 做成配置表管理后台。
8. 把用户变成无限审批机。
9. 把系统变成用户认知回音室。
10. 把多智能体做成热闹但不可验证的剧场。
11. 把文件协议做成沉重框架。
12. 把“未来感”建立在复杂度上。

## 16. 当前收敛判断

第三阶段真相可以收敛为十句话：

1. 模型会越来越强，但单体智能不会替代能力集群。
2. 系统的核心不是自动化，而是人类能力放大。
3. 第一入口不是任务，而是张力显影。
4. 中心对象不是工作流，而是 Promise。
5. 系统必须解放用户精力，承接与思考无关但消耗注意力的体力型执行劳动。
6. 第二身体是当前最准确的具象：感官、神经、肌肉、反射、免疫、记忆、睡眠、疼痛和人类意志必须分开建模。
7. 大模型统领小模型的前提是 `Verifiable Move`，否则多智能体协作会变成不可验收的剧场。
8. UI 的核心不是页面，而是 Lens，让人类按张力、可能性、组织、进展、决策、证据、疼痛和联邦关系切换观察方式。
9. 本次脑暴本身就是系统应具备的 Probe：从用户模糊担忧中显影出真实想要的第二身体与能力集群。
10. 长期价值不在替 AI 成长，而在让人类、模型、工具、技能和其他超级个体形成可控的能力网络。

## 17. 下一步需要继续细化的问题

后续不应马上进入代码重构，应继续澄清：

1. `Probe` 如何主动但不冒犯。
2. `Promise` 的最小文件协议是什么。
3. `Capability Organism` 如何导入、沙盒、评估和授权。
4. `Verifiable Move` 的最小 schema 是什么。
5. `Human Bandwidth` 如何避免把用户变成审批机。
6. `Federation` 如何支持多个超级个体协作。
7. `Second Body` 的感官、神经、肌肉、免疫、记忆、睡眠、疼痛如何落成文件协议。
8. `Lens` 的最小视图协议是什么，如何让 UI 只是投影而不是新的真相源。
9. 哪些旧的 `Workflow / Role / Skill / Agent` 概念应保留、降级、重命名或淘汰。
