# 超级个体外骨骼与能力集群真相

> 状态：当前真相。
>
> 本文档取代 `01-从0开始的未来愿景脑暴.md` 与 `02-Codex的第二视角脑暴.md` 作为当前阶段的正向判断。前两份文档保留为历史脑暴素材，不再作为真相源。

## 0. 当前判断

未来模型会变强，但这不会消灭外骨骼系统的意义。

原因不是“模型不够聪明”，而是：

```text
单体智能再强，也不等于能力集群。
个体模型再强，也不等于多人、多模型、多工具、多环境的可控协作系统。
```

因此本项目不应定位为：

```text
给弱模型补能力的工作流平台
```

而应定位为：

```text
面向超级个体与超级个体集群的能力外骨骼。
```

它的核心使命是：

```text
识别人类说不清的张力与野心
  -> 生成可选择的能力增强方案
  -> 调度模型、工具、技能、角色、人类与其他超级个体
  -> 交付可见、可控、可验证、可复利的世界变化
```

## 1. 为什么“模型内化”不会消灭这个方向

模型会内化大量通用能力：

- 通用规划。
- 常见工具调用。
- 常见工作流设计。
- 常见角色扮演。
- 常见技能使用。
- 常见代码、文案、研究和分析模式。

但模型很难完全内化以下东西：

- 用户此刻说不清的真实张力。
- 用户长期想成为的更强形态。
- 用户所在环境的真实状态。
- 用户项目、工具、账号、文件、权限和组织关系。
- 多个模型、工具、人类之间的协作协议。
- 执行证据、失败记录、责任边界和复盘结构。
- 不同超级个体之间的能力拼接、冲突处理和成果合并。

更关键的是，即使单个模型未来很强，仍然存在硬限制：

| 限制 | 说明 |
|---|---|
| 吞吐限制 | 一个智能体不能无限并行研究、执行、评审、试错。 |
| 注意力限制 | 战略、执行、红队、质检放在同一上下文里会互相污染。 |
| 视角限制 | 单模型可以模拟多视角，但真实分离的角色、模型、人类更利于对抗和验证。 |
| 现实限制 | 文件、权限、运行环境、组织关系不在模型参数里。 |
| 协作限制 | 多个强个体协作需要共享协议、证据链、边界和合并机制。 |

所以外骨骼的长期价值不是替模型思考，而是把智能组织成更大的能力结构。

类比：

```text
手机永远很强，但台式机仍然存在。
单张显卡永远很强，但显卡集群更强。
单个超级个体会越来越强，但超级个体集群一定更强。
```

## 2. 北极星

本系统的北极星不是“自动化”，也不是“工作流”，更不是“角色 prompt 管理器”。

北极星是：

```text
让人类把模糊痛点、未成形野心、长板、短板、环境资源和外部智能，
组织成可行动、可协作、可复利的能力集群。
```

换句话说：

- 让用户的长板更长。
- 让用户不被精力上限限制创造价值。
- 让用户不被自己不懂的短板阻断创造价值。
- 让用户能借助模型、工具、技能和他人能力扩展能力边界。
- 让多个增强后的超级个体可以像算力集群一样协作。

系统不是为了让用户变成“更会使用 AI 软件的人”。

系统是为了让用户变成：

```text
更强的创作者
更强的老板
更强的研究员
更强的产品人
更强的工程师
更强的组织者
更强的跨领域行动者
```

## 3. 人类在系统中的位置

人类不是 prompt 工程师。

人类也不是无限审批机。

人类在系统里的核心角色是：

```text
意志 / 品味 / 目标感 / 价值判断 / 授权 / 否决权
```

系统不应该要求人类先把任务说清楚。真实用户常常只有：

- 痛点。
- 烦躁。
- 隐约的不满。
- 未成形的野心。
- 对现状的排斥。
- 对某种未来自己的向往。

因此第一能力仍然是主动识别，但应从“意图识别”升级为：

```text
张力显影。
```

张力显影要识别：

- 用户真正被什么消耗。
- 用户真正想放大的能力是什么。
- 用户害怕失去什么控制权。
- 用户想保留哪些亲自决策。
- 用户想把哪些短板外包给系统。
- 用户的长板在哪里，如何进一步放大。
- 用户真正想成为哪类更强的人。

## 4. 不是外脑，而是能力外骨骼

“外脑”容易走错方向。

它容易变成：

- 替用户沉淀偏好。
- 替用户做判断。
- 越学越封闭。
- 被用户已有认知限制。
- 让系统陷入决策地狱。

更准确的方向是：

```text
能力外骨骼。
```

外骨骼不是替用户成为另一个脑子，而是：

- 扩展感官：发现用户看不到的风险、机会、证据和模式。
- 扩展手臂：执行用户没精力做的任务。
- 扩展团队：临时组织角色、模型、工具、专家和协作者。
- 扩展实验室：低成本试错，验证方向。
- 扩展免疫系统：发现错误、越权、质量下降和重复失败。
- 扩展记忆：记住环境、失败路径、决策依据和可复用资产。

## 5. 能力增强的四种形态

### 5.1 长板放大

用户本来就擅长的能力，系统应让它更强。

例子：

- 创作者：灵感捕获、结构化、风格迭代、分发节奏。
- 产品人：用户洞察、机会评估、原型生成、反馈闭环。
- 研究员：证据网络、假设管理、反例搜索、综述生成。
- 工程师：架构推演、代码执行、测试验证、回归证据。
- 老板：战略台账、风险雷达、组织调度、授权控制。

这里系统不是“代替用户”，而是把用户原本的能力变成更高带宽、更少摩擦、更可复用的系统。

### 5.2 短板桥接

用户不懂、不擅长、没时间、没精力的部分，系统应提供外部能力。

例子：

- 不懂设计，但可以调度设计审查与原型生成。
- 不懂法律，但可以调度合规检查与风险提示。
- 不懂运维，但可以调度环境诊断与部署验证。
- 不擅长表达，但可以把模糊想法转成清晰方案。
- 不擅长收尾，但可以维持证据、清单、验收与复盘。

短板桥接不等于让用户永远依赖系统。它应同时提供：

- 直接产出。
- 可理解解释。
- 可学习路径。
- 风险提示。
- 人类介入点。

### 5.3 边界拓展

系统不应只完成用户已经知道要做的事。

它还应扩展用户的想象边界：

- 你以为你要自动化，也许你需要的是诊断系统。
- 你以为你要流程，也许你需要的是团队。
- 你以为你要工具，也许你需要的是承诺协议。
- 你以为你要更快，也许你需要的是更少决策。
- 你以为你要执行，也许你需要先验证方向。

这要求系统必须有 `Possibility Map`，而不是直接把用户输入变成任务。

### 5.4 超级个体级联

当多个增强后的人类协作时，价值不是简单相加。

系统需要支持：

- 能力声明：每个超级个体能提供什么能力。
- 边界声明：什么能做，什么不能做。
- 证据声明：凭什么相信产物。
- 交付协议：输入、输出、验收、责任。
- 冲突处理：分歧如何暴露、裁决和记录。
- 能力组合：如何把多个能力拼成更大的结果。

这部分是未来最重要的方向之一：

```text
单人外骨骼 -> 超级个体 -> 超级个体集群 -> 能力网络
```

## 6. 当前核心原语

这些不是最终架构，但现在应作为第三文档的真相原语。

| 原语 | 当前定义 |
|---|---|
| `Tension Field` | 用户带来的痛点、欲望、恐惧、约束、资源、野心和身份张力。 |
| `Probe` | 主动显影张力的对话、观察、追问、类比和证据收集机制。 |
| `Possibility Map` | 多种解决形态的展开，不急于收敛成工作流。 |
| `Promise` | 系统与人类之间的持续承诺，定义系统帮用户增强什么能力。 |
| `Capability Organism` | 可迁移、可适配、可评估、可学习的一组角色、技能、工具、记忆种子和运行轨迹。 |
| `Crew / Swarm` | 围绕一次 Promise 临时组织起来的模型、工具、角色、人类和能力。 |
| `Verifiable Move` | 输入小、输出小、可检查、可并行、失败成本低的最小动作。 |
| `Evidence Trail` | 对外可解释的证据、决策、风险、产物和验证轨迹。 |
| `Lens` | 面向人类的可变观察镜头，而不是固定页面。 |
| `Trust Gradient` | 不同能力从观察、提案、草稿、沙盒到代理执行的授权等级。 |
| `Human Bandwidth` | 对人类精力、打断频率、决策方式和解释深度的建模。 |
| `Pain Signal` | 重复失败、低质量、阻塞、越权、过多介入等系统疼痛信号。 |
| `Mutation Proposal` | 系统发现改进空间后生成的能力、流程、评估或组织变更提案。 |
| `Federation` | 多个超级个体、组织或能力包之间的互联协作协议。 |

## 7. Promise 应是中心对象

工作流的中心是流程。

人的中心不是流程，而是：

```text
系统承诺帮我变强什么？
```

因此 `Promise` 比 `Workflow` 更接近中心对象。

一个 Promise 应描述：

```yaml
promise:
  human_tension: "我想把模糊野心变成可执行的产品方向"
  capability_growth:
    strengthen:
      - "产品判断"
      - "机会识别"
    compensate:
      - "用户研究不足"
      - "执行收尾不足"
    expand:
      - "从单人想法扩展到团队验证"
  system_commitment:
    - "主动追问并显影真实张力"
    - "生成至少三种可能方案"
    - "组织研究、质疑、原型、评审能力"
    - "记录关键证据与决策"
  human_control:
    - "最终方向裁决"
    - "高风险动作授权"
    - "审美与价值判断"
  success_signals:
    - "用户不再停留在模糊焦虑"
    - "至少一个方向进入可验证实验"
    - "产物能被第三方理解并继续推进"
```

围绕 Promise 再生成：

- 组织形态。
- 能力包。
- 技能选择。
- 原子动作。
- 评估标准。
- 记忆策略。
- 人类介入点。
- 可分享切片。

## 8. 能力有机体，而不是模板

下载技能会越来越容易。

但下载技能不等于获得能力。

通用技能只是种子，真正的能力还需要：

- 适配用户环境。
- 适配用户目标。
- 适配项目状态。
- 适配权限边界。
- 适配质量标准。
- 适配已有工具和协作者。
- 经过运行、验证、失败和修正。

因此可分享对象不应只是模板，而应是：

```text
Capability Organism / 能力有机体
```

一个能力有机体可以包含：

- 角色组合。
- 技能包。
- 工具声明。
- 文件协议。
- 记忆种子。
- 评估标准。
- 示例输入输出。
- 示例运行轨迹。
- 失败经验。
- 适配指南。
- 风险边界。

导入后，系统不应直接信任它，而应经过：

```text
导入 -> 沙盒运行 -> 本地适配 -> 评估 -> 授权 -> 纳入可用能力
```

## 9. 大小模型协作的真实边界

大小模型协作不是口号。

必须把工作拆到 `Verifiable Move` 级别，协作才成立。

### 9.1 大模型适合

- 张力显影。
- 可能性展开。
- 战略判断。
- 复杂综合。
- 组织设计。
- 关键取舍。
- 反事实推理。
- 高层评审。

### 9.2 中模型适合

- 草拟方案。
- 局部评审。
- 信息整理。
- 结构化重写。
- 中等复杂度判断。
- 多候选比较。

### 9.3 小模型适合

- 抽取。
- 分类。
- 打标签。
- 格式化。
- 查重。
- schema 检查。
- 引用初筛。
- 小范围改写。

### 9.4 规则程序适合

- 确定性校验。
- 文件扫描。
- 差异比较。
- 格式转换。
- 测试执行。
- 权限检查。

### 9.5 人类适合

- 价值判断。
- 审美判断。
- 最终裁决。
- 高风险授权。
- 身份方向选择。
- 对“我想成为谁”的判断。

## 10. 防止决策地狱

系统如果持续成长但缺少约束，会制造决策地狱。

必须内置以下机制：

| 机制 | 作用 |
|---|---|
| `Possibility Map` | 先展开可能性，但必须限制候选数量和比较维度。 |
| `Human Bandwidth` | 根据用户精力决定提问数量、解释深度和打断频率。 |
| `Default Policy` | 低风险问题可按默认策略推进，高风险问题必须等待。 |
| `Decision Batch` | 把多个低紧急度问题合并成一次决策。 |
| `Evidence Trail` | 只展示可行动证据，不暴露内部推理噪声。 |
| `Reversible First` | 优先执行可回滚、低成本动作。 |
| `Timebox` | 对探索和争论设定时间盒，避免无限发散。 |
| `Dissent Slot` | 保留反方意见，但不让反方无限拖慢执行。 |

原则：

```text
系统要扩展用户能力边界，而不是消耗用户决策带宽。
```

## 11. 防止认知封闭

外骨骼如果只学习用户偏好，会让用户变强但变窄。

必须避免：

- 越来越迎合用户旧习惯。
- 越来越确认用户已有判断。
- 越来越排斥陌生领域。
- 越来越把本地记忆当真理。
- 越来越难引入外部能力。

因此系统需要：

- 外部资料校准。
- 反方观点。
- 多模型分歧。
- 外部专家或能力包导入。
- 失败样本。
- 反直觉方案。
- 不做方案。
- 对用户目标的温和挑战。

这不是为了否定用户，而是为了防止系统成为用户认知的回音室。

## 12. 文件原生的意义

文件原生不是复古。

它的价值是：

- 可读。
- 可迁移。
- 可版本控制。
- 可审计。
- 可被不同模型接管。
- 可被人类直接理解和修改。
- 不被某个 UI 或平台锁死。

未来 UI 只是镜头：

- 意图镜头。
- 可能性镜头。
- 组织镜头。
- 进展镜头。
- 决策镜头。
- 证据镜头。
- 记忆镜头。
- 联邦协作镜头。

真相应尽量落在文件协议中，UI 负责投影、编辑、授权和状态展示。

## 13. 超级个体联邦

本项目不能只面向单用户。

未来更大的价值来自多个超级个体协作。

一个超级个体不是“一个人 + 一个聊天机器人”，而是：

```text
人类意志
+ 个体外骨骼
+ 私有环境记忆
+ 能力包
+ 工具权限
+ 执行证据
+ 可协作接口
```

多个超级个体协作时，需要联邦协议：

- 能力发现：我能提供什么。
- 需求发布：我需要什么。
- 边界声明：我不能做什么。
- 信任等级：你能自动接入到什么程度。
- 成果交付：输出是什么，证据是什么。
- 冲突解决：分歧如何暴露和裁决。
- 隐私保护：哪些记忆和文件不能外传。
- 贡献追踪：谁贡献了什么能力和产物。

这会把系统从个人效率工具推进到：

```text
能力网络。
```

## 14. 与现有平台的差异

本项目不应正面竞争：

- n8n 式自动化画布。
- LangChain 式开发框架。
- 单纯 Agent Builder。
- 单纯技能市场。
- 单纯知识库。
- 单纯项目管理工具。

它们都可能成为系统的一部分，但不是系统的中心。

中心应是：

```text
人类能力增强与能力集群协作。
```

如果未来模型厂商提供更强 Agent，本系统仍可存在，因为它负责：

- 本地文件真相。
- 用户张力显影。
- Promise 契约。
- 能力有机体适配。
- 多模型/多工具/多人协作。
- 执行证据。
- 授权与信任梯度。
- 超级个体联邦。

## 15. 反模式

必须避免：

1. 把系统做成工作流编辑器。
2. 把角色做成 prompt cosplay。
3. 把技能做成一堆不可验证的上下文文本。
4. 把成长做成用户偏好堆积。
5. 把记忆做成聊天记录。
6. 把自动化当成目标，而不是能力增强的副产物。
7. 把 UI 做成配置表管理后台。
8. 把用户变成无限审批机。
9. 把系统变成用户认知回音室。
10. 把多智能体做成热闹但不可验证的剧场。
11. 把文件协议做成沉重框架。
12. 把“未来感”建立在复杂度上。

## 16. 当前收敛判断

第三阶段真相可以收敛为五句话：

1. 模型会越来越强，但单体智能不会替代能力集群。
2. 系统的核心不是自动化，而是人类能力放大。
3. 第一入口不是任务，而是张力显影。
4. 中心对象不是工作流，而是 Promise。
