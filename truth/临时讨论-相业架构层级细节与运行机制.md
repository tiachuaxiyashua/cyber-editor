# 临时讨论：相业架构层级细节与运行机制

> 状态：临时讨论稿，不是当前真相源。
>
> 合并条件：只有当本稿中的层级边界、文件契约、风险治理、藏管理和并发机制经过讨论确认后，才可吸收到 `00-当前真相源-人工智能软件社会相业架构.md`。

## 0. 本稿目标

本稿解决一个问题：如何从最简单的相业关系，逐步演进成可运行、可治理、可复盘、可迁移的软件社会。

根律仍然保持简单：

1. 相承载稳定存在。
2. 业改变相。
3. 业由因起，向愿而行。
4. 律定边界，法成能力，位明责任，行者承业而行。
5. 果必须携证，证入藏，藏再成为新因缘。
6. 人是愿主、授权源和最高裁决源。

任何新增层级、机制、文件、调度策略，都只是这些根律的展开，不能变成新的根概念。

## 1. 前沿趋势边界

这里的前沿趋势不是照搬外部框架，而是抽取对本架构有边界作用的工程事实。

本稿在 2026-05-12 参考的前沿基线：

- JSON Schema Core：schema 应声明方言、标识符、引用和结果结构。
- Semantic Versioning：公开契约需要明确破坏性变更、兼容新增和补丁修复。
- Model Context Protocol：工具和资源访问需要根目录边界、授权和宿主管辖。
- OpenAI 工具调用实践：工具参数应结构化、可严格校验，高风险调用应受安全门控。
- LangGraph 持久化与可恢复执行：长运行状态需要检查点、恢复、人类介入和重放能力。

| 趋势 | 对相业架构的要求 |
|---|---|
| 结构化契约成为默认 | 相、业、律、证、藏必须有 schema，不能只靠自然语言解释 |
| 可恢复执行成为底座 | 任何长业都必须能暂停、恢复、重放、拒收，不能只靠会话上下文 |
| 高风险工具调用需要人类确认 | 外部副作用、写文件、删除、花钱、发消息等必须先形成可审查的待授权业 |
| 根目录和能力边界由宿主管辖 | 行者不能靠自觉守边界，文件根、工具能力和外部资源必须由运行底座拦截 |
| 追踪和评估成为生产能力 | 不能只看最终果，必须能评估每次行、工具调用、拒收、升级和仲裁 |
| 版本兼容必须显式化 | 法、律、位、业模板、schema 都要有版本和迁移策略 |
| 非可信因相必须隔离 | 外部网页、用户粘贴、第三方文档不能直接进入高权限上下文，只能先结构化抽取 |
| 大模型更强但仍会犯错 | 架构不能假设模型一次正确，必须用证、拒收、复验、风险升级和小范围迭代兜底 |

因此，相业架构不能退化成“一个更聪明的行者”。它必须成为一个能够装载更强模型、更多工具、更复杂协作，同时仍保持可控的外骨骼。

## 2. 从最小相业开始演进

### 2.1 零阶：只有相

最小系统只有文件：`.软件社会/相/因/`、`.软件社会/相/愿/`、`.软件社会/相/果/`。

这时系统只能保存东西，不能可靠改变东西。

能做：

- 保存用户表达。
- 保存目标草案。
- 保存结果草稿。

不能做：

- 证明结果从何而来。
- 判断谁有权修改。
- 追踪修改是否污染其他相。
- 让下游拒收。

### 2.2 一阶：加入业

加入 `业/` 后，系统有了最小变化单位。最小业只需要 `ye_id`、`schema`、`因`、`愿`、`律`、`行.status`、`果.expected`、`证.required`。

此时系统能回答：

- 为什么改。
- 要改成什么。
- 什么算完成。
- 哪些检查必须通过。

### 2.3 二阶：加入只追加证相

单业仍会出现“自称完成”。因此加入 `相/证/事件流/`，把扫描、验收、拒收、授权、审计都保存为只追加证相。只追加证相不覆盖旧事实，每条至少包含 `event_id`、`ye_id`、`kind`、`result`、`created_at`。

此时系统开始具备复盘能力。

### 2.4 三阶：加入律、位、法、行者

当业变复杂，需要拆开四件事：

| 概念 | 解决的问题 |
|---|---|
| 律 | 什么不能做、什么必须升级、什么算失败 |
| 位 | 从哪个责任视角判断 |
| 法 | 用什么可复用方法成事 |
| 行者 | 谁或什么承接本次行 |

一个业可以让多个行者处于多个位共同承接，例如同时引用 `文档架构位`、`反方评审位`、`术语一致性扫描法`、`影响面扫描法`、`small-model-scan` 和 `frontier-model-review`。

关键点：不是行者组织世界，而是业根据因、愿、律、位、法召行者。

### 2.5 四阶：加入业网

多个业开始互相引用，例如：`显影业 -> 设计业 -> 写作业 -> 评审业 -> 清理业 -> 下游拒收业`。

但业网不是固定路线。它是事实发生后的关系投影：

- 一个业可以派生多个业。
- 一个业可以拒收另一个业的果。
- 一个业可以修正另一个业的果。
- 一个仲裁业可以裁决多个业的冲突。
- 一个风险升级业可以把判断交给更高位。

主动运行时可以采用有向关系，但不能让路线图压过业本身。

### 2.6 五阶：加入藏、信、险、镜

复杂系统必须沉淀：

| 概念 | 加入原因 |
|---|---|
| 藏 | 防止重复尝试，保存经验、偏好、环境事实、失败复盘 |
| 信 | 记录某个行者、法、位在特定条件下是否可靠 |
| 险 | 累积多个小风险，防止局部安全合成全局危险 |
| 镜 | 把复杂运行状态投影给人类，让人知道何时介入 |

至此，相业架构从单文件变化演进成软件社会。

## 3. 层级设计

这里的层不是新的根概念，而是实现时的责任边界。每一层都只处理相和业。

### 3.1 文件相层

职责：

- 保存所有可迁移存在。
- 保证每个相有稳定路径、版本、摘要和状态。
- 保证同一个事实不会散落成多个互相冲突的真相源。

主要目录包括：`相/因/`、`相/愿/`、`相/律/`、`相/位/`、`相/法/`、`相/行者/`、`相/果/`、`相/证/`、`相/藏/`、`相/镜/`、`相/信/`、`相/险/`。

必须提供：

- `xiang_id`
- `schema`
- `version`
- `status`
- `created_at`
- `updated_at`
- `source_refs`
- `supersedes`
- `superseded_by`
- `checksum`

不能做：

- 直接执行变化。
- 自行判断完成。
- 覆盖只追加证相。

### 3.2 契约层

职责：

- 定义 schema。
- 定义状态机。
- 定义引用解析。
- 定义版本迁移。
- 定义缺字段恢复策略。

契约文件包括：`契约/schema/xiang.schema.json`、`契约/schema/ye.schema.json`、`契约/schema/lv.schema.json`、`契约/schema/zheng.schema.json`、`契约/state/ye-state.yaml`、`契约/state/xiang-state.yaml`、`契约/migration/xiangye.v0-to-v1.yaml`。

契约层必须回答：

- 这个文件是什么类型。
- 它使用哪个 schema 版本。
- 它引用的相如何解析。
- 缺字段时是拒收、补默认值，还是派生修复业。
- 版本不兼容时是否允许自动迁移。

不能做：

- 不经业直接修改业务内容。
- 用自然语言替代机器可检查字段。

### 3.3 业核层

职责：

- 创建业。
- 推进业状态。
- 挂载因、愿、缘、律、位、法、行者。
- 生成果和证。
- 派生后续业。
- 管理拒收、仲裁、升级。

业状态机主线是 `拟立 -> 待承接 -> 运行中 -> 待验收 -> 完成`；运行中可进入 `暂停/恢复/仲裁/升级/废弃`，待验收可进入 `拒收 -> 修正业`。

业核层最重要的边界：

- 业不是行者会话。
- 业不是固定路线节点。
- 业记录必须在行者替换后仍可继续。
- 高风险业必须先形成待授权果，再执行外部副作用。

### 3.4 行者适配层

职责：

- 把模型、会话、工具、脚本、人类专家、外部服务统一适配为行者。
- 管理行者能力、上下文、权限、成本、可靠性和隔离。
- 根据业的律和位选择行者。

行者相最小字段包括：`xiang_id`、`schema`、`type`、`capabilities`、`context_policy`、`tool_policy.filesystem_roots`、`tool_policy.write_requires_approval`、`trust.default_level`。

不能做：

- 自己成为真相源。
- 私自扩大文件根。
- 私自调用高风险工具。
- 把未验证因相放进高权限上下文。

### 3.5 治理层

职责：

- 执行根律。
- 执行权限律、风险律、质量律、成本律、安全律。
- 管理授权、拒绝、升级、冻结和审计。

治理层不是一个特殊大脑。它本身也由相和业组成：

- 律相：定义边界。
- 授权业：请求人类或高位行者授权。
- 风险评估业：计算险。
- 仲裁业：处理冲突。
- 审计证：记录谁在何时批准了什么。

治理层必须在运行底座强制执行，不能只显示在界面上。

### 3.6 沉淀层

职责：

- 管理藏、信、险、证。
- 控制哪些经验可被检索。
- 控制哪些经验已经过时。
- 防止藏污染和负迁移。

沉淀层的核心不是“记住更多”，而是：

- 只把通过证支撑的内容沉淀为藏候选。
- 只有适用范围明确的藏才能被自动检索。
- 过期、冲突、低信内容必须降权。
- 每次引用藏都要记录使用痕迹。

### 3.7 镜层

职责：

- 给人类展示系统状态。
- 呈现当前业、风险、分歧、待授权项、证链和下游影响。
- 支持人类插手、暂停、授权、拒绝、裁决。

镜层不能做：

- 成为真相源。
- 隐藏风险。
- 用绿色状态替代证。
- 把人类变成频繁点击的审批机器。

镜层应该让人类看到：

- 系统为什么这样做。
- 哪些判断已经有证。
- 哪些判断仍是推测。
- 当前风险为什么升级。
- 如果不介入会发生什么。

### 3.8 联邦与迁移层

职责：

- 打包和迁移法、位、律、业模板、证样本、评估集。
- 管理版本、兼容性、签名、来源和信任等级。
- 支持多个超级个体协作。

可迁移单元不应叫“大能力集合”。应该拆成：

| 可迁移相 | 内容 |
|---|---|
| 法包 | 一组方法、模板、操作步骤、适用边界 |
| 位包 | 一组职责位置、验收权、上报条件 |
| 律包 | 一组机器可执行律和人类可读根律说明 |
| 业模板 | 常见业的最小结构和验收证 |
| 评估包 | 反例、样本、验收题、红队题 |
| 藏种子 | 可选的经验沉淀，必须带来源和适用范围 |

## 4. 关键运行机制

### 4.1 藏管理机制

藏的生命周期是：`候选 -> 待证 -> 可检索 -> 被引用 -> 衰减 -> 过期 -> 清理 / 重验`。

藏相最小字段包括：`xiang_id`、`schema`、`claim`、`source_refs`、`scope.applies_to`、`confidence`、`expires_when`、`supersedes`、`negative_examples`。

藏管理必须有四个拦截点：

1. 入藏前：没有证，不能入藏。
2. 检索时：范围不匹配，不能装载。
3. 使用时：必须记录哪个业引用了它。
4. 修改后：影响面扫描业必须判断旧藏是否过期。

防止负迁移：

- 藏不能全局默认生效。
- 藏必须有适用范围。
- 藏必须有反例。
- 藏必须有过期条件。
- 相互冲突的藏必须触发仲裁业。

### 4.2 律与权限机制

律分三层：

| 层级 | 内容 | 谁能改 |
|---|---|---|
| 根律 | 人类价值、不可越界事项、最高授权边界 | 人类 |
| 运行律 | 文件根、工具权限、成本阈值、风险阈值 | 人类授权的治理业 |
| 业律 | 本次业的质量线、拒收条件、交付边界 | 立业者或授权行者 |

权限执行必须采用“先预览，后授权，再执行”：

```text
拟行 -> 生成预览果 -> 风险评估 -> 授权 / 拒绝 / 编辑 -> 执行 -> 留证
```

高风险操作不能直接执行：

- 删除文件。
- 批量改写。
- 对外发送。
- 付款。
- 发布。
- 调用外部高敏服务。
- 读取敏感根目录。

授权证必须绑定：

- 授权人。
- 授权时间。
- 授权对象。
- 预览摘要。
- 参数摘要。
- 有效期。
- 是否一次性。
- 执行后的证。

### 4.3 文档防污染机制

文档污染的典型形式：

- 新旧术语混用。
- 当前真相源和历史文档并列生效。
- 修改主文档但入口未改。
- 修改概念但案例未改。
- 旧藏继续被检索。
- 示例仍引用废弃路径。

每次重要文档修改必须派生四个业：

| 业 | 目的 |
|---|---|
| 影响面扫描业 | 找出受影响文件、目录、引用、案例、入口 |
| 术语一致性业 | 扫描旧词、同义词、反例、混用表述 |
| 下游消费检查业 | 检查入口、索引、临时稿、历史稿是否会误导 |
| 藏清理业 | 标记旧藏过期、被取代或需要重验 |

写文档不能只改可见段落。必须同时处理：

- 当前文件。
- 入口文件。
- 引用路径。
- 示例。
- 对比表。
- 历史归档说明。
- 藏相。
- 质量证。

### 4.4 风险累积与逐级上报

风险不是单次业字段，而是险相累积。

险相最小字段包括：`xiang_id`、`schema`、`risk_type`、`local_level`、`cumulative_level`、`sources`、`impact`、`threshold_hit`、`required_escalation`。

风险累积律：

| 条件 | 结果 |
|---|---|
| 单业低风险，但连续修改同一真相源 | 累积为中风险 |
| 多个低风险业共同影响入口、 schema 或根律 | 累积为高风险 |
| 涉及删除、发布、付款、外部承诺 | 直接高风险 |
| 影响多人协作或长期决策 | 至少中风险 |
| 行者低信且任务高影响 | 升级 |

逐级上报链是：`原子行者 -> 专业位行者 -> 统筹位行者 -> 仲裁位行者 -> 人类愿主`。

解释：

- 原子行者适合小范围、低风险、可验证动作。
- 专业位行者负责专业判断。
- 统筹位行者负责跨文件、跨业、跨目标影响。
- 仲裁位行者负责冲突裁决，但必须受根律和人类授权管辖。
- 人类愿主是最高裁决源。实现时可以把人类投影为最高位行者，但概念上人不是普通行者资源。

上报必须携带：

- 发生了什么。
- 为什么当前层级不能决策。
- 有哪些候选方案。
- 每个方案的风险。
- 不决策的后果。
- 推荐方案和反方意见。

### 4.5 文件并发机制

文件驱动系统必须正视并发。否则多个业会同时改同一相，造成真相分叉。

最低机制：

| 机制 | 作用 |
|---|---|
| 相版本号 | 判断写入时是否基于最新版本 |
| 校验摘要 | 防止无感覆盖 |
| 写前锁 | 防止两个业同时写同一相 |
| 写后证 | 记录本次变化 |
| 只追加证相 | 防止历史被覆盖 |
| 合并业 | 处理并发修改冲突 |
| 仲裁业 | 处理无法自动合并的冲突 |

写入协议是：`读取相版本 -> 生成修改预览 -> 获取写锁 -> 校验版本未变 -> 写入新版本 -> 追加证相事件 -> 释放锁`。如果版本已变，则 `停止写入 -> 生成冲突证 -> 派生合并业 -> 必要时升级给更高位`。

禁止：

- 行者直接覆盖文件。
- 无证合并。
- 把运行日志当最终相。
- 把失败写入吞掉。

### 4.6 质量与一次做对机制

一次做对不是一次生成完美，而是让错误在最小范围内被发现。

质量律至少分四级：

| 等级 | 要求 |
|---|---|
| 格式线 | schema、表格、链接、路径、字段通过 |
| 语义线 | 概念一致、无明显冲突、能被下游消费 |
| 证线 | 关键判断有证，假设和未验证点显式标出 |
| 反方线 | 高价值果经过反方攻击或下游拒收测试 |

携证之果必须说明：

- 引用了哪些因。
- 依赖哪些缘。
- 受哪些律管辖。
- 谁以什么位、用什么法完成。
- 哪些判断有证。
- 哪些地方只是推测。
- 下游如何使用。
- 下游如何拒收。

### 4.7 非可信因相隔离机制

非可信因相包括：

- 网页内容。
- 第三方文档。
- 用户粘贴的大段文本。
- 外部工具返回。
- 历史过时文档。
- 低信行者生成的果。

处理律：

1. 非可信因相只能进入低权限解析业。
2. 解析业只产出结构化字段，不产出高权限指令。
3. 高权限业只能读取结构化后的候选因相。
4. 外部文本不得直接进入根律、运行律或高权限行者上下文。
5. 如果外部文本影响工具调用，必须先经过风险评估和授权。

### 4.8 可恢复执行机制

长业不能靠一段会话活着。检查点至少包括：业状态检查点、行者上下文摘要、已完成行记录、副作用执行证、待授权项、失败原因、恢复入口。

恢复律：

- 已有证的副作用不能重复执行。
- 未完成行可以重试。
- 不确定是否完成的行必须派生核查业。
- 高风险恢复必须先进入待授权状态。
- 恢复后必须追加恢复证。

### 4.9 评估与回归机制

每个重要法、律、位、业模板都应有评估集。

评估集包括：

- 正例。
- 反例。
- 边界样本。
- 历史失败样本。
- 对抗样本。
- 人类裁决样本。

评估不只评果，也评运行轨迹：

- 是否越权。
- 是否遗漏因。
- 是否引用过时藏。
- 是否没有上报风险。
- 是否没有保留证。
- 是否把低信结论当事实。

### 4.10 非用户日志系统

日志系统是必要的非用户功能，但不是新的根概念。它的职责是支持排障、性能分析、安全审计、恢复和运行观测；只有被业引用、被验收或被风险评估命中的日志片段，才会提升为证相、险相或信相。

日志分层：

| 日志类 | 主要用途 | 是否默认进入真相 |
|---|---|---|
| 调试日志 | 开发排障、定位异常分支 | 否，只短期保留 |
| 运行日志 | 记录业状态推进、行者调用、工具调用、重试 | 否，命中问题后可提升为证相 |
| 审计日志 | 记录授权、拒绝、越权拦截、高风险预览和执行 | 是，以审计证形式保存 |
| 安全日志 | 记录敏感根访问、外部调用、脱敏、阻断 | 是，必要时生成险相 |
| 性能日志 | 记录耗时、成本、上下文大小、重试次数 | 否，聚合后可生成信相或险相 |
| 质量日志 | 记录质量门、拒收、反方评审、回归结果 | 是，以质量证形式保存 |

日志事件最小字段：

| 字段 | 含义 |
|---|---|
| `event_id` | 日志事件唯一标识 |
| `time` | 发生时间 |
| `level` | `debug/info/warn/error/security/audit` |
| `kind` | 事件类型，如 `tool_call`、`approval`、`quality_gate` |
| `ye_id` | 关联业，没有则为空 |
| `xiang_refs` | 关联相 |
| `actor_ref` | 关联行者或人类授权者 |
| `action_ref` | 关联行 |
| `summary` | 人类可读摘要 |
| `payload_ref` | 大载荷位置，不直接塞进日志主记录 |
| `sensitive` | 是否包含敏感信息 |
| `retention` | 保留策略 |
| `promote_to` | 是否提升为证相、险相或信相 |

日志系统必须遵守：

1. 日志默认不是相业真相源，只是运行底座的观测材料。
2. 审计、安全、质量类日志一旦影响裁决，必须提升为证相。
3. 敏感日志必须脱敏、分级、限权，不能直接暴露给普通行者。
4. 大模型上下文不能无差别塞入完整日志，只能通过检索、摘要和证相引用进入业。
5. 日志必须有轮转、压缩、过期和导出策略，防止无限增长。
6. 日志写入失败不能静默吞掉；若影响审计或恢复，必须阻断高风险业。
7. 日志不能替代证。证必须说明它证明什么，日志只说明发生过什么。

日志到相业的提升路径：

| 触发条件 | 派生业 | 生成相 |
|---|---|---|
| 工具调用失败 | 失败归因业 | 失败证 |
| 授权被拒绝 | 授权复盘业 | 审计证 |
| 多次重试超阈值 | 风险评估业 | 险相 |
| 某行者连续低质量 | 信评估业 | 信相 |
| 敏感根访问被拦截 | 安全审计业 | 安全证、险相 |
| 性能持续恶化 | 性能诊断业 | 性能证、优化候选业 |

日志系统和镜层的关系：

- 日志面向开发者、运维者和治理业。
- 镜面向人类愿主和协作者。
- 镜可以展示日志摘要、异常趋势和待决策点，但不能把原始日志直接当成人类可读真相。
- 高风险场景下，镜必须显示“哪些日志已提升为证，哪些只是辅助材料”。

## 6. 必须补充但尚未定稿的问题

### 6.1 调度权到底在哪里

候选答案：

1. 调度权属于业核层。
2. 调度权属于特殊位行者。
3. 调度权本身也是一种业。

建议：调度不是根概念。调度应表现为一组治理业、派生业和授权业。实现时可以有调度服务，但概念上不能把调度服务变成新的上帝。

### 6.2 业网是否允许环

建议：

- 引用关系允许形成环，因为现实复盘和修正可能互相引用。
- 主动执行链必须有边界：预算、深度、时间、收敛条件、风险阈值。
- 若同一业反复派生修正业，必须触发停机评审业。

也就是说，存储层可以有环，运行层必须有可停止机制。

### 6.3 高位行者如何避免权力过大

高位行者越有全局观，越可能形成新的集中失败点。

防守方式：

- 高位行者只能裁决给定问题，不能无限扩大范围。
- 高位裁决必须携证。
- 高位裁决必须可被人类复查。
- 高位行者的信用也会下降。
- 人类可以冻结高位行者。

### 6.4 藏和证如何避免膨胀

必须有清理业：

- 删除无引用临时相。
- 降权低信藏。
- 合并重复藏。
- 标记过期证。
- 对长期未使用法进行冷藏。

清理不能实际抹除审计证事件，只能改变可检索状态。

### 6.5 法包、位包、律包如何共享

临时判断：

- 共享包必须声明 schema 版本。
- 共享包必须声明适用范围和不适用范围。
- 共享包必须带反例。
- 共享包必须带最小评估集。
- 共享包导入后默认低信，必须经过本地试用才升信。

## 7. 演进路线

### 7.1 第一阶段：单机最小闭环

目标：

- 相文件可保存。
- 业文件可创建。
- 果必须携证。
- 旧术语、链接、表格、schema 可检查。
- 调试日志、运行日志和质量日志可本地保留。

不做：

- 多行者复杂协作。
- 联邦共享。
- 自动长期优化。

### 7.2 第二阶段：治理闭环

目标：

- 文件根边界。
- 工具授权。
- 风险累积。
- 高风险暂停。
- 人类裁决镜。
- 审计日志、安全日志可提升为证相或险相。

不做：

- 全自动执行外部副作用。

### 7.3 第三阶段：藏和信

目标：

- 藏候选。
- 藏入库。
- 藏检索。
- 藏过期。
- 行者和法的场景化信用。

不做：

- 假装长期成长一定有效。

### 7.4 第四阶段：多行者协作

目标：

- 原子行者处理小业。
- 专业行者处理专业业。
- 统筹行者处理跨域业。
- 仲裁业处理冲突。

不做：

- 多行者聊天剧场。

### 7.5 第五阶段：可迁移软件社会

目标：

- 法包、位包、律包、业模板、评估包可分享。
- 包导入后低信试运行。
- 不同超级个体之间可以交换可验证果和证。

不做：

- 把别人的经验无条件当成本地真相。

## 8. 当前最小可讨论结论

1. 相和业仍是唯一根结构。
2. 层级只是实现剖面，不是新本体。
3. schema、生命周期、反例必须写进真相源。
4. 更细的运行机制应先在临时稿讨论，成熟后再合并。
5. 藏管理、律权限、文档防污染、风险累积、逐级上报、文件并发、非用户日志系统，是第一批必须解决的运行机制。
6. 高风险必须逐级上报，更有全局观的行者只能在受律和证管辖下裁决；最高裁决源仍是人类。
7. 文件驱动不是简单把内容写成 Markdown，而是所有相、业、证、律、状态、授权、风险都必须有可迁移文件表达。
