# 当前真相源：人工智能软件社会相业架构

> 本文是 `truth/` 当前真相源。它替代此前以“帧”为核心的旧表达，但保留核心目标：让人类以愿望、品味和授权撬动 AI 组织，扩展能力边界，释放体力劳动，连接多个超级个体。

## 0. 一句话

人工智能软件社会不是“智能体聊天室”，也不是“自动化流程平台”，而是一个以文件为可迁移载体、以工作契约为变化核心、以证据和质量为闭环的外骨骼系统。

用新的术语说：

> 人起愿，相承载世界，业推动变化，行者承业而行，法提供能力，律约束边界，果必须携证，证入藏并反过来成为新的因缘。

本文中的佛教式命名只是工程隐喻，不引入宗教判断。命名目标是让抽象足够统一、可组合、可扩展，并避免旧词如 `agent`、`flow`、`skill`、`role` 带来的既有误解。

## 1. 为什么要从“帧元”改为“相业”

旧文档把核心称为“工作帧”。这个方向是正确的：系统不应以固定流程或长期智能体为根，而应以一次次可验证工作为核心。

但“帧”这个词有三个问题：

1. 它像图像帧，容易被误解成流程节点或 UI 卡片。
2. 它不天然表达责任、后果、证据和质量。
3. 它容易被继续扩展成九项表单，导致最小单元变胖。

讨论后我们将核心概念改为 `业`：

> 业 = 一次有原因、有目标、有条件、有边界、有方法、有执行、有结果、有证据的可验证工作契约。

这个命名更贴近本质：

- 它不是执行者。
- 它不是流程节点。
- 它不是上下文包。
- 它是让稳定存在发生变化的一次工作契约。

同时，旧“物”改为 `相`：

> 相 = 一切可保存、可引用、可呈现、可迁移、可比较的稳定存在。

最终根模型不是 `帧 + 物 + 执行者`，而是：

> 一切稳定存在皆为相；一切相之变化皆由业发生。

行者、位、法、律、藏、证、果都可以是相；它们的生成、修改、验证、废弃才是业。

## 2. 根规则

相业架构只保留五条根规则：

| 规则 | 说明 |
|---|---|
| 一切可被保存和引用者，皆为相 | 文档、代码、记忆、证据、Agent 会话、角色配置、能力包、风险记录都是相 |
| 一切相之变化，皆由业发生 | 创建、修改、验证、废弃、合并、迁移、评审都必须通过业 |
| 业由因起，向愿而行 | 输入信息和目标意图必须分开，不能混成一个字段 |
| 业受律约束，依位召行者，用法而行 | 规则、职责、执行代理、能力方法必须分离 |
| 行成其果，果必有证，证入藏 | 结果必须可验收、可追溯、可复盘，经验沉淀后成为新因缘 |

这套规则不要求“一切都是业”。准确说法是：

> 一切变化都由业发生，一切结果都沉淀为相。

## 3. 核心术语

### 3.1 总表

| 新名 | 旧概念 | 定义 | 不是 |
|---|---|---|---|
| 人 | 人类价值源 | 愿望、品味、授权、责任、最终裁决的源头 | 不是系统内普通相，不是被 AI 管理的资源 |
| 相 | 物 / 对象 / 文件化存在 | 可保存、可引用、可呈现、可迁移的稳定存在 | 不主动改变自己 |
| 业 | 帧 / 工作契约 | 让相发生变化的一次可验证工作契约 | 不是 Agent，不是流程节点 |
| 因 | 输入 / 触发 / 张力 | 用户表达、情绪、痛点、问题种子、材料、冲突、环境信号 | 不是目标 |
| 愿 | 目标 / 意图 | 本次业想达成的目的、方向、所求 | 不是输入材料 |
| 缘 | 条件 / 上下文 / 资源 | 支持业发生的环境、依赖、上下文、可用资源、时机 | 不是业本身，不是变换动作 |
| 律 | 规则 / 约束 / 治理 / 质量边界 | 权限、风险、质量、成本、伦理、边界、不可越界事项 | 不是能力方法 |
| 位 | Role / 职责位置 | 行者承接某个业时所处的责任位置和判断视角 | 不是 Agent 本体 |
| 法 | Skill / 方法论 / 能力包 | 可复用的技能、方法、工具链、模板、套路、规程 | 不是规则边界 |
| 行者 | Agent / 执行代理 | 可承接业并执行行的代理，会话、模型、人、工具、脚本、服务都可成为行者 | 不是业的真相源 |
| 行 | 变换 / 执行动作 | 实际发生的推理、调用、生成、修改、评审、仲裁、迁移 | 不是条件 |
| 果 | 输出 / 产物 | 业成熟后产生的结果、方案、代码、文档、决策、状态变化 | 不等于可信完成 |
| 证 | 证据 / 凭证 / 验收 | 为什么相信果成立、失败或需要降级的依据 | 不等于漂亮解释 |
| 藏 | 记忆 / 经验库 / 证据沉淀 | 证、经验、偏好、环境知识、失败复盘的沉淀处 | 不是永远正确的真理库 |
| 镜 | 人类可读投影 | 把复杂相和业网投影成人能理解的进度、风险、决策视图 | 不拥有真相 |

### 3.2 因和愿必须拆开

旧表达容易把输入信息和目标意图合并成“意图”。这会导致一个根本错误：系统分不清“发生了什么”和“想达成什么”。

| 项 | 含义 | 示例 |
|---|---|---|
| 因 | 触发业的材料、张力、痛点、表达、情绪、环境事实 | “我觉得架构不对”“文档看不懂”“代码和文档冲突” |
| 愿 | 本次业希望走向的目标 | “找到更简单的抽象”“让文档成为未来重构真相源” |

同一个因可以导向不同愿：

- 用户说“这个文档不对”。
- 愿一：找出文档漏洞。
- 愿二：重写文档。
- 愿三：设计评审机制。
- 愿四：暂停设计，回到意图澄清。

如果不拆开，AI 会直接把用户表达当任务，导致过早执行、方向错误、反复返工。

### 3.3 缘不是业

`缘` 只表示促成业发生的条件，不表示整个工作契约。

缘可以包括：

- 当前可见上下文。
- 可调用模型。
- 可用工具。
- 已存在证据。
- 可用预算。
- 依赖关系。
- 外部时机。
- 上下游相。

因此，不能把旧“帧”直接改叫“缘”。旧“帧”更接近 `业`，而不是 `缘`。

### 3.4 行者不是模型

行者不是单纯模型。用户所说的 Agent 更接近这里的 `行者`：

> 行者 = 模型 + 会话上下文 + 工具权限 + 当前状态 + 可承接业的代理身份。

例如：

- 一个 GPT 会话。
- 一个 Claude 项目会话。
- 一个本地脚本。
- 一个代码搜索工具。
- 一个外部 API。
- 一个真实人类专家。
- 一个自动测试运行器。

但行者本身仍然是相。行者可以被记录、比较、授权、禁用、替换、评估。真正推动变化的是业。

### 3.5 位不是角色扮演

`位` 取代旧 `Role`。它不是人格设定，而是职责位置。

同一个行者可以在不同业中处于不同位：

| 行者 | 业 | 位 |
|---|---|---|
| GPT 会话 A | 攻击架构方案 | 反方评审位 |
| GPT 会话 A | 重写文档 | 文档架构位 |
| 人类用户 | 裁决方向 | 愿主位 |
| 测试脚本 | 验证 Markdown 链接 | 校验位 |

位定义的是：

- 看什么。
- 对什么负责。
- 不能越过什么边界。
- 何时必须上报。
- 用什么标准判断。

### 3.6 法不是规则

`法` 取代旧 `Skill`，也包含方法论。

法是可复用的履约能力：

- 架构攻击法。
- 意图显影法。
- 代码反哺文档法。
- 风险评估法。
- 对抗评审法。
- 迁移切片法。
- 文档排版法。
- 自动测试法。

规则不叫法，规则叫 `律`。否则“能力方法”和“禁止边界”会混淆。

### 3.7 律包含质量，但不等于质量

律是边界系统。它包括：

- 权限律：谁能做什么。
- 风险律：什么情况必须升级。
- 质量律：什么算好、什么硬失败。
- 成本律：预算、时间、资源上限。
- 安全律：隐私、外部副作用、不可逆操作。
- 根律：人类写入、AI 只读的最高约束。

质量不再叫“质量契约”作为根概念，而是质量律的一部分。某个业可以引用一个或多个质量律。

## 4. 业的结构

### 4.1 标准业

标准业的结构是：

| 组成 | 必须回答的问题 |
|---|---|
| 因 | 这次业因何而起，输入和张力是什么 |
| 愿 | 本次业要达成什么，不达成什么 |
| 缘 | 当前有哪些上下文、资源、依赖、时机 |
| 律 | 权限、风险、质量、成本、边界是什么 |
| 位 | 需要什么职责位置来承接判断 |
| 法 | 可用什么方法、技能、模板、工具链 |
| 行者 | 谁或什么来承接本次业 |
| 行 | 实际如何变换、生成、修改、评审、仲裁 |
| 果 | 产生什么结果，给谁使用 |
| 证 | 为什么相信果成立，失败或降级如何记录 |

简化表达：

> 业由因起，向愿而行；缘助其成，律定其界；行者依位用法，行成其果，果必有证。

### 4.2 轻量业、标准业、高风险业

不是每个业都要填满大表。否则架构会拖死执行。

| 等级 | 适用场景 | 最低要求 |
|---|---|---|
| 轻量业 | 低风险、可逆、局部、小成本动作 | 因、愿、律、果、证 |
| 标准业 | 需要交接、复盘、下游依赖的工作 | 因、愿、缘、律、位、法、行、果、证 |
| 高风险业 | 高成本、不可逆、外部副作用、影响多人或长期决策 | 标准业 + 风险积累 + 独立验收 + 人类授权或仲裁 |

“一次做对”不是一次生成完美，而是用匹配风险等级的业结构，避免错误扩大。

### 4.3 携证之果

果不能只是输出文本。可信果必须携证。

一个携证之果至少说明：

- 引用了哪些因。
- 依赖哪些缘。
- 遵守哪些律。
- 由哪个行者以什么位、用什么法完成。
- 哪些判断有证据。
- 哪些判断只是推测。
- 哪些地方未验证。
- 下游如何消费。
- 失败时如何拒收、重做或降级。

这解决的是 AI 常见问题：新生成时看似完整，修改时顾此失彼，留下大量过时幻觉。

## 5. 相的分类

相不是死物。它是一切可保存、可引用、可呈现的稳定存在。

| 相类 | 内容 |
|---|---|
| 因相 | 用户表达、情绪、痛点、张力、环境事实、问题材料 |
| 愿相 | 本愿、阶段愿、业愿、取舍偏好 |
| 律相 | 根律、权限律、风险律、质量律、成本律、安全律 |
| 位相 | 愿主位、架构位、反方位、执行位、校验位、仲裁位 |
| 法相 | 方法论、能力包、工具链、模板、脚本、评审套路 |
| 行者相 | Agent 会话、模型、工具、人类专家、脚本、外部服务 |
| 果相 | 文档、代码、方案、数据、决策、状态变更 |
| 证相 | 引用、测试、评审、验收、拒收、失败记录 |
| 藏相 | 记忆、经验、偏好、失败复盘、环境知识 |
| 镜相 | 给人类看的进度、风险、证据、决策点和组织状态 |
| 信相 | 行者、法、位、果在特定条件下的历史可信度 |
| 险相 | 风险记录、风险积累、不可逆动作、外部副作用 |

所有相都可以作为业的因、缘、律、法、位、果或证被引用。

## 6. 业网，而不是 Flow

本文不再保留 `Flow` 作为根概念。

传统 Flow 的问题是：

- 容易先画固定流程，再把工作塞进去。
- 容易把节点成功当成真实成功。
- 容易将复杂协作压成单向自动化管线。
- 容易让人类变成审批节点，而不是愿源和裁决者。

相业架构只保留 `业网`：

> 业网 = 多个业通过因、缘、果、证、律、拒收、修正、仲裁、升级等关系自然形成的引用网络。

业网不是根对象，而是关系投影。

业之间可以有这些关系：

| 关系 | 含义 |
|---|---|
| 引用 | 一个业引用另一个业的果或证 |
| 派生 | 一个业生成后续业 |
| 评审 | 一个业检查另一个业的果 |
| 拒收 | 下游业声明上游果不可用 |
| 修正 | 新业修正旧业之果 |
| 仲裁 | 仲裁业裁决多个业之间的冲突 |
| 升级 | 风险、价值、授权问题升级给更高位或人类 |
| 废弃 | 果或藏被标记为过时、冲突或不再适用 |

运行时看起来可能像流程图，但本质不是 Flow 驱动，而是：

> 业引用业，业生成业，业评审业，业修正业，业约束业。

## 7. Agent 驱动与业驱动的区别

用户对 Agent 的理解是正确的：Agent 不是模型，而是带独立上下文、角色、工具、边界和任务的代理会话。

在简单任务中：

> Agent + 契约文件 ≈ 一个业被一个行者承接。

此时两者差别不大。

差异出现在复杂协作中：

| 问题 | Agent 驱动 | 业驱动 |
|---|---|---|
| 工作状态在哪里 | 主要在 Agent 会话上下文 | 主要在业记录、果、证、藏中 |
| Agent 能否替换 | 替换后容易丢失上下文 | 可替换，只要业记录完整 |
| 多 Agent 如何协作 | Agent 之间对话协调 | 多行者承接同一业或派生业，结果回写同一业网 |
| 失败如何复盘 | 翻聊天历史 | 查因、愿、律、行、果、证 |
| 下游能否拒收 | 往往不明确 | 下游业可按律拒收果 |
| 质量标准在哪里 | Prompt 或 Agent 设定里 | 律相中，可被多个业复用 |
| 长期演化靠什么 | Agent 记忆 | 藏、证、信、险和相版本 |

一句话：

> Agent 驱动让代理推动工作；业驱动让工作契约调度代理。

业驱动不是不要 Agent，而是不让 Agent 会话成为系统唯一真相。

## 8. 运行机制

### 8.1 从人类模糊表达到业网

典型运行顺序：

1. 人发出表达：愿望、痛点、情绪、困惑、目标或命令。
2. 系统记录因相：保留原始表达，不急着解释成任务。
3. 显影业启动：追问、类比、反例、取舍测试，识别真实愿。
4. 立业：把本次可执行变化写成业。
5. 配缘：挂载必要上下文、资源、依赖、历史和可用行者。
6. 奉律：引用根律、质量律、风险律、权限律。
7. 定位：选择需要的位，如架构位、反方位、执行位、仲裁位。
8. 取法：选择可用方法论、技能包、工具链。
9. 召行者：选择 Agent 会话、模型、脚本、工具、人类专家或外部服务。
10. 行：执行变换。
11. 成果：生成果相。
12. 留证：验收、测试、引用、拒收、失败、降级都写入证。
13. 入藏：可复用经验进入藏，过时内容打废弃标记。
14. 投镜：将进度、风险、决策点呈现给人类。
15. 继续生业：果、证、藏成为新业的因缘。

### 8.2 人类什么时候介入

人类不是每个步骤的审批员。人类介入点应集中在：

| 场景 | 为什么必须介入 |
|---|---|
| 愿不清 | 系统无法判断用户真正想要什么 |
| 价值冲突 | 涉及取舍、品味、人生方向、组织方向 |
| 授权边界 | 需要花钱、发布、删除、对外承诺、访问敏感资源 |
| 不可逆风险 | 影响外部世界或难以回滚 |
| 高分歧 | 多个行者、多个位或多个法得出强冲突结论 |
| 长期承诺 | 影响未来组织、产品、法律、伦理或声誉 |

人类是愿主，不是流程节点。

### 8.3 根律与机器可执行律

自然语言根律给人看，但不能直接当运行时硬约束。

例如：

| 人类可读根律 | 机器可执行律 |
|---|---|
| 不要破坏用户资产 | 禁止无备份删除指定路径；修改前必须生成检查点 |
| 不要泄露隐私 | 敏感目录不可外发；外部 API 调用前必须脱敏或请求授权 |
| 高风险需要确认 | 成本超过阈值、对外发布、删除、支付、发送消息必须暂停 |
| 质量不能靠自称完成 | 高风险果必须有独立证、下游可拒收、人类可抽检 |

根律由人类写入，AI 只读。普通业不能修改根律；修改根律必须通过人类授权的启动级动作。

### 8.4 质量与拒收

质量不再是“优化一下”。质量属于律。

每个重要业至少要声明：

- 最低可交付线。
- 优秀标准。
- 硬失败条件。
- 谁能验收。
- 下游如何消费。
- 下游如何拒收。
- 失败后重做、拆分、换行者、升级还是停止。

下游拒收不是情绪反馈，必须基于律：

> 下游业只能以“上游果不满足哪条律、缺少哪类证、无法作为哪类因缘”为理由拒收。

拒收后可派生：

- 修正业。
- 仲裁业。
- 补证业。
- 拆分业。
- 升级业。
- 废弃业。

### 8.5 风险积累

风险不是单业字段，而是险相和险证的累积。

低风险业串联可能变成高风险：

- 多次小额调用累计成高成本。
- 多次局部修改累计成大范围架构漂移。
- 多个低敏信息组合成隐私泄露。
- 多次文档补丁累计成真相源混乱。

因此需要风险评估业：

| 输入 | 输出 |
|---|---|
| 当前业、上游果、下游依赖、历史失败、外部副作用 | 风险等级、升级要求、是否允许继续、是否需要人类授权 |

风险评估业也可以由行者执行，但不能绕过根律。

### 8.6 藏的污染与过时幻觉

AI 修改旧文件时常见问题是顾此失彼：

- 新章节改了，旧章节仍保留旧概念。
- 文档改了，目录和示例没改。
- 架构名改了，案例仍使用旧名。
- 旧记忆继续被检索，当成当前真相。
- 上下文里同时存在新旧定义，AI 混用。

因此，任何重要修改业必须派生两个辅助业：

| 辅助业 | 作用 |
|---|---|
| 影响面扫描业 | 找出概念、文件、示例、引用、目录、测试、记忆的影响范围 |
| 过时清理业 | 标记废弃、替代、仅适用于旧版本、与当前真相冲突、需要重验的藏相 |

藏不是永远正确的记忆库。每条藏相必须带：

- 来源。
- 版本。
- 适用范围。
- 置信度。
- 创建时间。
- 过期条件。
- 替代关系。
- 反例。
- 最近验证证据。

检索到的藏只能作为候选因缘，不能直接当事实。

## 9. 文件驱动形态

文件名是未来设计草案，不代表当前工程已经实现。

```text
.软件社会/
  根/
    根律.yaml                 # 人类写入，AI 只读
    启动录.yaml               # 启动来源、根律版本、首业创建记录

  相/
    因/                       # 用户表达、张力、问题、环境信号
    愿/                       # 本愿、阶段愿、业愿
    律/                       # 权限律、风险律、质量律、成本律、安全律
    位/                       # 愿主位、架构位、反方位、执行位、仲裁位
    法/                       # 技能、方法论、工具链、模板、规程
    行者/                     # Agent 会话、模型、工具、人类接口、服务
    果/                       # 文档、代码、方案、数据、决策、状态变化
    证/                       # 验收、测试、引用、拒收、失败、评审记录
    藏/                       # 记忆、经验、偏好、环境知识、失败复盘
    镜/                       # 人类可读进度、风险、决策点
    信/                       # 历史可信度、能力表现、责任归因
    险/                       # 风险记录、风险积累、外部副作用

  业/
    当前业网.yaml
    业实例/
    业模板/
    显影业/
    执行业/
    评审业/
    仲裁业/
    治理业/
    迁移业/
    清理业/

  录/
    证录.jsonl                # 只追加，记录果和证
    险录.jsonl                # 只追加，记录风险积累
    信录.jsonl                # 只追加，记录信用变化
    审计录.jsonl              # 只追加，记录谁在何时做了什么
```

这里有一个重要实现原则：

> 可读相可以被更新，但关键证录、险录、信录、审计录应只追加。

只追加记录不是新的根概念，而是为了避免 AI 修改时覆盖历史、制造过时幻觉、破坏追溯链。

| 项 | 内容 |

| 提供 | 进度、风险、分歧、证据、决策点、组织状态 |
| 不做 | 不拥有真相，不替代业、果、证和藏 |

## 11. 五个极端复杂场景案例

### 11.1 案例一：普通人发起家用机器人创业公司

用户表达：

> 我想做一个能赚钱的家用机器人，但我不懂硬件、供应链、融资、法规和市场。

#### 因

- 用户有创业冲动，但不清楚真正想解决什么痛点。
- 市场中存在老人照护、家务清洁、儿童陪伴、宠物照料等可能需求。
- 用户缺乏硬件、供应链、法规、融资经验。
- 技术趋势和成本结构不确定。

#### 愿

- 找到一个第一阶段可验证、可融资、可小规模落地的机器人产品切口。
- 不追求一次定义完整公司，而是先找到可验证的事业入口。

#### 关键相

| 相类 | 示例 |
|---|---|
| 因相 | 用户动机、目标人群痛点、竞品资料、成本约束 |
| 律相 | 资金上限、法规安全、隐私、儿童/老人安全、不可虚假融资承诺 |
| 位相 | 创业显影位、市场侦察位、硬件供应位、反方投资人位、产品架构位 |
| 法相 | 用户访谈法、竞品拆解法、成本估算法、法规扫描法、商业模型测算法 |
| 行者相 | 大模型创业顾问、硬件专家、人类用户、市场调研脚本、供应链 API |

#### 业网

| 业 | 主要作用 | 果 | 证 |
|---|---|---|---|
| 显影创业本愿业 | 找出用户到底想做产品、赚钱、改变行业还是证明自己 | 本愿说明 | 访谈记录、取舍题回答 |
| 痛点侦察业 | 找出高频付费场景 | 痛点地图 | 用户语料、竞品评论、价格证据 |
| 产品切口生成业 | 给出多个小切口 | 候选切口 | 需求、成本、法规、技术边界 |
| 反方投资评审业 | 攻击商业假设 | 失败清单 | 投资人视角反证 |
| 原型验证拆解业 | 把切口拆成低成本验证动作 | 原型路线 | 成本、时间、人力、风险 |
| 供应链可得性业 | 检查关键物料和制造路径 | BOM 风险表 | 供应商、交期、替代件 |
| 融资叙事生成业 | 在证据基础上形成融资故事 | 融资材料草案 | 不确定性声明、证据引用 |

#### 为什么相业架构有价值

传统 Agent 驱动容易让“创业顾问 Agent”直接写商业计划书。相业架构先显影本愿，再让市场、硬件、法规、融资、反方位分别承业，并把所有果和证沉淀到同一个创业业网。

关键不是多 Agent 聊天，而是每个商业判断都必须携证，且下游融资叙事不能吞掉上游风险。

### 11.2 案例二：百万行老系统重构并修复文档失真

用户表达：

> 这个系统太乱了，我想重构，但怕一改就炸，文档也不可信。

#### 因

- 代码规模巨大。
- 文档与代码冲突。
- 业务仍在运行。
- 测试不足。
- 团队没人敢承担全局重构责任。
- 历史上下文中存在大量过时记忆。

#### 愿

- 找到低风险、可验证、可回滚的重构路径。
- 同步修复代码、文档、测试和记忆，让后续 AI 不再基于旧幻觉继续工作。

#### 关键业

| 业 | 果 | 证 |
|---|---|---|
| 恐惧显影业 | 系统真正害怕什么 | 事故历史、热点文件、业务依赖 |
| 代码热点扫描业 | 高风险模块地图 | 变更频率、复杂度、调用关系 |
| 文档漂移扫描业 | 文档-代码冲突表 | 文档段落、代码入口、owner |
| 切片设计业 | 可闭环重构切片 | 回滚路径、测试缺口、影响范围 |
| 补测试业 | 重构保护网 | 测试命令、覆盖范围、失败日志 |
| 小范围重构业 | 局部改造结果 | diff、测试、运行证据 |
| 过时藏清理业 | 废弃或替换的记忆清单 | 新旧真相对照、替代证 |
| 下游拒收业 | 检查产物能否被后续业消费 | 拒收理由或通过证 |

#### 特别机制：防止 AI 修改顾此失彼

每次修改前必须派生：

- 影响面扫描业：找受影响文件、概念、测试、示例、记忆。
- 过时清理业：把旧说法标记为废弃、替代、仅适用于旧版本或需要重验。
- 携证之果检查业：确保新果说明引用、假设、未验证点和下游消费方式。

#### 为什么相业架构有价值

传统 Flow 会说“扫描 -> 设计 -> 重构 -> 测试”。但真实风险在于上下文污染和过时记忆。相业架构把代码、文档、测试、藏、证都作为相，把每次变化作为业，并要求果必携证。

这不是简单自动化，而是建立可持续重构社会。

### 11.3 案例三：跨城市灾害救援调度

用户表达：

> 三个城市同时受灾，物资、车辆、志愿者、医院容量都在变化，我要知道先救哪里、调什么、怎么避免乱。

#### 因

- 多地灾情实时变化。
- 信息来源真假混杂。
- 资源有限。
- 生命风险高。
- 道路和天气动态变化。
- 错误调度会造成不可逆后果。

#### 愿

- 在生命优先和证据可信前提下，形成可追溯、可调整、可授权的救援调度建议。

#### 关键律

| 律 | 内容 |
|---|---|
| 生命优先律 | 任何低价值目标不得压过生命风险 |
| 来源分级律 | 未验证消息不能直接触发高风险调度 |
| 人类确认律 | 涉及救援优先级冲突必须升级 |
| 可追溯律 | 每个调度建议必须说明数据来源和假设 |
| 次生风险律 | 不得为了局部救援制造更大拥堵或医疗挤兑 |

#### 业网

| 业 | 果 | 证 |
|---|---|---|
| 多源信号收集业 | 灾情因相池 | 来源、时间、可信等级 |
| 谣言与冲突识别业 | 可疑信息清单 | 交叉验证、冲突来源 |
| 需求缺口地图业 | 生命风险与物资缺口 | 医院容量、道路状态、求援密度 |
| 资源供给地图业 | 可调资源清单 | 库存、位置、可用时间 |
| 调度候选生成业 | 多套调度方案 | 假设、成本、响应时间 |
| 次生风险评审业 | 方案风险 | 拥堵、医疗挤兑、安全风险 |
| 人类授权业 | 高风险调度批准或驳回 | 指挥员确认 |
| 执行反馈业 | 实际执行状态 | 到达时间、失败原因、新灾情 |

#### 为什么相业架构有价值

这里不能让一个“救援 Agent”自主决策，也不能靠固定流程。每条信息、每个方案、每次授权、每个失败都必须成为可追踪的相和证。新反馈会成为新因，动态生成后续业。

相业架构允许快速变化，但不允许无证变化。

### 11.4 案例四：县域新能源产业政策与招商

用户表达：

> 我们县想发展新能源产业，但不知道押储能、光伏配套、运维服务，还是算力能源协同。

#### 因

- 地方政府希望发展产业。
- 财政能力有限。
- 周边城市也在竞争。
- 环境、土地、电网、人才、招商对象都有限制。
- 政策错误会造成长期资源浪费。

#### 愿

- 找到符合本地禀赋、可试点、可调整、可招商、可衡量的产业切口。

#### 业网

| 业 | 果 | 证 |
|---|---|---|
| 本地禀赋梳理业 | 资源禀赋相 | 土地、电力、交通、人才、财政数据 |
| 产业机会池业 | 可选产业方向 | 市场规模、竞争格局、政策窗口 |
| 竞争城市扫描业 | 对手地图 | 周边政策、企业流向、成本对比 |
| 政策工具模拟业 | 政策组合候选 | 财政测算、激励边界 |
| 企业视角反方业 | 招商吸引力问题 | 企业成本、供应链、人才风险 |
| 试点设计业 | 阶段试点方案 | 指标、预算、退出机制 |
| 试点复盘业 | 扩大、调整或停止建议 | 数据、企业反馈、财政效果 |

#### 人类介入点

| 介入点 | 原因 |
|---|---|
| 选择产业切口 | 涉及长期公共价值 |
| 批准政策工具 | 涉及财政、公平和外部承诺 |
| 确认招商承诺 | 涉及政府信用 |
| 扩大或停止试点 | 涉及长期资源配置 |

#### 为什么相业架构有价值

传统咨询会交付一份报告。相业架构交付的是可运行的政策学习系统：每次试点都是业，每个结果都有证，每个政策承诺受律约束，每次失败进入藏，影响下一轮业。

### 11.5 案例五：多个超级个体联合创造大型世界观产品

用户表达：

> 我们几个人都很有想法，想共同创造一个大型世界观产品，但怕风格冲突、设定混乱、商业化破坏灵魂。

#### 因

- 多个创作者各有审美和长板。
- 世界观需要长期一致性。
- 商业化、社区共创、艺术表达之间存在冲突。
- AI 可大量生成内容，但也会制造设定污染。

#### 愿

- 让多个超级个体和 AI 行者共同创造一个长期演化、风格统一、可商业化但不丢失灵魂的世界观系统。

#### 核心相

| 相类 | 示例 |
|---|---|
| 愿相 | 世界母题、审美原则、不可破坏的灵魂 |
| 律相 | 世界规则、角色一致性、商业化边界、社区输入边界 |
| 位相 | 世界主理位、设定守门位、商业反方位、社区吸收位、艺术审美位 |
| 法相 | 世界观扩展法、设定一致性检查法、角色弧线法、商业验证法 |
| 藏相 | 世界史、设定库、角色档案、风格样本、失败设定 |

#### 业网

| 业 | 果 | 证 |
|---|---|---|
| 母题显影业 | 世界核心母题 | 创作者访谈、反例、取舍记录 |
| 世界律建立业 | 不可破坏规则 | 设定一致性测试 |
| 角色群生成业 | 核心角色候选 | 母题引用、冲突关系 |
| 反方设定评审业 | 设定漏洞清单 | 矛盾、俗套、风格漂移 |
| 多创作者冲突仲裁业 | 保留、融合、废弃决定 | 审美理由、人类裁决 |
| 商业化边界业 | 授权与变现规则 | 不破坏世界律的商业方案 |
| 社区输入吸收业 | 可采纳社区内容 | 信用、证据、冲突检查 |
| 藏清理业 | 废弃设定和旧版本标记 | 替代关系、版本证 |

#### 为什么相业架构有价值

传统工具帮助写文案或画图。相业架构组织的是一个创作社会：人保留灵魂和审美，AI 承担大量体力劳动、设定检查、反方攻击、版本清理和社区输入筛选。

核心不是“让一个 Agent 写世界观”，而是让每个创作变化都成为有因、有愿、有律、有证的业。

## 12. 为什么这套架构更先进

| 对比项 | 传统工作流 | 多智能体 Agent 驱动 | 相业架构 |
|---|---|---|---|
| 核心单位 | 流程节点 | Agent 会话 | 业 |
| 稳定存在 | 数据表或文档 | Agent 记忆 | 相 |
| 状态中心 | 流程引擎 | Agent 上下文 | 业记录、果、证、藏 |
| 组织方式 | 人先画流程 | 人先配 Agent | 由因愿立业，业召行者 |
| 方法复用 | 流程模板 | Prompt / Skill | 法 |
| 角色职责 | 节点配置 | Agent 人设 | 位 |
| 约束方式 | 节点规则 | System Prompt | 律 |
| 质量控制 | 节点完成 | Agent 自称完成 | 果必携证，下游可拒收 |
| 记忆沉淀 | 日志或知识库 | Agent 记忆 | 藏，有来源、范围、版本、过期 |
| 人类位置 | 操作者 / 审批员 | Agent 管理者 | 愿主、授权者、裁决者 |
| 复杂协作 | 固定流程变复杂 | Agent 对话失控 | 业网自然生长 |

## 13. 反向检查

未来设计若继续漂移，用这张表检查。

| 问题 | 答不上来的后果 |
|---|---|
| 这是相还是业 | 分不清稳定存在和变化动作 |
| 这个业的因是什么 | 可能脱离真实问题 |
| 这个业的愿是什么 | 可能把输入当目标 |
| 这个业依赖哪些缘 | 可能缺上下文或资源 |
| 这个业受哪些律约束 | 可能越权、低质量或高风险 |
| 行者处于什么位 | 可能责任不清 |
| 行者用什么法 | 可能方法不可复用、不可评审 |
| 行产生了什么果 | 可能只有过程没有交付 |
| 果携带哪些证 | 可能假完成 |
| 下游能否拒收 | 坏果会继续污染后续业 |
| 藏中哪些内容已过时 | AI 修改会顾此失彼 |
| 风险是否累积 | 多个低风险业可能合成高风险 |
| 人类为什么介入 | 如果不是愿、价值、授权、不可逆风险，就可能过度打扰 |
| 是否又在画 Flow | 如果先画固定路线而不是从因愿立业，设计退化 |
| 是否又把 Agent 当真相源 | 如果状态只在会话里，无法交接和复盘 |

## 14. 当前架构仍然脆弱的地方

本文已经比旧帧元表达更清楚，但还不是实现级协议。主要风险如下：

| 风险 | 为什么危险 | 后续必须补的设计 |
|---|---|---|
| 术语过度诗化 | 名字好听但实现者可能误解 | 每个术语必须有 schema、生命周期和反例 |
| 业结构变重 | 因、愿、缘、律、位、法、行、果、证可能变成大表单 | 需要轻量业、标准业、高风险业三档 |
| 律自然语言化 | “不要危险”“质量要高”无法被代码拦截 | 需要机器可执行律 |
| 行者上下文污染 | 一个 Agent 会话连续承接多个业会混入旧假设 | 需要业级上下文装载和会话隔离策略 |
| 藏污染 | 旧记忆、旧文档、旧概念会被继续引用 | 需要过时清理业、版本、适用范围、失效标记 |
| 证伪装成证明 | 有证只能说明检查发生过，不代表检查正确 | 需要证的质量评审和评审者信用 |
| 风险累积不可见 | 多个小动作合成大风险 | 需要险录和风险积累规则 |
| 仲裁权力过大 | 仲裁业可能变成新的上帝对象 | 仲裁必须受根律、证和人类授权约束 |
| 文件并发冲突 | 多个业同时修改相会导致真相分叉 | 需要锁、版本、合并、只追加证录 |
| 与当前代码差距大 | 当前工程并未实现相业运行时 | 需要迁移路线，不可直接宣称完成 |

## 16. 结论

相业架构的核心不是佛教术语，也不是命名美化，而是一个工程原则：

> 不让 Agent 会话成为系统唯一真相；不让流程图成为变化的唯一组织方式；不让输出文本自称完成。

最终目标是让人类作为愿主，把模糊痛点、创意、审美、价值和授权转化为可执行、可验证、可复盘、可迁移、可协作的 AI 软件社会。

最短表达：

> 人起愿；相承载；业发动；律定界；位明责；法成能；行者行；行成果；果携证；证入藏；藏复生新因缘。
